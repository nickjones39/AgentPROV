## R1. A generic class-I rule for defence denials logged as tool errors (done 2026-10-12: rule by regen-batch, hook and profiles in phase 10d, D-113)

**Finding.** Seven phase-10d sources log a defence's refusal of a tool call as a `tool` message whose `error` is the
defence's text (phase-10d error census over the bytes at each pin; counts are tool messages):

| Source | Defence (identity) | Denial text (start) | Messages |
|---|---|---|---:|
| interbolt-agentdojo | `interbolt-strict-enforce`, `interbolt-targeted-enforce` | `Blocked by security policy.` (exact) | 1,879 |
| glitch-agentdojo | `glitch` | `DENIED by the gateway:` | ≥ 244 |
| mohameduk-agentdojo | `ubag`, `ubag_behavioral` | `ubag-blocked: BLOCK` (deny), `ubag-blocked: REVIEW` (hold) | 2,440 + 291 |
| geryon-agentdojo | `progent` (condition B) | `ValidationError: The tool '<name>' is not allowed.` | ≥ 494 |
| gate | `gate*` | `BLOCKED by security policy` | ≥ 1,041 |
| bookkeeper | `munim*` | `Declined by the account's money gate.` | ≥ 177 |
| aiauthz | `aiauthz` | `Blocked by aiAuthZ policy:` | 9 |

Without a rule, the generic D.6.6 rows map each as a `tool_execution` with status `error` (class I through
`agentdojo.tool_msg_is_one_execution_unverified@1`): a call that never ran is recorded as executed. This is the hazard
the Mandate profile fixed with `mandate.decline_prefix@1` (verify/mandate-agentdojo-eval.md §3.7).

**Proposal.** One profile-parametric rule in the `agentdojo` catalogue, class I (no twin needed, D.5.4):

```toml
[[rule]]
id = "agentdojo.defence_denial_message"
version = 1
class = "I"
status = "active"
statement = "A tool message whose error is the denial text the profile's quirk states for a defence of the file (an exact text, a prefix or a regular expression) records that defence's refusal of the call: the call was not executed, the message is generated by a decision of the defence (verdict deny) whose subject is the refused tool_call part, and the logged error is the decision's reason, verbatim. Other errors of the same defence are not denials. Class I: the reading rests on the logged text and the profile, not on verified defence code."
premises = ["/messages"]
assumptions = []
evidence = ["D.6.6 (denial and decline rows)", "docs/reports/phase10d/routing.md R1"]
tests = ["tests/adapters/agentdojo/test_phase10d_sources.py::test_defence_denial_hook"]
since = "0.1.0"
```

and a new hook module `adapters/agentdojo/hooks/defence_denial.py` (phase 10d writes it once the rule exists; it is not
shipped before, because a quirk citing an undeclared rule stops the import): quirk `agentdojo.defence_denial_message`,
params `{ defences = [<globs over the file's defence actors>], error_equals = [...], error_prefix = [...],
error_regex = "...", content_equals_error = <bool> }`, hook point `tool_message` returning
`ToolDecision(defence=<the matching defence actor>, rules=("agentdojo.defence_denial_message@1",), ev="I", reason="error")`,
census key `denials`. A hold (`ubag-blocked: REVIEW`) is mapped as a deny with its text as the reason, because the call
was not executed; the profile notes it.

**Effect once added:** a catalogue entry (the `agentdojo` catalogue digest, and so the golden and gate-D PROV digests,
change as for every earlier catalogue addition); no existing profile declares the quirk, so no existing AER changes.

**Done (D-113).** The rule is on main as proposed; the hook is `adapters/agentdojo/hooks/defence_denial.py` with
`params.denials` matchers (`defences` globs; `error_equals`, `error_prefix` or a whole-text `error_regex`; optional
`content_equals_error`), census key `denials`. Measured on every pinned snapshot (the censuses in `r1/` reconcile with the
profiles' `observed` counts):

| Source | Matcher | Denials |
|---|---|---:|
| interbolt-agentdojo | `interbolt-*`, exactly `Blocked by security policy.` | 1,879 |
| glitch-agentdojo | `glitch`, prefix `DENIED by the gateway: ` | 531 |
| mohameduk-agentdojo | `ubag`, `ubag_behavioral`, exactly `ubag-blocked: BLOCK` or `ubag-blocked: REVIEW` | 2,731 |
| geryon-agentdojo | `progent`, the whole text `ValidationError: The tool '<name>' is not allowed.. Please try ...` | 773 |
| gate-agentdojo | `gate-*`, prefix `BLOCKED by security policy`, output equal to the error | 1,101 |
| bookkeeper-agentdojo | `munim*`, prefix `Declined by the account's money gate. ` | 180 |
| aiauthz-agentdojo | `aiauthz`, prefix `Blocked by aiAuthZ policy: ` | 9 |

Not denials: Progent's JSON-schema argument errors under condition B (their text does not say the call was refused);
one gate denial text in a `local` log whose identity names no defence (D-105), which stays a tool error. Gate's

## R2. `tools/seed_git_cache.py` can fetch over the network from a partial clone (owner: phase 12, `raw/` and tools)

`seed_git_cache.py` runs `git fetch --depth 1` from a local clone through `raw.fetch.Fetcher`, whose git environment does
not set `GIT_NO_LAZY_FETCH`. The phase-10c staging clones are partial clones (`--filter=blob:none`) whose promisor remote
is GitHub, and a few blobs are absent at each pin (figures and documents). The clone's `upload-pack` would then fetch them
lazily from GitHub, a network access the seeding tool presents as offline. **Proposal:** set `GIT_NO_LAZY_FETCH=1` and
`GIT_ALLOW_PROTOCOL=file` in the seeding path (or in `Fetcher._git_env` when `file_protocol` is set), and fail on an
absent blob. Phase 10d does not use the tool; `tools/agentdojo/phase10d_trial.py seed` packs the objects with lazy fetch
and https blocked into a scratch cache (D-100). Also: `git ls-tree -l` prints `BAD` as the size of an absent blob, which
`parse_ls_tree` turns into a `ValueError`; a typed `raw.fetch.git` error would be clearer.

## R4. Identity rows that name a defence but no model (done 2026-10-12: rows by regen-batch; llm-lock profiled in phase 10d, D-114)

llm-lock (Wakeful-Cloud/llm-lock, 53,307 logs, GPL-3.0) records its defence arm only in the path
(`data/agentdojo/<defence>[/<classifier>]/logs/local/...`) and its model nowhere (D-92: `unk /model not_recorded`; the
code default is a note, never an assertion). An identity table row requires `model` (`TABLE_ROW_KEYS`), so a row cannot
say "defence `embedding`, model not recorded"; the only alternatives are asserting the code default (forbidden by D-92)
or dropping the defence (it then reads as undefended, which is false for eight of the nine arms). **Proposal:** allow
`model = "not_recorded"` (or an absent `model`) in a table row: the mapper then writes `unk /model not_recorded`, raises
`identity_unresolved` for the model only, and still writes the row's defence under the identity rule. A two-line change in
`parse_identity_table` and `resolve_identity`, plus a test; byte-neutral for every existing profile (no existing row
omits the model). **llm-lock waits for it** (no profile is shipped in phase 10d).

**Done (D-114).** `llm-lock-agentdojo` uses nine such rows (`tables/llmlock_defence_arms.toml`); every log is
`identity_unresolved` with the arm's defence written. The 88,197 tool errors are not denials: the defences are output
detectors that abort the run or redact the output (see R10), so llm-lock declares no R1 quirk.

## R6. Orphan tool results in gate (no owner change needed; disclosed)

In 819 gate logs a tool message answers a call that the preceding assistant message does not list (its `tool_calls` is
empty; the tool message's `tool_call` names the function, often with a gate denial as its error). The mapper reports
`orphan_tool_result` and leaves the request unlinked, as it should. A gate hook could mark the gate as the requester of
these executions (as AgentDyn's CaMeL hook does), but that needs a rule and evidence from the gate's code that it parses
calls from the model's text. Recorded for the gate's import report and the datasheet.

## R10. Runs ended by a detector abort (done 2026-10-12 in phase 10d at the user's choice, D-116)

llm-lock's defences are tool-output detectors (`defense_utils.EnhancedPromptInjectionDetector`): after a tool runs they
classify its output and, on a detection, raise AgentDojo's `AbortAgentError`, which ends the run; AgentDojo then logs the
messages up to that output with `error` null. The log ends at the flagged tool message, and the verdict survives only in
the detector's extra keys (`classification_result`, `*_malicious_probability`, kept in `ext.agentdojo.extra`). Today the
AER maps such a run as one that simply stopped after an executed tool: the defence's decision is not represented.
Counts at the pin (logs ending at a tool message): embedding 1,281, hybrid/protectai 1,694, llm 4,278, multiclass 4,252
(11,505). The other detector arms (both transformer arms, hybrid/qualifire) never abort: they replace the flagged output
by AgentDojo's sentinel, which the generic `pi_detector_redaction` quirk already maps as a redact decision (13,857
redactions); the pinned code only aborts, so those runs used an earlier state of `defense_utils.py`. **Proposal:** a class-I rule stating that, in a file whose defence is a declared
aborting detector, a log that ends at a tool message records the detector's decision on that output (subject the tool
result part, verdict `abort` if the vocabulary gains one, else a namespaced reason), with the detector keys as premises.
**Done (D-116):** verdict `terminate` (already in the vocabulary), rule `agentdojo.detector_abort_after_output@1`, the
new hook point `log_end` and the quirk `agentdojo.detector_abort` (`hooks/detector_abort.py`); 10,164 runs name the
single trailing output, 1,341 runs with several outputs name the request message and raise the info issue
`agentdojo.detector_abort_output_unrecorded`.
