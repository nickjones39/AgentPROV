Title: `AgentPROV v0.1.0`

> AgentPROV 0.1.0 is the first public release of AgentPROV, an execution-provenance framework for LLM-agent security
> research. It turns agent execution logs (imported from benchmark runs, or captured live) into a canonical execution
> record (AER), semantic annotations (SEM) and W3C PROV bundles (core, inference and assessment), validates them, and
> packages them as hash-chained, recomputable corpora.
>
> **What is in this release**
> - The `agentprov` command-line tool and library (Python 3.14), the live-capture writer `agentprov-capture`, and the
>   draft-only Zenodo uploader `agentprov-zenodo`.
> - Import adapters for the AgentDojo family of logs (AgentDojo, AgentDyn, ROPE and over 20 third-party studies),
>   Inspect, OpenHands, Gemini CLI, Qwen Code, AutoGen, AgentOps, DTap, MCPHunt, CredLeak and wire logs.
> - The desktop application (viewer, import, run and package pages) for macOS, Linux and Windows.
> - The specification (`docs/architecture/`) and the user guide (`docs/user-guide/`).
>
> **Corpora.** The corpora built with this release are published on Zenodo as one collection: <umbrella DOI>. Each
> corpus has a datasheet, its licence class and a root digest you can check with `agentprov verify`.
>
> **Building commits.** The corpora record the AgentPROV commits that built them. This repository starts a new history
> at v0.1.0; those commits are preserved as source snapshots, with a manifest that checks their stage code digests
> against the corpora, in the software record: <software DOI>. The public tree equals development commit `<R>` minus
> the files listed in `docs/reports/release/public-export.toml`.
>
> **Desktop bundles**
>
> | File | Platform | Tested on a clean machine |
> |---|---|---|
> | `AgentPROV-macos-arm64.dmg` | macOS 15 or later, Apple silicon | on the build Mac |
> | `AgentPROV-linux-aarch64.tar.gz` | Linux arm64, glibc 2.39 or later | yes (Ubuntu 24.04) |
> | `AgentPROV-linux-x86_64.tar.gz` | Linux x86_64, glibc 2.35 or later | yes, under emulation (Ubuntu 22.04) |
> | `AgentPROV-windows-arm64.zip` | Windows 11 ARM64 | yes (live runs: macOS and Linux only) |
> | `AgentPROV-windows-x64.zip` | Windows 11 x64 | yes, under emulation (live runs: macOS and Linux only) |
>
> - **macOS:** the app is signed ad hoc, not notarised. On first launch macOS refuses it; open System Settings › Privacy
>   & Security and click **Open Anyway** (macOS 15 and later no longer offer Control-click › Open for this).
> - **Windows:** the bundles are not code-signed. SmartScreen shows a warning: choose **More info**, then **Run anyway**.
> - **Linux:** unpack the archive and run `AgentPROV/AgentPROV`; the folder has a desktop-entry installer.
> - Check every download against `SHA256SUMS` (signed: `SHA256SUMS.sig`, verify with `ssh-keygen -Y verify` and the key
>   in `allowed_signers`).
>
> **Limits of v0.1.** Live capture works and is tested, but live corpora cannot be sealed yet (planned for v0.2). PROV
> grows with the square of the model calls in a run (see the roadmap). Model-provider terms for redistributing model
> outputs were not assessed; each datasheet says so.
>
> **Licence.** MIT for the code (`LICENSE`); third-party components and data in `THIRD_PARTY_NOTICES.md`. Corpora carry
> their own licence classes on Zenodo.
>
> **Cite:** see `CITATION.cff` ("Cite this repository").

## 6. Signing options (V-4, V-5, V-6)

Prices and programme terms are from my knowledge, **not checked online today**; confirm on the vendors' pages before
paying.

| Option | Cost (approx.) | What it changes for a user | Effort and risk |
|---|---|---|---|
| **macOS ad hoc** (today, D-657) | none | Gatekeeper blocks the first launch; the user clicks Open Anyway in System Settings once | none; already built and tested |
| **Apple Developer ID + notarisation** | Apple Developer Program, about USD 99 a year (individual) | the `.dmg` opens with a normal "downloaded from the internet" prompt; no Settings detour | enrolment (identity check, days); `build_bundle.py --sign-identity` already signs with the hardened runtime; notarisation (`xcrun notarytool submit`, then `stapler staple`) is a manual step to add; the certificate's key must live in your keychain, never in the repository. Notarised apps keep running after the membership lapses; new builds need a live membership |
| **Windows unsigned** (today, D-750) | none | SmartScreen warning: More info › Run anyway; some corporate machines block unsigned executables | none |
| **Windows OV code-signing certificate** | roughly USD 200–500 a year; since 2023 the key must sit on a hardware token or a cloud HSM | the publisher name shows; SmartScreen still warns until the certificate builds reputation (downloads over weeks) | buying, identity validation, a token or a cloud signing service; `signtool` in the Windows build; renewal |
| **Windows EV certificate** | roughly USD 300–700 a year, hardware token | as OV; EV no longer buys immediate SmartScreen reputation (Microsoft's 2024 change, as I understand it; confirm) | as OV, stricter validation |
| **Microsoft Trusted Signing** (Azure) | about USD 10 a month | signed with a Microsoft-issued certificate in your validated name; reputation as for OV | an Azure subscription and identity validation; eligibility for individuals has been limited by country; confirm |
| **SignPath Foundation** (free for open-source projects) | none | signed, but the publisher shown is "SignPath Foundation", not you | apply after the repository is public; signing runs from a CI build of the public repository (the bundles would be built on GitHub runners, not locally) |
| **Linux** | none | Linux desktop bundles are not code-signed by convention; `SHA256SUMS` and its signature are the check | none |
| **SSH-signed tag and `SHA256SUMS`** (V-6) | none | GitHub shows the tag "Verified"; anyone can check `SHA256SUMS` with your public key | one signing key (yours, never in the repository), `git config gpg.format ssh`, `git tag -s`, `ssh-keygen -Y sign -n file` |
| **Sigstore / GitHub artifact attestations** | none | a transparency-log record of who built what | needs the build to run on GitHub Actions (OIDC); the bundles are built locally in VMs, so not now |

**Recommendation.** For a research-software release whose users are researchers, V-4 and V-5 as today plus V-6 (free)
give integrity without cost. The Apple programme is the one purchase with a clear effect (no Settings detour on
macOS); the Windows options cost more and still warn until reputation builds.
