**RT-1 depends on the DRIFT build's hook guard (done on this branch, at the request of the regen-batch session's
review of D-116):** `DriftBuild` runs none of the generic build's quirk hook points (`log_end` from D-116 included). A
declared quirk whose hook implements any of them and whose selector matches a DRIFT file raises the seal issue
`drift.quirk_hook_not_applied` (detail: the quirk id) instead of being skipped silently; `mapping_hook_points` reads
the `QuirkHook` fields, so a hook point added later is covered without a change. Census-only hooks are inert. Test:
`test_drift.py::test_a_matching_mapping_hook_is_reported_not_skipped`. Byte-neutral for `v0.k11`/`v1.k14`: no
stored corpus selects a DRIFT file. Tests that assert DRIFT files seal as `unsupported_variant` change with it (the
importer then maps them where a profile declares the variant). `DriftMapper` has the same `mapper_id` and version, so
execution ids do not depend on which class maps.
