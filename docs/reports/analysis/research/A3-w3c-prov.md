# A3. W3C PROV: issue classes, validation options and agent-provenance modelling

Research brief for AgentPROV (`agentprov-prov/0.1`). No repository changes were made. Date: 2026-10-11.

How to read this document. Claims carry bracketed source numbers that resolve to the "Sources" list at the end.
"[opened]" means I read the page or source file; "[snippet]" means I only saw a search-result summary, so treat
such claims as unverified. Statements marked **(probe)** are my own measurements on a read-only sample of local
corpora under `~/.agentprov/corpora` and are indicative, not corpus-wide results. Statements marked **(inference)**
are my reasoning, not a source claim. All web content was treated as data.

## 0. Key findings (read this first)

1. **Event-ordering constraints do not need timestamps.** PROV-CONSTRAINTS 6.2 defines ordering over
   *instantaneous events* (generation, usage, start, end, invalidation) and says the times attached to events are
   irrelevant for checking ordering [1][opened]. Inference 7 and 8 make every entity and activity carry such events
   in the normal form [1]. So the repository statement "no relation carries a time ... so the event-ordering
   constraints are not instantiable" (`src/agentprov/validate/constraints.py` docstring; EF E.1.4 preamble and the
   C47 "no times: not applicable" remark) is too strong. The constraints *are* instantiable from the relation
   structure alone. The practical consequence is narrow (finding 2), but the claim should be corrected.
2. **Only Constraint 42 produces a strict ordering edge.** In the 6.2 text every other ordering rule yields
   "precedes" (non-strict); the one other "strictly precedes" rule (start-of-starter) is inside a commented-out
   block, labelled TBD [1][opened]. A document is invalid on ordering only if the event graph has a cycle that
   contains a strict edge [1][opened]. So for AgentPROV the decidable ordering failure is: **a cycle through
   `wasDerivedFrom`** (directly, or closed through other precedes-edges such as C34/C43/C45/C48). This check is
   cheap and not implemented. In a 400-document probe I found no derivation, used/generated or `wasInformedBy`
   cycles in 3,470 bundles **(probe)**, so it is a guard, not a known defect.
3. **Validity is judged per bundle; AgentPROV's "application view" is its own addition.** PROV-CONSTRAINTS 7.2:
   each bundle is handled independently, with no interaction between bundles [1][opened]. Any external validator
   will therefore not see cross-bundle contradictions (core vs inference). The existing views in
   `constraints.py` already cover this; external tools cannot be used as an oracle for the union.
4. **Normal-form implications are not yet used by the checks.** Inference 9/10 (start/end trigger was generated by
   the starter/ender), 13 (attribution implies a generating activity associated with the agent) and 14 (delegation
   implies both agents associated with the activity) add statements in the normal form [1][opened]. The existing
   `single_generator` check counts only explicit `wasGeneratedBy`, so an explicit generation by another activity
   plus the implied one from Inference 9 is invisible to it.
5. **Library and interop risk is concentrated in the `prov` Python library.** 70+ recent GitHub issues
   (Jul-Oct 2026) report round-trip, PROV-JSON reader, PROV-N and PROV-O defects [8][opened via `gh`]. Several bear
   on AgentPROV's round-trip oracle (see B8). `prov` 3.2.2 itself writes `xsd:QName` for QName values, while AgentPROV
   writes `prov:QUALIFIED_NAME` (verified locally); both tokens occur in the specifications [2][5].
6. **`mentionOf` is a W3C Note construct, and PROV-JSON is not covered by PROV-LINKS** [6][opened]. AgentPROV emits a
   top-level `mentionOf` section inside bundles. Consumers other than `prov` 3.2.2 may reject or drop it.
7. **No off-the-shelf validator is a drop-in for 126k documents.** The only complete PROV-CONSTRAINTS
   implementations are the Java ProvValidator/ProvToolbox module, the SPARQL `prov-check` (alpha) and Prolog
   `checker.pl` [7][9][11]. There is no official SHACL formulation of the constraints [13]. Use them as a
   differential oracle on a stratified sample and as a source of the 280 W3C test cases, not as the main pass.
8. **Documents are small** (probe of 300 files: median 123 KB, p90 291 KB, max 1.06 MB; median 193 statements, p90 509,
   max 1,811 in bundles), so every graph check below is cheap in pure Python **(probe)**.

## 1. Catalogue of PROV issue classes

Columns inside each entry: **What** (description), **Clause**, **In AgentPROV** (how it shows up: core / inference /
assessment bundles, no relation times), **Detect** (concrete check), **Covered?** (existing validator ids from
`src/agentprov/validate/`), **Sev.** (Critical = makes the instance invalid under PROV-CONSTRAINTS or breaks a
serialisation; High = misleading provenance; Medium = quality or interop; Low = hygiene), **Cites**.
"Covered" is based on the module docstrings and code I read (`prov_structure.py`, `constraints.py`, `_provdoc.py`,
and the headers of `linkage.py`, `profiles.py`, `roundtrip.py`, `prov.py`, `tiers.py`). I did not read every function body
of `profiles.py` (729 lines) or `linkage.py`, so "not found" means "not named in the docstrings or code I read".

### A. PROV-CONSTRAINTS validity

PROV-CONSTRAINTS structure for orientation [1][opened]: Definitions and Inferences 5-21 (section 5), then Constraints
22-29 uniqueness/key, 30-49 event ordering, 50 typing, 51-55 impossibility, 56 membership of an empty collection
(sections 6.1-6.4). Validity (section 7.1): normalise (apply definitions, inferences, uniqueness; fail if a
uniqueness constraint cannot unify), build the event graph and reject any cycle with a strict edge, then apply typing
and impossibility constraints. Normalisation terminates (weak acyclicity) in polynomial time [1][opened].

**PI-01 Key constraints (C22 key-object, C23 key-properties).**
- What: one identifier denotes one element or relation; same-id statements are merged and their attributes combined;
  merge failure makes the instance invalid.
- Clause: C22, C23; 7.1 normalisation [1].
- In AgentPROV: within one bundle JSON object keys already forbid repeats; risk is *across* documents (see PI-30) and
  across the top level vs bundle (independent instances, so no clash).
- Detect: per container, ids unique per section; for ids in two sections check C53/C54 (PI-09).
- Covered: `pv.prov_structure.identifiers` (`duplicate_identifier`), `pv.constraints.identifiers` (`identifier_overlap`).
- Sev.: Critical. Cites [1].

**PI-02 Unique generation / invalidation / start / end (C24-C27).**
- What: at most one generation per (entity, activity), one invalidation per (entity, activity), one start event per
  (activity, trigger, starter), one end per (activity, trigger, ender); the duplicates are merged.
- In AgentPROV: `wasGeneratedBy` is the busy relation; `wasStartedBy` (1,084 in the 400-doc probe) is the only
  start/end relation emitted **(probe)**.
- Detect: key = (entity, activity) and (activity, trigger, starter); duplicates with different ids are a finding.
- Covered: C24 by `pv.constraints.unique_generation`. C26 (start uniqueness) not found. C25/C27 not instantiable
  (no `wasInvalidatedBy`/`wasEndedBy` emitted).
- Sev.: Medium (C26 gap: merging would be silent, not invalid). Cites [1].

**PI-03 Start/end time agreement (C28, C29).**
- What: if an activity has `startTime` and a `wasStartedBy` with a time, they must be equal (likewise end).
- In AgentPROV: relations carry no time (E.5.3 item 7), so not instantiable today. It becomes live if relation times
  are ever added (EF defers this).
- Detect: none now; add when relation times appear.
- Covered: n/a. Sev.: Low (forward-compat). Cites [1].

**PI-04 Event-ordering cycle containing a strict edge (C42, with C33-C49).**
- What: derived entity's generation strictly follows the original's generation (C42). All other ordering rules are
  non-strict. Invalid iff the precedes/strictly-precedes graph has a cycle through a strict edge.
- Clause: 6.2 ordering preamble; C42; 7.1 validity algorithm [1].
- In AgentPROV: `wasDerivedFrom` is rare (67 statements in the 400-doc probe, all revisions/redactions/placement)
  **(probe)**. A cycle needs `wasDerivedFrom` plus a back path, for example `wasStartedBy(te, p, mc)` giving
  gen(p) <= start(te), with gen(e1) strictly before gen(e2) and start(te) <= gen(e1) (C34/C43). Specialisation
  (C45) and attribution (C48) add more precedes-edges.
- Detect: build event nodes {gen(e), use(a,e), start(a), end(a), inv(e)} for every entity/activity (Inf. 7/8
  existentials) and the edges of C30-C49 present in the view; Tarjan SCC; flag any SCC containing a strict edge.
  Minimal version: DFS for a cycle in the `wasDerivedFrom` graph (strict self-loop through C42). Run per container
  and per inference application view.
- Covered: **No.** `constraints.py` says ordering is "not instantiable". Only MAY-flag time diagnostics
  (`pv.constraints.time.*`) exist.
- Sev.: Critical if present; likelihood low. Cites [1].

**PI-05 Non-strict ordering constraints (C30-C41, C43-C49).**
- What: usage within activity lifetime, generation before usage, trigger generated before start, agent exists before
  attribution/association, etc.
- In AgentPROV: satisfiable without a strict edge (each is "precedes"; a cycle of non-strict edges just means the
  events are simultaneous, which PROV allows) **(inference)**. They matter only in combination with PI-04.
- Detect: subsumed by PI-04's event graph.
- Covered: n/a (see PI-04). Sev.: Low alone. Cites [1].

**PI-06 Typing (C50) and entity/activity disjointness (C55).**
- What: each argument position types its node; an id typed both entity and activity is invalid. Agents may also be
  entities or activities (no disjointness) [1].
- In AgentPROV: bundles that reference core nodes by IRI without re-declaring them type the nodes by use; the view
  union can expose a clash a single bundle hides.
- Detect: typeOf sets per view; error iff {entity, activity} subset.
- Covered: `pv.constraints.typing`; `PV-NE-19` (`used` object is an activity; `mentionOf` ends are entities).
- Sev.: Critical. Cites [1].

**PI-07 Impossible unspecified-derivation parts (C51).**
- What: `wasDerivedFrom` with a generation or usage but no activity is invalid.
- In AgentPROV: `aprov.t_map@1` and `t_annotate@1` emit `wasDerivedFrom(b, raw, activity, g, u)` with an activity.
- Detect: any `wasDerivedFrom` with `prov:generation` or `prov:usage` and no `prov:activity`.
- Covered: not found as a named check; may be implied by relation-argument shape (`pv.prov_structure.relations`). Verify.
- Sev.: Critical if present, trivial to add. Cites [1].

**PI-08 Specialisation reflexive / cyclic (C52 plus Inf. 17-20).**
- What: `specializationOf(e, e)` invalid. The Rec's 2-cycle statement is commented out, but irreflexivity plus
  transitivity (Inf. 19) rules out longer cycles, because a cycle closes to `specializationOf(e, e)` [1][opened].
- In AgentPROV: `specializationOf(bundle, xd:provenance)` and the implication mention => specialisation [6].
- Detect: cycle detection on the `specializationOf` graph (including `mentionOf` as a specialisation).
- Covered: direct reflexive case only (`pv.constraints.identifiers`, `specialization_reflexive`). Longer cycles: no.
- Sev.: Critical if present; likelihood very low. Cites [1][6].

**PI-09 Identifier overlap (C53 relation ids; C54 element vs relation ids).**
- Covered: `pv.constraints.identifiers` (`identifier_overlap`). Sev.: Critical. Cites [1].

**PI-10 Empty collection membership (C56).**
- Covered: `pv.constraints.typing` (`empty_collection_member`). Sev.: Critical. Cites [1].

**PI-11 Multiple generators of one entity (C39 is a *simultaneity* rule, not uniqueness).**
- What: PROV allows several generating activities if their generation events are simultaneous. AgentPROV's "at most
  one generating activity per entity per bundle" is a *profile* rule above C39, which is a legitimate stricter
  choice.
- Detect: as implemented, plus the implied generations of Inf. 9, 10, 13 (PI-12).
- Covered: `pv.constraints.single_generator` (explicit statements only). Sev.: Medium. Cites [1].

**PI-12 Implied-statement consistency (Inf. 9, 10, 13, 14, 5, 6, 11, 12).**
- What: normal form adds existential statements: trigger generated by starter (9/10); an attributed entity has a
  generating activity associated with the agent (13); both agents of a delegation are associated with the
  activity (14); `wasInformedBy` <=> shared entity (5/6, non-transitive) [1][opened].
- In AgentPROV:
  - `aprov.start_tool@1` `wasStartedBy(te, p, mc)` needs `wasGeneratedBy(p, mc)`. By construction `gen_part` supplies
    it, but nothing validates that the starter is *the* generator of the trigger.
  - `wasAttributedTo(m, actor)` plus an explicit `wasGeneratedBy(m, mc)` where `mc` is not associated with `actor`
    leaves the attribution unsupported (NE-4 prevents emission by design).
  - `actedOnBehalfOf(rt, ag, te)` deliberately leaves `wasAssociatedWith(te, ag)` implied only (EF E.1.4 `assoc_tool`).
- Detect: expand Inf. 9/10/13/14 on the view and re-run PI-11, plus lints: trigger's explicit generator == starter;
  attribution => some explicit generator is associated with the agent; delegation => report implied-only associations.
- Covered: PI-12 expansion not found. `PV-NE-4`, `PV-NE-13` cover the design-time prohibitions.
- Sev.: Medium. Cites [1].

**PI-13 Communication is not transitive; `wasInformedBy` <=> shared entity (Inf. 5/6).**
- Covered by design: `pv.profiles` closure checks (`closure_duplicate`, `closure_extra`, `closure_missing`,
  `closure_incomplete`, `closure_class`, `closure_premise`) and `PV-NE-7`; `pv.constraints.self_communication`.
- Note: the Rec has no inference that `wasDerivedFrom` is transitive either (text beside Inf. 11-12) [1][opened].
- Sev.: High. Cites [1][2].

**PI-14 Validity for documents with no times.**
- What: the Rec defines validity on the event structure; absent times are fine, and "an application MAY flag time
  values that appear inconsistent" [1][opened]. Absent timestamps never invalidate a document; they only shrink
  what ordering evidence exists for the human reader.
- In AgentPROV: 4,834 of 5,418 activities (89%) in the probe have no `prov:startTime` **(probe)**; per E.5.3 item 7 this
  is intended where the AER has no UTC time.
- Detect: report the time-coverage ratio as a quality metric (PI-27), not as a failure.
- Covered: `pv.profiles` (`sentinel_time`, `time_on_non_activity`, `time_without_aer`, `relation_time`), MAY flags.
- Sev.: Low. Cites [1].

### B. Serialisation: PROV-DM / PROV-N / PROV-JSON / PROV-O

**PI-15 QName and IRI form.**
- What: PROV-N QUALIFIED_NAME is looser than XML QName: PN_LOCAL may contain `/ @ ~ & + * ? # $ !`, percent escapes
  and backslash escapes, must not end with `.`, and forbids `= ' ( ) , : ; " [ ]` unescaped. Expansion is prefix IRI
  plus local part [3][opened]. `prov` issue #524: a local part PROV-N cannot write is accepted and percent-encoded
  on output, changing the IRI; #473, #517, #518 concern default-namespace and `default` prefix edge cases [8].
- In AgentPROV: node names follow `NODE_NAME_RE`; QName regex `QNAME_RE` in `prov_structure.py` accepts a trailing `.`
  or `-` in the local part (PN_LOCAL forbids a trailing `.`).
- Detect: validate expanded IRIs (RFC 3987) and PN_LOCAL, including "last char is not `.`"; namespace IRIs end in `#` or
  `/`; no prefix named `default`.
- Covered: `pv.prov_structure.qnames`, `.prefixes`, `.identifiers` (regex-level). Trailing-dot case: no.
- Sev.: Low. Cites [3][8].

**PI-16 Datatype token for QName values.**
- What: PROV-DM names the datatype `prov:QUALIFIED_NAME` [2][opened]. The PROV-JSON Submission types QName values as
  `xsd:QName` [5][opened]. `prov` 3.2.2 *writes* `xsd:QName` (verified locally: `{"$": "prov:SoftwareAgent", "type": "xsd:QName"}`);
  `prov` issue #168 argued for that, and #238 handles reading `prov:QUALIFIED_NAME` [8]. ProvToolbox's model source
  references both tokens (`Name.java`, `QualifiedName.java`, `ValueConverter.java`) [9][opened via `gh search code`].
- In AgentPROV: canonical form is `{"$": q, "type": "prov:QUALIFIED_NAME"}` (EF E.5.3 item 3; `prov/_ir.py`).
- Detect: conformance probe: read a sample through ProvToolbox and `prov`, assert QName attribute values come back as
  qualified names, not strings.
- Covered: the form is enforced (`pv.prov_structure.values`); round-trip proves `prov` reads it
  (`pv.roundtrip.model_equality`); third-party readers untested.
- Sev.: Medium (interop). Cites [2][5][8][9].

**PI-17 Top-level member set, `mentionOf` and PROV-JSON.**
- What: the PROV-JSON Submission defines sections per relation, `prefix`, `bundle`; PROV-LINKS does not define a
  PROV-JSON form for `mentionOf` and is a Working Group Note (experimental, not Recommendation-track) [5][6][opened].
- In AgentPROV: `mentionOf` section inside inference/assessment bundles; 6,840 mentions in the 400-doc probe **(probe)**.
- Detect: gather an interop matrix (ProvToolbox read, `prov` read, JSON-Schema validation) per construct; make the
  assessment/inference bundles skippable by consumers (core stays standard).
- Covered: C6 caveat in EF E.5.2; `pv.prov_structure` accepts the section.
- Sev.: Medium. Cites [5][6].

**PI-18 Bundle semantics.**
- What: a bundle is a named set of descriptions and is itself an entity; "a bundle's identifier identifies a unique
  set of descriptions" [2][opened]. PROV-N: bundles cannot be nested [3][opened]. PROV-JSON: bundle content is a
  normal document, no nesting, bundle also described as an entity [5][opened]. PROV-O does not specify an RDF
  encoding for bundles; TriG named graphs are only illustrative [4][opened]. `prov` #449: `NamespaceManager` copies
  document prefixes into bundles [8].
- In AgentPROV: bundle IRI includes derivation key `dk` (EF E.3.4), prefixes at document level only.
- Detect: bundle IRI uniqueness across a corpus (content changes imply new `dk`); bundle entity present; no nesting.
- Covered: `pv.prov_structure.bundles`, `.prefixes`, `_document` nesting codes; `dk` stability is a corpus concern (PI-30).
- Sev.: High if violated. Cites [2][3][4][5][8].

**PI-19 Unidentified relations and blank-node keys.**
- What: PROV-JSON assigns blank-node ids (`_:...`) to unidentified relations and says to ignore them semantically
  [5][opened]. `prov` issue #145 (closed) reported duplication on JSON round trip [8].
- In AgentPROV: `specializationOf`, `hadMember`, `mentionOf` use `_:<rule>.<h16>` keys (deterministic).
- Detect: blank ids confined to unidentified relations; round-trip does not multiply them.
- Covered: `pv.prov_structure.identifiers` (`statement_id`, `blank_node`), `pv.roundtrip.graphs`.
- Sev.: Low. Cites [5][8].

**PI-20 Qualified vs unqualified PROV-O.**
- What: PROV-O says consumers should treat the qualified form as implying the unqualified one, and including both is
  encouraged [4][opened]. The `prov` library writes only the qualified form for identified relations (AgentPROV caveat C1).
  Issues #217 (two relations with one id and different formals do not round-trip), #226 (anonymous delegations
  collapse), #250 and #303 (qualified nodes lose the influencer or decode as two records) were closed in 2026 [8][opened].
- In AgentPROV: all influence relations are identified; unqualified layer added on demand (E.5.4).
- Detect: per named graph, qualified-node count == identified-relation count; each qualified node has its influencer property.
- Covered: `pv.roundtrip.completeness` (typed, bidirectional), `.graphs`. `unqualified_layer` is `not_applicable`.
- Sev.: Medium. Cites [4][8].

**PI-21 Library defects bearing on the oracle.**
- What: (a) EF caveat C9 (substring rewrite on decode). (b) `prov` #527: literal equality compares by value for some
  datatypes and loses the lexical form for others, so `model_equality` is weaker than a byte test; AgentPROV's
  typed completeness check is the right backstop. (c) #525: record equality ignores the id when the left record has none,
  so `a == b` and `b == a` can disagree. (d) #530-#532: the JSON reader keeps the last duplicate key, accepts one-element
  arrays for formal attributes and gives `hadMember` arrays inconsistent ids [8][opened]. (e) #514: `xsd:dateTime` range
  follows Python `datetime`.
- In AgentPROV: strict JSON loader and JCS byte equality precede the `prov` read, so (d) cannot silently alter input;
  (b)/(c) bear on `pv.roundtrip.model_equality` only.
- Detect: keep `completeness` and `graphs` as the decisive round-trip checks; add a reverse-order equality assert.
- Covered: yes for (a), (d); partial for (b), (c). Sev.: Medium. Cites [8].

**PI-22 JSON-level hygiene.**
- What: RFC 7493 (I-JSON) forbids duplicate member names and limits integers; the PROV-JSON Submission ships a
  non-normative JSON Schema (Draft 4) [5][opened]; its own examples contain inconsistencies [5].
- Detect: strict loader (done); validate each document against the Submission schema as an independent structural oracle.
- Covered: strict loader, `pv.prov_structure.value_form` (I-JSON integer bound). Schema check: no.
- Sev.: Low. Cites [5][25].

**PI-23 Round-trip loss between PROV-JSON, PROV-N and PROV-O.**
- What: `prov` issues cover PROV-N escapes (#223, #524), code-point escapes (#521), literal typing (#522, #527), language
  tags (#472) and PROV-O datatype fidelity (#218, #225, #256) [8].
- In AgentPROV: PROV-N is not produced. The PROV-O path is covered by `pv.roundtrip.*`.
- Detect: as PI-21; add a single PROV-N smoke conversion in an interop sample only.
- Covered: PROV-O yes; PROV-N not in scope. Sev.: Low. Cites [8].

### C. Graph-structure and quality issues

**PI-24 Cycles in derivation / dependency.**
- What: derivation cycles are invalid (PI-04). Cycles in the `used`/`wasGeneratedBy` graph or in `wasInformedBy`
  are legal PROV (non-strict) but imply a causal loop that a single agent run cannot have, so they indicate wrong
  generator/consumer pairing **(inference)**.
- Detect: SCC over (activity -> used entity -> generating activity) and over `wasInformedBy`; any non-trivial SCC is a
  finding. Run per application view.
- Covered: no. Probe: 0 cycles in 3,470 bundles of 400 documents **(probe)**. Sev.: High if present. Cites [1].

**PI-25 Disconnected subgraphs and orphans.**
- What: nodes in no relation, or components unreachable from the execution root, make downstream queries incomplete.
- In AgentPROV: many nodes are legitimately relation-free (attributes link them): `apv:Gap` entities, the capture
  profile, the execution description. Application-view probe over 400 documents: 5,835 `apv:Gap` entities (16% of
  35,648 entities), 400 capture profiles, and unexplained orphans of 129 `apv:TextPart`, 119 `apv:Harness` agents,
  32 `apv:Step` activities, 24 `apv:ToolRuntime` and 24 `apv:Defence` agents **(probe)**. Per-bundle counts mislead
  because INFERRED relations live in inference bundles.
- Detect: weakly connected components over the union of bundles; allowlist by `prov:type`; report per-type orphan rates
  and the Gap ratio. Add "tool-result part with neither generator nor gap/overwritten status".
- Covered: no (`pv.prov_structure.references` is about dangling references, not orphans). Sev.: Medium. Cites [15][18].

**PI-26 Dangling references and undeclared nodes.**
- Covered: `pv.prov_structure.references` (`unresolved_argument`, `core_undeclared`), including assessment views.
- Sev.: Critical. Cites [1][2].

**PI-27 Completeness and quality metrics.**
- What: survey literature proposes trace completeness, provenance accuracy, dependency coverage and temporal
  consistency but notes they lack agreed definitions [20][opened]. Huynh et al. derive data-quality predictions from
  network metrics of PROV graphs [18][snippet]; Moreau's aggregation by provenance types summarises graphs by k-hop
  type signatures and supports outlier detection and conformance checking [15][snippet].
- Detect (corpus-level, descriptive): Gap ratio; time-coverage ratio (89% of activities untimed in the probe); share of
  `INFERRED` statements; mean in/out degree per node class; provenance-type census with k = 1 or 2 to find rare
  structural signatures; entities with no generator excluding declared inputs.
- Covered: accounting exists in the AER/seal; no PROV-graph metrics. Sev.: Medium. Cites [15][18][20].

**PI-28 Duplicate nodes for the same thing.**
- What: the same message, model or payload as several nodes. AgentPROV forbids content hash as identity (NE-15), so
  duplicates are by design distinguishable.
- Detect: group entities by (type, `apv:contentSha256`) and by (`apv:servedModel`, provider) per document; report counts,
  and optionally assert `alternateOf` is not needed.
- Covered: `PV-NE-15` (identity), no duplicate-content report. Sev.: Low. Cites [2].

**PI-29 Granularity.**
- What: PROV leaves granularity to the application [2][opened]. Over-fine (a node per part, per token) inflates graphs;
  over-coarse hides influence. The survey lists granularity levels run, step, tool-call, parameter, claim, token [20][opened].
- In AgentPROV: message + part entities, `hadMember` for requests; context window is a set of `used` edges, not a node.
- Detect: nodes and edges per activity histogram; flag outliers over p99.
- Covered: no. Sev.: Low. Cites [2][20].

**PI-30 Cross-document merge conflicts (corpus level).**
- What: when many documents share IRIs (`raw:`, `sw:`, `rules:` are shared; `x:` and `xd:` are per execution), merging
  them into one RDF dataset triggers C22/C23 merging and shows disagreement as multi-valued or conflicting attributes.
- Evidence: within each of 5 corpora (600 files sampled each) the shared top-level statements were identical; across a
  1,500-file mix of corpus snapshots, `rules:agentdojo.1` had 6 distinct `apv:sha256` digests, `rules:agentprov-prov.0.1`
  2 and `rules:inspect.1` 2 **(probe)**. That is expected when snapshots from different phases are mixed, but it shows the hazard.
- Detect: group top-level statements by (section, key) across the corpus; require byte-equal JCS; fail on any variant
  (AD-18 says a verification-status change is a new catalogue version).
- Covered: not in `validate/` as read; may exist in corpus integrity (`agentprov verify`). Verify.
- Sev.: High for any combined release. Cites [1].

**PI-31 Attribution vs association confusion; delegation without association.**
- What: attribution (entity -> agent) implies a generating activity associated with the agent; association assigns
  responsibility for an activity; delegation implies both agents are associated with the activity [1][2][opened].
  A practitioner reading (search synthesis) lists misuse of `wasAttributedTo` on activities and of `wasInformedBy` as
  `wasDerivedFrom` as the common errors [snippet].
- Covered: `PV-NE-4`, `PV-NE-13` (composite and scripted attribution), typing (PI-06). Lints in PI-12 are new.
- Sev.: High. Cites [1][2].

**PI-32 Misuse of `wasInformedBy`; transitive closure assumptions.**
- Covered: see PI-13 (`PV-NE-1`, `PV-NE-7`, closure equality). Consumers who take the transitive closure over
  `wasInformedBy` or `wasDerivedFrom` overstate dependency; document this in the datasheet. Sev.: High. Cites [1][2].

**PI-33 Inferred vs asserted provenance ("provenance of provenance").**
- What: PROV records conversion provenance with bundles as entities and `wasDerivedFrom(bundle, input)` [2][opened].
- Covered: `pv.linkage.class_bundle`, `.method`, `.existence`, `PV-NE-11` (`inferred_in_core`), `PV-NE-17`.
- Sev.: High. Cites [2].

**PI-34 Temporal claims without evidence.**
- Covered: `PV-NE-6` (`relation_time`, `sentinel_time`, `time_without_aer`), MAY flags. Sev.: High. Cites [1].

**PI-35 Evidence-class statements are plain attributes.**
- What: PROV has no reification of statements except identified relations; `apv:evidenceClass` is a custom attribute, so
  no PROV tool enforces it.
- Covered: `pv.linkage.evidence_attributes`, `.existence`, `.premise`. Sev.: Medium. Cites [2][4].

## 3. Validation tooling options for about 126,000 documents

| Option | Detects | Performance | Limits |
|---|---|---|---|
| Existing tier 4 (`validate_prov`) | Structure, a PROV-CONSTRAINTS subset, linkage to AER, never-emit rules, PROV-O round trip | Pure Python; documents are small (probe) | No ordering check, no normal-form expansion, no external oracle |
| `prov` 3.2.2 `ProvDocument.unified()` | Key constraints C22/C23 and type rules C53-C55 as merges [8 #253, #325] | Measured on one 9-bundle, 81-record document: read 0.13 s, `unified()` 6 ms | Deliberately excludes ordering constraints 30-49 (issue #325 says they need a document-wide event ordering) |
| ProvToolbox `prov-validation` (Java) and the ProvValidator service [9][10] | Implements normalisation, uniqueness, inference, type and event-ordering with Floyd-Warshall on a sparse event matrix (source: `EventMatrix.java`, `Validate.java`, validates top level and each bundle separately) | ProvToolbox 2.2.2 (2023-09-28) is the latest release I found. Worst case cubic in event count; JVM start per file dominates if run as a CLI, so call the library in one JVM | I could not confirm a documented CLI `validate` option; the service page lists no constraint coverage; independent per-bundle only; reads PROV-JSON via its `core.json` package |
| `prov-check` (SPARQL, rdflib driver) [11] | All constraints; 279/280 W3C test cases, per its README | Not measured; SPARQL 1.1-heavy, alpha, last updated 2021 | Qualified-form PROV-O only; needs TriG per bundle (AgentPROV produces TriG on demand, E.5.4); "super alpha" |
| `checker.pl` (Prolog, Cheney) and the SPIN version [7][12] | Reference-style second implementation | Not measured | Not packaged; SPIN version is incomplete |
| SHACL (pySHACL) [13][26] | Local shapes (typing, required attributes, cardinalities) only | Not measured | No official PROV-CONSTRAINTS shapes; Nexus shapes are data-management oriented; the 2018 W3C thread and a 2025 data-shapes discussion say the constraints were never done in SHACL [13]; ordering needs transitive closure (SHACL-SPARQL) |
| Moreau canonical form [14] | Equality, signature and validation independent of encoding; applies to invalid documents too | Benchmark dataset published [14][snippet] | Not an off-the-shelf validator; relevant to hashing and signing, which AgentPROV already does through JCS |

Recommended plan (inference): keep the Python tier 4 as the only full-corpus validator (extended with P1); run ProvToolbox
as an independent oracle on a stratified sample and on W3C test cases; do not build a SHACL layer unless external reviewers
need one.

## 4. Provenance for AI / LLM agent systems

**Prior work.**
- PROV-AGENT (Souza et al., eScience 2025): extends PROV with `AIModelInvocation` and `AgentTool` activities, `Prompt`/`ResponseData`
  entities and an `AIAgent` agent; tool activities are linked to model invocations by `wasInformedBy`; `ResponseData` is attributed to the agent;
  error propagation is traced through `wasInformedBy`/`used`/`wasGeneratedBy`, never `wasDerivedFrom`. Stated limits: LLMs only, minimal
  agent metadata, preliminary single-use-case evaluation, no threats section [19][opened].
  Contrast with AgentPROV: NE-4 refuses attribution of composite outputs, and NE-1/NE-7 forbid `wasInformedBy` without a witnessing entity.
- Survey "From Agent Traces to Trust" (arXiv 2606.04990): keeps PROV base relations (Use, Generate, Derive) and adds Support, Depend-on,
  Contradict, Invalidate, Trigger, Update; lists unmet needs (claim-level support, evidence vs citation, contradiction, memory invalidation,
  tool-argument influence, inter-agent responsibility); notes granularity trade-offs and proposed but undefined quality metrics [20][opened].
- Agent-BOM (arXiv 2605.06812) and "Correct Is Not Governed" (arXiv 2608.12761) are agent-audit graph/provenance-integrity papers that do not use
  W3C PROV in their abstracts [23][opened]. I did not read their full texts.

**OpenTelemetry GenAI semantic conventions.** Now maintained in `open-telemetry/semantic-conventions-genai`; all agent, tool and inference span
conventions are `Development` status, so names can change [21][opened]. Relevant parts:
- Operations include `chat`, `invoke_agent`, `execute_tool`, `plan`, `retrieval`, memory operations; `invoke_agent` spans are CLIENT or INTERNAL;
  `execute_tool` is INTERNAL and "SHOULD NOT record two different spans for one call" [21][opened].
- `gen_ai.conversation.id` is conditionally required "if and only if the library has one readily available", `gen_ai.response.id`, `gen_ai.tool.call.id`,
  `gen_ai.request.previous_response.id`, `gen_ai.request.stream` and time-to-first-chunk exist; tool call arguments/results and message content are opt-in [21][opened].
- I found no retry-specific rule in the agent-spans, inference or spans files I searched.
- Spans form a trace tree (parent/child) plus separate span links for causal relations [22][snippet]. **(inference)** A parent span is closer to
  "started by"/"part of" than to PROV communication, so mapping parent-child to `wasInformedBy` would overstate data-mediated causality. I found no
  published OTel-to-PROV mapping.

**Modelling difficulties, with the position AgentPROV has already taken (EF).**
| Difficulty | PROV constraint or text | AgentPROV position | Residual risk |
|---|---|---|---|
| Context window as entity | PROV has no closed world; `used(a, collection)` does not entail `used(a, member)` [2][1] | Per-message `used` with `apv:contextIndex`; collection mode deferred (E.6) | Large `used` fan-out; class INFERRED for reconstructed context |
| Tool-call ids | ids are provider strings, may repeat across turns | `apv:providerCallId` attribute; pairing evidence class by method (OBSERVED, DERIVED, INFERRED) | Positional pairing is INFERRED; duplicated ids across calls need uniqueness lint (PI-28) |
| Retries | PROV has no retry relation | `apv:retryOf` attribute, never a relation | Retry chains are invisible to PROV traversal; document |
| Streaming | generation is the instant an entity is completely created [2][opened] | Response entity generated by the call activity; no per-chunk nodes | Partial/failed streams: `apv:outputStatus` and `Gap`, not partial entities |
| Multi-agent hand-offs | start by trigger entity implies the trigger was generated by the starter (Inf. 9) [1] | `wasStartedBy` (`spawn`, `authorise`), `actedOnBehalfOf` | PI-12 lints; delegation implies associations (Inf. 14) |
| Decisions/defences that rewrite content | revision chains via `wasDerivedFrom` (`prov:Revision`) | separate `Decision` activity, redaction as derivation | Only strict-order source in the graph (PI-04): keep acyclic |
