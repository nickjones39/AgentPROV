## Items 98–100 (D-530, D-560; session phase-10i follow-up; user-approved 2026-10-14/15; held branch `phase-10i-context`)

Write-up: `docs/reports/phase10i/D-530-archive-context-pin.md`. Trial evidence: `docs/reports/phase10i/README.md` §10.

- **Item 98: re-map with per-unit inputs** (`corpus/rawtree.py`, `corpus/derive.py`, one `import_source` hunk).
  - A re-map (`recompute`, `derive` of `expand`/`aer`, `verify --level rederive`) rebuilds the context trees and
    pinned objects a snapshot recorded.
  - `StoredRawTree` keeps context files and LFS objects out of the primary inputs. Without this, DTap's LFS pointer and
    its object collided on one label (`corpus.rawtree.invalid`).
- **Item 99: the CLI wires per-unit inputs** (`cli/import_.py`, runner hunks).
  - Declared context pins come from `--context ROLE=PATH` or the fetch cache; `--no-context ROLE` skips one.
  - A download pin is an archive context (RedCode Qwen Code's supplementary zip).
  - `lfs_object` pins give pinned objects, including for readers without per-unit inputs (MCPHunt).
- **Item 100: D-560.** Archive members that a profile `exclude` entry names are registered and counted in
  `selection_excluded`.

**What moves.**
- **`aer` stage `engine_code_sha256`** (`adapters/runner` + `aer`, class 1), on the pre-round integration premerge
  (2026-10-21): `sha256:6f85c964…63ed93a7` (integration head `2c69be39`) → `sha256:882fcbc7…3f1806`
  (`phase-10i-context-premerge`). Only `adapters/runner/importer.py` differs under those directories. Earlier predictions
  were `856b7a09…` → `10359560…` (against `0f668fdf`) and `7e71c65f…` → `be047ce3…` (against `da2e0252`). Any later commit
  to `adapters/runner/` or `aer/` on either side moves it again. It moves for every corpus at its next import or re-map.
- **No `expand` code digest moves.** A first build added `RawObjectStore.locate` to `raw/store.py`, which is an
  `EXPAND_MODULES` file, so it would have moved every archive corpus's `expand` digest. The premerge reads the stored
  object's path in `corpus/rawtree.py` instead (`StoredRawTree._locate`), and `raw/` is untouched. `cli/` and `corpus/`
  are in no stage digest.
- **One more `expand` stage definition** for each corpus with an archive context (none stored today).
- **Register rows and `selection_excluded` counts (D-560)** for archive-input corpora with `exclude` entries.
  AgentOps-Bench's import gains 3,842 `select.out_of_scope` rows and 4 `select.not_execution_artefact` patterns' worth
  of rollup rows. Others: `credleak-p15b`, `code-agent-misalignment-geminicli`, `seagent-agentdojo`,
  `controlarena-persistent`, and 10j's `authority-caps`/`ipi-defenses`. Their next import's `register.jsonl` and
  manifest counts differ by exactly those rows.
- **`snapshot.context[]`** gains `pin` (and `input` for an archive context) in working manifests built with a context
  tree. Sealed corpus-0.1 manifests carry no context entry.
- **`snapshot.context[].verification`** (pre-round review PR-1, 2026-10-22, class 2 for working manifests;
  user-approved in the deferrals window, D-221 addendum): a context tree the CLI resolves without a `PinCheck` records
  how it verified itself instead of `null`: `{kind: "download", verified: <stored>, unverified: 0}` for a download pin's
  archive (RedCode Qwen Code's and redcode-exec-openhands' `supp`), `{kind: "blob", ...}` for a git pin read from the
  fetch cache (DTap's and AgentOps-Bench's `tasks` with `--fetch`). A `--context ROLE=PATH` copy keeps its `PinCheck`
  counts (kind `blob`); a re-map carries the recorded value (NF-26). Without it, D-221's seal refused these
  corpora (`package.refused.unverified`).

**No AER, SEM or PROV byte changes for a corpus imported with its context.** A re-map now *restores* the joins that a
re-map used to drop. Before the change, the AgentOps-Bench trial showed 3,360 unexplained changes and DTap (no LFS) 40 of
48; with the change, `recompute --dry-run` is identical, which the regression tests check. DTap corpora with LFS objects
become re-mappable for the first time: their recompute gate never ran before.

**Expected after it lands.** `recompute` at main reports the `aer` stage digest drift for stored corpora (a
code-digest-only change). Archive-input corpora with excludes show the D-560 register rows as corpus-file differences
until they are re-imported in the round.
