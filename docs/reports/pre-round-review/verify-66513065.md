## Findings

**V-1 [fix before the round; class 0; owner core B]: raw-withhold #7 (6f1d6597) makes cached git commits count as
uncached when their acquisitions row records an absolute store path.**
- **Cause:** `Fetcher._git_cached` (`raw/fetch.py:1192-1202`) requires `row["store"]` to equal the cache-relative bare
  path exactly.
- **Effect:** the real `~/.agentprov/cache/acquisitions.jsonl` has 7 git rows written on 2026-10-08 with an absolute
  store. Two of the commits they cover have no relative row:
  - `c274885610ef`, the agentdojo-upstream profile pin, also named by adprov-v1;
  - `53c1fa98baed`, named by the inspect catalogue.

  For both, c4d7b785 gives `cached` and 66513065 gives `not cached`. So an offline `import --fetch` of them is refused
  (`raw.fetch.network_refused`, exit 4), and `verify`'s pin listing drops to unverified.
- **Probes:** `probes-ver/raw-withhold/probe_{git_cached,abs_rows,profile_pins,offline_fetch}.py`, all read-only on the
  cache.
- **Fix:** accept an absolute store that resolves to the same bare path, or migrate the 7 rows. Add a test with an
  absolute-store row.

**V-2 [minor; class 1; owner tier-4]: #18 follow-up.** Since #18, identical-byte header artefacts share one raw entity
with a multi-valued `apv:provPrimary`.
- **Cause:** `profiles._ne20` (`profiles.py:595-605`) still builds a last-wins scalar map.
- **Effect:** when the twins differ in `prov_primary` (native vs secondary), the engine's correct output fails PV-NE-20.
  This is latent: no stored AER has duplicate digests.
- **Fix:** compare sets, and parametrise the existing test.

**V-3 [minor; class 1; owner tier-4]: E-3 residual.** The pointer binding for the seven `LINKED_PREMISE_RULES` accepts a
pointer to any record one hop away, including the run or attempt scope and actor records.
- **Measured:** `assoc_tool` accepts 17/27 wrong records, `decision` 12/29, `n_model` 12/29, `gen_result` 7/29,
  `n_part` 4/29.
- D-621 records the one-hop design, but not that scope and actor records pass as evidence.
- **Fix:** exclude `/scope`, `/parent` and actor references from the link relation, or record the residual in D-621 and
  E.10.

**V-4 [minor; class 1; owner io/phase-12 security]: D #13 is fixed only partly.**
- **Cause:** the hook replaces `_posixsubprocess.fork_exec`, but `subprocess._fork_exec` was bound when `subprocess` was
  imported, before the hook.
- **Effect:** both paths still start a child process in a T1 worker with no audit event:
  - calling `subprocess._fork_exec`;
  - a fresh import of `_posixsubprocess`.
- G.4.4 (D-630) says only native code remains outside the hook.
- **Fix:** also patch `subprocess._fork_exec` and block the `import` event for `_posixsubprocess`, or correct G.4.4.
