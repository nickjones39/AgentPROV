AGENTDOJO TRACELOGGER (agentdojo head and 2024-06, agentdyn a/b/c, rope incl. rope-slice, survey agentdojo-runs, mandate). One JSON object per file and one execution per file. The variant is classified by the key set (adapters/agentdojo/dialect.py classify):
- A file is TraceLogger when it is a dict holding suite_name and user_task_id plus a `messages` or `conversations` list.
- v0.k11 = K11 {suite_name, pipeline_name, user_task_id, injection_task_id, attack_type, injections, messages, error, utility, security, duration}.
- v1.k14 = K11 + {benchmark_version, evaluation_timestamp, agentdojo_package_version}. The discriminator is agentdojo_package_version. If utility, security or duration is missing, the variant is v1.k14.incomplete.
- drift.k18.{messages|conversations} = files with `build_constraints`. KD18_BASE adds injection_isolation, dynamic_validation, adaptive_attack, tool_permission, initial_trajectory, initial_checklist and total_tokens, and has no injections, error or evaluation_timestamp.
- pre_v0 = no pipeline_name (git history only).
- Known fork extras (ROPE) are injection_attack_name, error_type and router_bucket. Any other extra key is kept and flagged.

Message list `messages`:
- Each message is {role, content}. system and user carry only those two keys.
- assistant adds `tool_calls`, a list of {function: str, args: dict, id: str|null|absent|"", placeholder_args?}.
- tool messages carry {role:"tool", content, tool_call_id, tool_call: {function, args, id, placeholder_args?}, error: str|null}.
- `content` is a str in v0.k11. In v1.k14 it is a list of blocks {type: "text"|"thinking"|"redacted_thinking", content}, or null. A null final assistant content signals up to 3 silent passes.
- `injections` maps injection vector -> payload string. `error` is the run-level error string or null.
- Outcomes are the bools `utility` and `security`, where security=true means the injection task succeeded (attack success). In `none` runs security is a benign constant, and in DoS attacks it is derived from utility.
- `duration` is float seconds.
- Timestamps: v0.k11 has none. v1.k14 has `evaluation_timestamp`, a naive local time with no zone (artefact naive_timestamp). There are no per-call times anywhere.
- Model id: never trust pipeline_name. Take it from the path facet each profile names: head/2024-06 pipeline_dir minus a defence suffix plus 4 identity rows; AgentDyn pipeline_dir via tables/agentdyn_pipeline_dirs.toml (model/defence/provider/variant/codebase; part by sniffed variant); ROPE model_dir (optional segment; ablation/* and router/* are gpt-4o-mini); survey results_dir slug; Mandate pipeline_name minus -mandate_<mode>.
- Layout templates (adapters/agentdojo/layout.py) are aligned from the right unless they have an optional `{x?}` component (ROPE). Facets: pipeline_dir|model_dir|results_dir, suite, task_dir, attack_dir, file stem. path_must_agree checks suite_name, user_task_id, attack_type and injection_task_id against the path.
- Facet values a sampler should key on, per part: head/2024-06 (pipeline_dir, attack_dir, suite, generation variant); AgentDyn a (table model x defence, attack, suite); ROPE (model_dir or arm tree, attack_dir, suite); survey (results_dir, attack, suite); Mandate (pipeline_dir, attack).
- Call-id style corroborates the provider: call_* = OpenAI, toolu_* = Anthropic, tool_call_?????????? = client random, chatcmpl-tool-* = vLLM, tool_* = Gemini via OpenRouter. Null ids come from local and Google models.
- Strays: skip .DS_Store and ._* files.

DRIFT build (agentdyn c and d): messages are DRIFT's re-serialised turns; tool outputs are post-isolation copies. There is no system message and no injection map. Calls can appear in text and are never executed.

ADPROV transcript/v1 (adprov-v1 release and converted-legacy). The release tree has one JSON object per <stem>.transcript.json, laid out as <model_folder>/prov/<attack>/<stem>.transcript.json.
- Each attack directory also holds a sibling <stem>.json (old PROV output, never a candidate). Every model folder has manifest.json, outcome_replay.json and checksums.sha256.
- Membership test: adprov_schema == "transcript/v1", with an object `meta` and a list `turns`.
- Top-level order is adprov_schema, meta, turns, optional discarded_attempts[{turns, reasoning_alignment?}].
- meta members, in order: model, model_id, suite, user_task_id, injection_task_id, attack_type, injections, utility, security, started_at, ended_at, wall_clock_s, agentdojo_version, benchmark_version. Optional: model_config (with usage), source, pipeline_name, timing_stubbed, run_error, reasoning_alignment, n_attempts, capture {complete, n_attempts, llm_calls_total, assistant_turns_total, passes[{pass, llm_calls, assistant_turns, tool_calls, tool_results, environment?}]}.

MESSAGES (/messages, a list in order; the fingerprint for L1-04 is this list). Each element has a role key: system | user | assistant | tool. Observed key sets:
- {role, content}: system and user messages.
- {role, content, tool_calls}: assistant messages.
- {role, content, tool_call_id, tool_call, error}: tool messages.

content: in v1.k14 it is a list of blocks [{"type":"text","content":<str>}] or null. In v0.k11 (CrAIBench) it is a plain string or null. Assistant content is null when the message only calls tools. A null content in the LAST assistant message triggers the silent-rerun quirk.

tool_calls: a list of {function:<str>, args:<object>, id:<str|null>, placeholder_args:null}, or null. ids are all null in kongminos, null in 1,848 gate calls and 877 ceferisbarov calls, and repeated in 1 gate log, so linking is positional.

A tool message carries:
