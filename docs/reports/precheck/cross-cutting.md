# Cross-cutting findings and canonical classes

Set 2026-10-15 after the wave-1 completeness critic found the same artefact classed differently across corpora. Every
dossier applies these rules; a corpus finding that is an instance of a cross-cutting item cites its `CC-nn` id and uses
the class and severity given here (a corpus-specific count or consequence may raise the severity, with the reason).

## Classification rules

| # | Situation | Class | Severity |
|---|---|---|---|
| R1 | An upstream harness or checker defect visible in the data (an issue-tracker bug, a broken tool, a pre-fix checker) that **no** `artefacts.toml` entry or profile quirk covers yet | `source-defect`, with a proposed `artefacts.toml` entry | S2 if it biases an outcome metric, otherwise S3 |
| R2 | The same, already covered by an `artefacts.toml` entry, a profile quirk or a decision | `expected-known` (cite the id); if the existing entry's counts or scope are wrong, also a `documentation-mismatch` S3 for the entry | as the entry says; S3 otherwise |
| R3 | A paper, README or results-page number that the released logs do not reproduce, where the logs are internally consistent | `documentation-mismatch` (the source's documentation, not our code) | S2 if a headline number of the paper, S3 otherwise |
| R4 | Our own docs (census, profile comment, regen-batch, registry note) disagree with the data or the engine | `documentation-mismatch`, routed to the owner of the doc | S3 unless it changes a manuscript number |
| R5 | A property of a pre-check tool (not of the corpus) | `analysis-artefact`; never counted as a corpus finding in the readiness verdict | S3 |
| R6 | A difference between the pre-check sample and the paper that the sample design explains (stratified draw, 1 per stratum) | not a finding; report the post-stratified rate and the L1 population rate beside it | — |
