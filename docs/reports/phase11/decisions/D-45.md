# D-45: `render` is on demand only; `--all` is removed and `--select` needs `--limit` (phase 11, U7)

Status: implemented on branch `phase-11-u7`, for consolidation into DECISIONS.md by the orchestrator.
Code: `src/agentprov/cli/render.py`. Tests: `tests/cli/test_cli_render.py` (`test_there_is_no_render_all_option`,
`test_select_without_limit_is_a_usage_error`, and the former `--all` cases, now `--limit N`).

## Decision

1. **No render-all.** `agentprov render` has no `--all` option. A bare `render --corpus DIR` is a usage error (exit 2,
   "nothing selected"), as before. `--all` is an unknown option (exit 2).
2. **Allowed selections.**
   - `--ex ID...`: the named executions (bounded by what the user typed).
   - `--limit N`: the first N executions with PROV output, in index order.
   - `--select KEY=VALUE[,VALUE...]` **together with** `--limit N`. A filter alone can match every execution of a corpus
     (for example `--select suite=workspace` on 20,000 logs), so it is a usage error (exit 2) without `--limit`.
   - `--ex` with `--limit` and `--ex` with `--select` keep working; `--limit` truncates after the filter.
3. **What did not change.** Output location and the output guard (never inside a corpus, exit 4), `--bundle`,
   `--format`, `--show-content`, `--jobs`, `--dry-run`, determinism, exit codes, and the skip of executions that have no
   `agentprov-prov/0.1` output.

## Why

The user's phase-11 rule (PLAN rule 5, 2026-10-11): renders are on demand for selected single executions and never a render
of every graph. N.2.13 (as built, phase 7) listed `--all` as one of four ways to select; with 18,000 to 35,000 executions per
corpus and one Graphviz process per graph, an `--all` (or an unbounded `--select`) is a job of hours that nobody means to
start from a shell. Removing the option makes the safe behaviour the only one. A research workflow that needs many graphs
asks for a count and gets exactly that many.

## Rejected alternatives

- **Keep `--all` behind a confirmation flag (`--i-really-want-all`).** Still a render of every graph is one flag away; the
  user's rule says it must not exist.
- **Require `--limit` for every selection, `--ex` included.** `--ex` already names a finite, typed list; a limit on it
  adds nothing.
- **A hard upper bound on `--limit` (for example 1000).** A number the user typed is a deliberate bound; an invented cap
  would be arbitrary and would need its own flag to lift.
- **Keep `--select` alone and warn.** A warning does not stop a long run.

## Downstream effects

None on AER, SEM, PROV or corpus bytes, the compat gate or any manifest. The N.2.13 text ("one of `--ex`, `--select`,
`--limit` or `--all`", and the synopsis) and K.5.12 need the as-built note: `--all` removed, `--select` requires `--limit`.
