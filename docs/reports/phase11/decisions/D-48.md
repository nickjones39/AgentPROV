# D-48: `agentprov stats` and `agentprov.api` design choices (phase 11, U6)

Status: implemented on branch `phase-11-u6`, for consolidation into DECISIONS.md by the orchestrator.
Code: `src/agentprov/stats/` (`__init__.py`, `source.py`, `tables.py`, `fieldgroups.py`, `field_groups.toml`,
`exclusions.py`, `output.py`), `src/agentprov/cli/stats.py`, `src/agentprov/api.py`; `formats.py` gains
`agentprov-stats/0.1`. Tests: `tests/unit/stats/`, `tests/cli/test_cli_stats.py`, `tests/cli/test_public_api.py`;
output schema (test asset, M.1.10 row 6 precedent): `tests/cli/schemas/stats-0.1.schema.json`.
Spec: MN N.2.12, M.6, M.5; K.5.11; HL H.8.1; G.8.6; O.3.5; C.3.16; PQ Q.32; D.15.4; D.16.17 items 3-4.

## Decision

1. **One streamed pass per corpus, never pooled.** `compute(corpora, tables)` opens each corpus with
   `CorpusReader` (strict, read-only, chain-checked) and streams the index once; per row it reads the AER only when
   `unknowns`/`field_groups` (agent executions) or `--artefacts` need it, and the PROV file only for `statements`.
   Single process: N.2.12 asks for no `--jobs`. A file that cannot be read is a per-execution *failure* (counted by
   code in `failures`, listed in the CLI summary, exit 1), never a silent skip. Output carries no path and no clock.
2. **Verification.** A corpus is opened with `verify="checksums"` (N.2.12). A sealed corpus runs the H.5.5 `checksums`
   level (U1's `verify_checksums`, closed world); on failure the corpus gets **no tables** (its entry holds its identity
   and the finding codes) and the command exits 1. A working tree has no `checksums.sha256` (H.5.3 writes it at
   sealing), so it is `verification: "not_sealed"` and a notice recommends `agentprov verify`. `chain` and `rederive`
   raise `VerifyLevelUnavailable` (exit 5) until U4 implements them.
3. **Identity label** (N.2.12, H.8.1): `corpus_id`, `state`, `verification`, `content_digest` (the recorded one when
   sealed; computed by H.5.4 from the working manifest otherwise, `null` if that is not corpus-layer JSON) and
   `root_digest` (sealed and verified only). The report carries `fn_digest` (sha256 over the stats package's `*.py`
   and `*.toml`, framed by name and length) and `field_groups_sha256`, so a cache keys on `(content_digest, fn_digest)`.
4. **Grouping key** of every table is `(source_id, profile)`: the profile distinguishes parts of one source in one
   corpus; a consumer may aggregate counts, never rates (O.3.5 poolability).
5. **Counts.** Records by index `status`, `unit`, `execution_observed`, `completeness`; `n_executions = unit ==
   agent_execution ∧ execution_observed` (R-28); `n_outcome_only`; `prov_output` (rows with output for the spec);
   `rate_excluded` (item 10); `registry_parts` and `registry_import_status` from `adapters.registry` (I.5.1: the
   registry is the only status store; the claims library's *phrases* wait for `adapters/registry/claims.py`, U3).
   `register` counts register entries by `(stage, code, severity, disposition)`; with `--select`, only entries whose
   subject is a selected `ex`.
6. **Statements** are recounted from the stored PROV-JSON (the engine's `DerivationReport` is not stored). A statement
   is an entry of a PROV-JSON section that carries `apv:evidenceClass`; `evidence` is the letter `O`/`D`/`I`
   (`apv:Observed`/`Derived`/`Inferred`). Bundle kinds come from the E.4.2 bundle IRI (`xd:bundle.core.<dk>`,
   `xd:bundle.inf.<method slug>.<dk>`, `xd:bundle.assess.<profile slug>.<dk>`); top-level sections are `toplevel`;
   `method` is the slug. Entries without a class (the unidentified `specializationOf`, `mentionOf`, `hadMember`) go to
   `statements_structural`, so class totals equal the statement total (K.5.11 item 2). A rule id outside the shipped
   `aprov` catalogue (only checked for `agentprov-prov/0.1`) is counted under its escaped text and as failure
   `stats.prov.rule_unknown`; an unknown bundle IRI or section is a per-execution failure. `--per-execution` adds
   `statements_by_execution` (`ex × bundle × method × stype × evidence × rule → n`, O.3.5's `statements` frame); the
   aggregate table is its sum (tested). `--prov-spec adprov-v2.3-compat` counts compat graphs and prints the R-55
   notice.
7. **Field groups.** `field_groups.toml` is the data form of C.3.16 (selectors: `record`, `where`, `absent`,
   `named_by`, `refers`, `parts`, `pointer`, `array`, `fallback`; unknown keys refused; the ids must be O.3.5's list in
   order). Evaluation follows C.3.16 with these resolutions where the text is silent:
   - an `unk` key at the pointer, enclosing it, or below it makes the occurrence `unk:<reason>` (C.3.16 verbatim); for
     an array field a key *below* the array pointer is attributed to the item it names, not to the whole array;
   - a known-empty array (C.2.3) is one occurrence at the array pointer (an asserted value), not zero;
   - "weakest": `O` > `D` > `I` > every `unk`, and among reasons the first in C.7.1's order is the weakest; "stronger
     of the alternatives" uses the same order, and on a tie a declared status beats an undeclared one;
   - an occurrence is *undeclared* when its pointer is absent with no `unk` covering it (reported as `not_recorded`,
     counted separately in `undeclared`); a cell is undeclared when its status is `not_recorded` and every
     `not_recorded` occurrence behind it was undeclared;
   - `link`: `tool_execution /call`, else `/requested_by` when `/call` is absent and undeclared (`fallback`).
8. **Coverage denominators.** `coverage = (O + D) / (cells − not_applicable)` and `observed_share = O / (cells −
   not_applicable)` per `(source, profile, group)`; `cells` counts executions in the population that have at least
   one occurrence of the group (C.3.16: no occurrence, no cell), so a run without tools does not lower `t_tool`. A group
   with no cell has `coverage: null`. Row `group = "all"` sums every (execution, group) cell (O.3.5
   `fg_coverage_pct`). Rates are floats rounded to 6 decimals (JCS-stable); the integer counts are always given.
9. **Unknowns** are reported per occurrence source (`group`, `occurrence`, `record`, `pointer`): counts of the ten
   statuses, `undeclared`, and `share_<status>` columns summing to 1 (K.5.11 item 3 "per field pointer").
10. **Rate exclusions are family data, never code** (D.16.17 item 4; CLAUDE.md rule 9). `stats` holds no source name
    and no source-specific issue code (a test scans the package for every registered source id). Exclusions are read
    from `agentprov/adapters/<family>/rates.toml`, found as package data without importing an adapter module:

    ```toml
    version = 1
    family = "dtap"                              # must equal the directory name
    [[exclusion]]
    id = "dtap.rate.unresolved_rerun"            # <ns>.rate.<name>
    profiles = ["dtap-bench"]                    # profile ids in scope (required)
    issue_codes = ["map.dtap.unresolved_rerun"]  # index-row issue codes (register codes, H.6.3)
    judgement_origins = ["harness_default"]      # C.3.10 origins an outcome rate leaves out
    rates = ["field_groups", "unknowns", "outcome"]
    basis = "D.16.10"
    ```

    `field_groups`/`unknowns` exclusions remove matching executions from those populations (column `excluded`);
    `outcome` and `judgement_origins` are reported in the output's `exclusions` list for outcome-rate consumers (stats
    v0.1 computes no outcome rate). No family ships a `rates.toml` yet; phase 10b (DTap) adds one in its own directory.
    Outcome-only and scenario records need no declaration: they are outside every population by `unit` (R-28).
11. **Message roles as data** (D.16.17 item 3; D-28). `field_groups.toml` `[message_roles] assistant = ["assistant",
    "agent"]`: a `where = { role = "assistant" }` filter on a `message` record matches either verbatim role. It does not
    apply to `model_call.role` (the C.3.5 gateway role).
12. **Output** (`output.py`): JSON = JCS + LF (schema-checked in tests); text = aligned tables; Markdown = pipe tables;
    CSV = one block per (corpus, table) with `corpus_id,table,` leading columns, blank line between blocks, and a `'`
    prefix on string cells starting with `= + - @` (spreadsheet formula guard). Data-derived labels (model ids, unknown
    rule ids, notice details) pass `escape_untrusted` (G.8.6); no content string is ever read into a table.
13. **CLI.** `--corpus` repeatable (the same corpus twice is a usage error); `--tables` (default all four);
    `--artefacts`; `--per-execution` (requires `statements`); `--prov-spec`; `--select K=V[,V…]` over index-row
    members (`source_id, profile, unit, status, mode, completeness, execution_observed, adapter, snapshot`) and
    `facet.<name>` (full rows only); `--format`; `--out` (atomic; refused with exit 4 inside any corpus or sealed tree,
    G8). With the global `--json`, the summary takes stdout and the payload goes to `--out` or stderr (as `info`).
14. **`--artefacts`** calls `agentprov.artefacts.scan` per selected execution (every unit; the net handles
    outcome-only records) with the records of the execution's first SEM document (sorted profile reference) when it
    has one, and `table()` per `(source_id, profile, model)`; `model` is the sorted, escaped `model.requested` of the
    `llm_agent` actors, or `null`.
15. **`agentprov.api`** (M.6) re-exports the stats objects (`Corpus` = `StatsCorpus`). Deviations, all reported in the
    module docstring: `read_aer(row, corpus=…)` (a row alone does not locate its corpus); `verify_corpus` implements
    `checksums` only; `rows(corpus, "lineage")` raises `ApiUnavailable` until U3's manifest `sources[].lineage`;
    `check_claim`, `coverage_phrase`, `lint_text` delegate to `adapters.registry.claims` and raise `ApiUnavailable`
    until U3 ships it; `semantics_profile` returns `{id, version, sha256, files}` with TOML files parsed (no adapter
    module imported).

## Rejected alternatives

- **Reading the engine's report** for statement counts: it is not stored in a corpus; recounting the stored PROV-JSON
  is what K.5.11 item 2 demands anyway ("equal an independent recount").
- **Hard-coding exclusions** (e.g. by issue-code names or source ids) in `stats`: forbidden by D.16.17 item 4.
- **Extending the artefact or rule catalogue schema** with exclusion keys: both parsers refuse unknown keys and are
  owned elsewhere (`artefacts/`, `aer/rules`); a separate per-family data file keeps `stats` the only reader.
- **Executions without a cell in the coverage denominator**: it would make sources without tool calls or reasoning
  look lossy; C.3.16 says such a group yields no cell.
- **Pooling rows across corpora or profiles**: N.2.12 and O.3.5 forbid pooled rates.
- **`--jobs`**: N.2.12 does not ask for it; the smoke runs take seconds per thousand executions (stats-smoke.md).

## Downstream effects

No AER, SEM, PROV, index or manifest byte changes; no corpus is written. `formats.py` gains one id. `cli/main.py`
registers `stats` (COMMANDS gains one entry). The schema is a test asset, not a published schema.
