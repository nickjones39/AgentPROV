# D-42: licence classes in deposits; the offline deposit builder and its archive format (phase 11, U5)

Status: implemented on branch `phase-11-u5` (U5). Builds on AD-20(b), D-25 and the user's rulings of 2026-10-11
recorded in `PLAN.md` (derived licence `inherit` for every corpus; `ast-survey-agentharm` its own restricted-use class;
GPL-3.0 and AGPL-3.0 sources each their own corpus and class; CC-BY-NC sources in a separate `-nc` corpus under
`nc_partition`; mixed classes refused). For consolidation into DECISIONS.md by the orchestrator.
Code: `src/agentprov/release/{__init__,builder,metadata}.py`, `src/agentprov/cli/deposit.py` (dispatched from
`cli.package.DEPOSIT_HANDLER`), `tools/release_scan.py`; format ids `agentprov-deposit-manifest/0.1` and
`agentprov-release-scan/0.1` added to `formats.AS_BUILT_FORMATS`. Tests: `tests/unit/release/`,
`tests/cli/test_package_deposit_cmd.py`, `tests/boundary/test_release_offline.py`. Rehearsal:
`docs/reports/phase11/deposit-rehearsal.md`.

## Decision

1. **Licence class.** The class of a sealed corpus is `(licences.derived.spdx, sorted licences.restrictions)`, read from
   its manifest and checked equal to the recorded `licences.class` (H.2.10). SPDX ids compare exactly, so `GPL-3.0-only`,
   `GPL-3.0-or-later` and `AGPL-3.0-only` are three classes (D-25), and two corpora whose restrictions differ in any
   clause are two classes (`ast-survey-agentharm`, U-05).
2. **One class per deposit.** The builder refuses corpora of different classes in one deposit (exit 4,
   `release.refused.mixed_licence_classes`) unless `--allow-mixed-licence-classes` is given (MN N.2.11's flag). The
   override is recorded in `deposit-metadata.json` (`mixed_licence_classes`), in `DEPOSIT-MANIFEST.json` and in a
   "Deposit note" appended to each `DATASHEET-<id>.md` copy; the sealed corpus is never modified (AD-SW12).
3. **Non-commercial partition.** A non-commercial class (an SPDX id with an `NC` component) is admitted only in a corpus
   whose id ends `-nc`, whose licence policy is `nc_partition` and whose redistribution is `permitted-non-commercial`;
   an `-nc` corpus must carry a non-commercial class. An `-nc` class is never mixed with another class, **even with the
   override** (H.4.2: "a separately licensed `-nc` corpus and deposit"; `release.refused.nc_partition`).
4. **No relicensing of copyleft or NC sources.** When a source's SPDX id is GPL/AGPL/LGPL or non-commercial, the derived
   licence must equal it (D-25). With `derived = "inherit"` (D-44) this always holds; the check guards a later
   user-decision licence.
5. **Withhold and forbidden.** Raw policy `withhold`, licence policy `forbidden` or redistribution `not-permitted` are
   refused (exit 4; H.4.1, H.10.1(4)).
6. **Other preconditions** (H.10.1, G.9.4, N.2.11; each refuses before anything is written): release mode below CPython
   3.14.8 exits 3 (`envinfo.require_patched_for_archive(release=True)`, no override, Q.15a); an `interpreter_advisory`
   corpus exits 4; an unsealed, working or `.partial` tree exits 4; `release.status` must be `sealed`; strict validation;
   no `test_only` live corpus; the manifest validates (exit 1 otherwise); the corpus verifies (exit 1); a release scan for
   the same root digest with every finding triaged and none `real` unless `WITHHELD.json` names its fingerprint (exit 4;
   no scan result is a refusal, never a skip); a corpus with a `views/` tree exits 5 (views are not deposited in v0.1,
   AD-10 row 12, and a deposit without them could not pass archive-mode `verify`'s closed world).
7. **Offline by construction.** `agentprov.release` imports no network or process module and calls nothing named upload or
   publish (static test); importing it loads no network module (dynamic test); a build under a patched `Popen`/`socket`
   succeeds (behaviour test). The gitleaks run lives in `tools/release_scan.py`. The release scan, the verifier and the
   claims lint are injected (`scan=`, `verify=`, `lint=`), so the builder needs neither gitleaks nor U4.
8. **Release scan document** (`<corpus>.release-scan.json`, `agentprov-release-scan/0.1`, beside the sealed tree and
   outside its checksums): `target {kind: corpus, corpus_id, corpus_version, root_digest}`, `tools [{name, version,
   mode}]` (gitleaks 8.30.1 and the home-path/host-name search), `findings [{detector, rule, path, line, fingerprint =
   "<path>:<rule>:<line>", triage, reason}]`, `summary`. gitleaks runs `dir --redact --ignore-gitleaks-allow` with an
   explicit default-rules config and an empty ignore path in a reduced environment, so nothing inside scanned data can
   change the rules or hide a finding. No matched value is recorded. Triage is read from a reviewed TOML file.
9. **Archive format** (the contract for U4's archive-mode `verify`, D-38). Names `<id>-v<ver>.meta.zip` and
   `<id>-v<ver>.<stage>.<nnn>.zip`, stage ∈ `raw` (`raw/objects`), `aer`, `sem-<profile_dir>`, `prov-<spec_dir>`,
   `nnn` from `001`. Members `<id>-v<ver>/<corpus path>`, regular files only, sorted bytewise; `date_time` = release date
   00:00:00 clamped to 1980-01-01; `create_system = 3`; `external_attr = 0o100644 << 16`; DEFLATE level 6; no extra
   field, comment or data descriptor; no ZIP64 (archives and members below 2^31 − 1 bytes, at most 65,535 members). The
   meta archive holds everything outside those stage trees, `checksums.sha256`, `rules/` and `schemas/` included.
   Splitting is on shard boundaries (`raw/objects/<h0h1>`, `<ss>` of execution files), never inside one, planned on a
   deterministic upper bound of each member's stored size (`size + size // 2048 + 16` plus headers), so archive
   membership depends only on the corpus and never on the zlib version; archive bytes are reproducible with the same
   zlib (recorded). Each member is re-hashed while written and compared with `checksums.sha256` (exit 1 on change).
10. **`DEPOSIT-MANIFEST.json`** (`agentprov-deposit-manifest/0.1`): `status: draft-unpublished`, `release_date`,
    `archive_policy`, `producer` (AgentPROV version, git commit and cleanliness, Python, zlib), `licence_classes`,
    `mixed_licence_classes`, per corpus `{corpus_id, corpus_version, title, content_digest, root_digest, licence_class,
    member_prefix, verification {level}, release_scan {tools, findings, by_triage, scan_sha256, root_digest}, coverage
    {files, archived}, archives}`, per archive `{name, bytes, sha256, md5, corpus_id, corpus_version, stage, shards
    {first, last} | null, n_members, uncompressed_bytes, members_sha256}` with `members_sha256 = "sha256:" + sha256` of
    the sha256sum-format listing `<hex>  <member name>\n` sorted by name, and `documents` (README, CHANGELOG, datasheet
    copies, metadata) with sha256 and md5.
11. **`deposit-metadata.json`** (`agentprov-deposit/0.1`): `status: draft-unpublished`; `concept_doi` only from
    `release.toml`; `version_doi` always null (assigned at publication; never invented); `related_identifiers` only from
    `release.toml` and from what the sealed corpus records (the digest-checked source profile copy's `concept_doi` and
    arXiv `paper`, the snapshot's pinned git origin as a commit URL, alternative-origin DOIs, arXiv ids in
    `licences.attribution`), each with its `origin`; `licences` per class; `release_scans` (scanner versions);
    `root_digests`; `software`. `release.toml` is closed and checked (DOI, ORCID, DataCite relationType and
    relatedIdentifierType); a malformed file is a usage error (exit 2).
12. **Deterministic.** Two builds of the same sealed corpora with the same inputs are byte-identical, including from two
    independently copied seals (Q.20). The draft is written in `OUT.partial` and renamed; `OUT` must not exist, must not
    overlap an input corpus, and (CLI) must be outside every git work tree unless git-ignored.

## Rejected alternatives

- **Letting the override mix an `-nc` class.** H.4.2 requires a separately licensed `-nc` deposit; a record-level licence
  would misdescribe either part.
- **Splitting on actual compressed sizes.** Exact, but archive membership would then depend on the zlib version; the
  upper bound costs some archive-size headroom (JSON compresses roughly 5-10x, so archives stay far below the limit) and
  keeps membership content-determined.
- **ZIP64 for the spec's `2**31` default.** H.10.4 forbids extra fields; the default is `2**31 - 1`.
- **Running gitleaks from the builder.** H.10.1 and G.9.4 require the builder to be offline with no subprocess.
- **Silently skipping a missing scan or verification.** G.9.4 requires a scan result; its absence refuses.
- **Copying `release-scan.json` into the deposit.** Not in H.10.3; its digest, tools and triage counts are recorded
  instead.

## Deferred

- `verify --level chain` before archiving (H.10.1(3)): U4 supplies it through `verify=`; until then the built-in check is
  the `checksums` level (closed world) plus the manifest validator, and the recorded level says so.
- Archive-mode `verify` of the deposit (HL-T9 last clause; D-38): U4. The tests read archives in memory only.
- A `synthetic` corpus marker (N.2.11) does not exist in the v0.1 manifest; only `live.test_only` is checked.
- Separate concept DOIs per licence class (H.10.6): decided when the first non-permissive deposit is prepared.

## Release-scan rulings (user, 2026-10-11)

- **AgentPROV's own keys are known false positives.** `tools/release_scan.py` runs gitleaks with one committed
  allowlist, `_KEY_ALLOWLIST`, matched against the whole match (`regexTarget = "match"`, anchored):
  `^(derivationKey|subject_key|logical_key)":"((ex|lk)_)?[a-z2-7]{26}"$`. It hides exactly those
  content-addressed keys (`apv:derivationKey` in PROV bundles, `subject_key` in the register, `logical_key` in the
  index) and nothing else on the line; a secret elsewhere in the same JSONL record is still reported (tested against
  the real gitleaks). The scan document records the configuration digest (`tools[].config_sha256`).
  Rejected: triaging these findings by fingerprint per corpus (thousands per corpus, repeated at every release);
  a line-level allowlist (a JSONL record is one line, so it would hide real secrets in the same record).
- **AgentHarm's credential-shaped strings are fake benchmark values.** The gitleaks findings inside the AgentHarm
  benchmark content of `ast-survey-agentharm` (114 in the rehearsal) are triaged `synthetic-benchmark`, reason "user,
  2026-10-11: AgentHarm credential-shaped strings are fake benchmark values". Triage stays per fingerprint and per
  sealed root digest (the triage file is written for the real release); home-path and host-name findings are not
  covered by this ruling.
