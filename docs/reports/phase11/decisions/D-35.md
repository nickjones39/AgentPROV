## Decision

1. The June-2024 (`c274885`) and head (`089ed468`) working trees, which both record `corpus_id: agentdojo-upstream`,
   become **two corpora**, `agentdojo-upstream-2024-06` and `agentdojo-upstream-head` (D-27 c2), each with one snapshot,
   built from the one source profile `agentdojo-upstream@1`.
2. **The corpus id is taken from the corpus spec at sealing** (`corpora/<id>/corpus-spec.toml`, H.1.6), never from the
   working manifest; the working directory name is informative only (H.1.2).
3. The two corpora deliberately share content-addressed execution ids (14,182 shared runs, examination 2 §7.3); the
   datasheet says so (datasheet-items.md row 3) and pooled analyses deduplicate by execution id.
4. **Check that the corpus id appears in no AER/SEM/PROV bytes** (done read-only on 2026-10-11 over every phase-10
   working corpus; 300 seeded-sample files each of AER, SEM and PROV per corpus): no file holds a `corpus_id` member, and
   none of the sealed ids `agentdojo-upstream-2024-06`, `agentdojo-upstream-head`, `agentdyn-a`, `ast-survey-agentdojo`,
   `ast-survey-agentharm` or `adprov-v1-release` occurs. Where a corpus id equals another identifier (the profile ids
   `agentdojo-upstream`, `adprov-v1`, `agentdyn`, `mandate-agentdojo-eval`, `rope`), the occurrences are that
   identifier: AER `profile.id` and `artifacts[].origin.repo`, PROV `apv:originRepository`, and for `rope` the rule
   namespace and source text. Renaming a corpus therefore changes no AER, SEM or PROV byte and no golden digest.

## Why

A corpus has one source but may have several snapshots (H.1.1); the user chose two corpora so that each snapshot is
released, versioned and cited on its own and the head tree's generation mixing does not enter the June-2024 corpus.
Keeping the id out of the derived records is what lets the same execution id stand in both.

## Rejected

- One corpus `agentdojo-upstream` with both snapshots (H.4.2's original layout): rejected by the user's ruling.
- Corpus-scoped execution ids (two ids for identical bytes; D-27 c2).
- Re-importing to change the working manifests' `corpus_id` (rule 3: no corpus is regenerated).
