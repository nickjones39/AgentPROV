# D-44: corpus specs in git; the eight v0.1 corpus directories; derived licence `inherit` (phase 11, U3)

Status: implemented on branch `phase-11-u3` (U3); user rulings of 2026-10-11 (derived licence `inherit` for every
corpus; `ast-survey-agentharm` is its own restricted-use class). For consolidation into DECISIONS.md by the
orchestrator.
Code and data: `.gitignore` (the MN M.3.1 negations), `corpora/<id>/{corpus-spec.toml,CARD.md,CHANGES.toml}` for
`adprov-v1-release`, `agentdojo-upstream-2024-06`, `agentdojo-upstream-head`, `rope`, `agentdyn-a`,
`mandate-agentdojo-eval`, `ast-survey-agentdojo`, `ast-survey-agentharm`; `corpora/datasheet-statements.toml`;
`src/agentprov/corpus/spec.py`. Tests: `tests/unit/corpus/test_spec.py`.

## Decision

1. **`.gitignore`.** `/corpora/` is replaced by M.3.1's `/corpora/*/*` with the negations `!/corpora/*/corpus-spec.toml`,
   `!/corpora/*/CARD.md`, `!/corpora/*/CHANGES.toml`: only the three data-free build inputs of each corpus are
   committable; anything else written under `corpora/<id>/` stays ignored. The decided statements table
   `corpora/datasheet-statements.toml` sits directly under `corpora/` (not matched by `/corpora/*/*`) and is committed
   too.
2. **The eight v0.1 corpora** each get a spec (H.1.6), a card (H.9) and a changelog entry for `0.1.0`. The spec names the
   source, the profile (`<id>@1`), the parts, one snapshot whose origin is the pin the phase-10 import recorded (D-33;
   checked against the in-package profile pins by a test), the derive stages (`agentdojo.suites@1` or
   `inspect.agentharm@1`; `agentprov-prov/0.1`, plus `adprov-v2.3-compat` for `adprov-v1-release` only, per D-37), raw
   policy `include`, and the licence block. Selection is the profile's `[import]` (the specs name none).
3. **Derived licence `inherit` everywhere** (`[licence] derived = "inherit"`, `decided_by` names this ruling): the derived
   SPDX id is the source's (MIT for AgentDojo, ROPE, AgentDyn, Mandate; CC-BY-4.0 for the survey corpora and the
   AgentDojo-PROV release). Licence facts (SPDX, holders, basis, attribution, restrictions, unassessed items) are read at
   sealing from the source profile's `[licence]` table, never typed into the spec.
4. **`ast-survey-agentharm` is its own restricted-use licence class**: its profile carries the AgentHarm use clause in
   `[licence].restrictions`, so its class is `(CC-BY-4.0, [the clause])`, distinct from `ast-survey-agentdojo`'s
   `(CC-BY-4.0, [])` (AD-20(b); U-05).
5. **Upstream licence files** (`[licence] files`, an as-built addition to H.1.6): the names of the verbatim upstream files
   written to `LICENSES/<source_id>/`. `package` takes each from the corpus's own raw store when the import stored that
   file at the pinned commit (Mandate's `LICENSE`), otherwise from `--licence-file NAME=PATH`, and records the
   provenance in the generated `NOTICE.md`.

## Open items (licence facts not recorded; marked TODO in the specs)

- `adprov-v1-release`: which verbatim text is the release's `LICENSE` (the CC-BY-4.0 legal code of the data stamp, or the
  agentdojo-prov repository `LICENSE` at `579a908`, MIT for code) is not recorded in the registry or the profile; and the
  file for the embedded AgentDojo MIT notice (`AgentDojo-LICENSE`). User decision.
- The upstream `LICENSE` (and AgentDojo's `CITATION.bib`) of AgentDojo, ROPE, AgentDyn and the survey are not in their
  corpora's raw stores (the imports select `runs/` or a subtree); they are supplied at sealing. A pinned copy of each
  (a context artefact of a future import, or a committed licence-text directory) would make sealing self-contained.
- The DTap-Bench corpus id is not fixed yet; its datasheet rows use `dtap-bench`.

## Why

H.1.6 puts the build inputs under version control next to the code that builds the corpus; M.3.1's negations make that
possible while keeping corpora out of git (invariant 6). Inheriting the source licence avoids any relicensing question
(U-03 default).

## Rejected

- Committing the whole `corpora/` tree or the licence texts under `corpora/<id>/` (only the three spec files are
  admitted by M.3.1).
- Copying licence facts into the specs (a second source of truth; the registry and profiles are the only one).
- A separate licence decision per corpus (the user ruled `inherit` for every corpus).
