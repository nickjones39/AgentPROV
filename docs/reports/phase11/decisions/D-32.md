# D-32: raw objects of `recompute --out` / `derive --out` are copied by default; `--link-raw` hard-links them (phase 11, U2)

Status: implemented on branch `phase-11-u2` (U2); user-approved 2026-10-11; for consolidation into DECISIONS.md.
Code: `Derivation._copy_objects` in `src/agentprov/corpus/derive.py`; option `--link-raw` in `src/agentprov/cli/derive.py`.
Tests: `test_raw_objects_are_copied_by_default_and_linked_with_link_raw`, `test_tampered_raw_bytes_are_refused_before_anything_is_derived`.

## Decision

1. **Default: copy.** Every raw object the new version needs is copied into `NEW.partial/raw/objects/` through
   `RawObjectStore.put_stream(..., expected_sha256=...)`, so each object is re-hashed while it is copied (after the
   inputs-first pass already re-hashed it). A re-derive copies every object the source lists (origins, members and
   index raw entries); a re-map lets the importer store the non-member objects it reads from the source store and
   re-runs `expand` for the members (AD-12).
2. **Opt-in: `--link-raw`.** Each object is hard-linked (`os.link`) from the source store; an object already present in
   the output is skipped. When the file systems differ (`OSError`), the run falls back to copying and says so in a
   notice. A re-map with `--link-raw` links the non-member objects before the importer runs (the importer then finds
   them stored and only records their origins).
3. **`--dry-run`** builds into a private temporary tree that is removed afterwards, so it links when it can (falling
   back to a copy): no source byte or name changes either way.
4. `CorpusLayout.iter_tree` admits hard links and `testing.fs_guard` ignores `ctime` and the link count, so a linked
   source still verifies and still passes the "source unchanged" guard; MN N.2.4(6) ("hard-linked on the same file
   system, else copied") is superseded for the default by this decision.

## Why

A new corpus version is released, moved and deposited independently of its source; a hard link ties the two trees to
one file system and one inode, so a later accidental write through either path (the stores are read-only, but `chmod`
is not prevented) would change both. Copying is the safe default; linking saves the space and time of large stores
(the 2024-06 AgentDojo corpus) when the user chooses it.

## Rejected alternatives

- **Link by default, copy across file systems** (N.2.4(6) as written): couples the two versions silently.
- **Reference the source store** (no objects in `NEW`): `NEW` would not be a self-contained corpus and could not be
  sealed or deposited on its own.
- **Copy without re-hashing**: the inputs-first rule (baseline R5) applies to the copy too.
