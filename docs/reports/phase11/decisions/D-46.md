# D-46: `purge` lives in `corpus/purge.py` and `cli/purge.py`, not `raw/purge.py` (phase 11, U7)

Status: implemented on branch `phase-11-u7`, for consolidation into DECISIONS.md by the orchestrator.
Code: `src/agentprov/corpus/purge.py`, `src/agentprov/cli/purge.py`. Tests: `tests/unit/corpus/test_purge.py`,
`tests/cli/test_purge_cmd.py` (support: `tests/unit/corpus/purge_support.py`).

## Decision

1. **Module placement.** MN M.1.2 and G.9.6 name `agentprov.raw.purge`. During phase 11, `raw/` belongs to phase 12 (AGENTS.md
   section 0, ownership rules), so the engine is `agentprov.corpus.purge` (L5, which already reads `raw/` and owns the
   tombstone path, `CorpusLayout.tombstones`). It uses the public read API of `raw` (`RawObjectStore.has`/`path_for`,
   `decode_members`) plus filesystem operations; nothing in `raw/` changed. If phase 12 later wants the module under `raw/`,
   moving it is a rename.
2. **What `purge` does** (N.2.15; G.9.6; HL H.1.2, H.6.3).
   - Target: a **working** corpus (`--corpus DIR`, acting on `DIR.partial`) or the fetch cache (`--cache`, with `--cache-dir`
     as for `fetch`; an addition to the synopsis).
   - Tombstone: one JCS row `{"date", "reason", "sha256"}` in `raw/tombstones.jsonl` (or `<cache>/tombstones.jsonl`), sorted
     by digest, written atomically; no value or fragment. A second purge of the same digest keeps the first row.
   - Register: every execution whose index row cites the object (or an object expanded from it, when it is an archive
     container) gets `release.withheld` (stage `package`, disposition `withheld`, severity `info`, fixed detail text).
   - Removal: the object file is unlinked (after the tombstone and register writes, so an interrupted purge is finished by
     running it again). Origin rows, member rows and the index are kept.
   - Everything runs under the working tree's writer lock; `--dry-run` takes none and writes nothing.
3. **Guards and exit codes.** A sealed corpus is refused (4, `SealedCorpusError`; a dry run gives the same code). A missing
   corpus, a malformed digest or an unknown object is 2. A non-interactive invocation without `--yes` is 4; on a terminal the
   command asks for the first 8 digits of the digest; a wrong answer is 4. `--yes` is the explicit confirm flag.
4. **Containers.** Purging an archive container withholds the executions of its member objects too and lists the member
   objects that stay stored (they may hold the value); purging a member lists the stored containers whose bytes still
   contain it. The command never removes more than the one object it was asked to.
5. **Cache scope.** `--cache` removes downloaded files (Zenodo, Hugging Face, URL pins) by sha256. Git objects inside the
   bare repositories are not searched; the message says so when nothing matches (exit 2).
6. **Not rewritten.** `corpus.json` counts and the index rows' `issues` are not rewritten by a purge; they are refreshed when
   the corpus is derived or sealed (U2/U3), and the command prints a notice. A later `import` into the same working corpus
   would store the leaked file again; blocking tombstoned digests at ingest is raw-layer work (phase 12).

## Why

The ownership rule forbids editing `raw/`; the spec's own contract (a tombstone beside the origin records, `release.withheld`
for the citing executions, no sealed-corpus changes, confirmation) fits the corpus layer, which owns the register and the file
layout. Writing the tombstone first and unlinking last makes the operation resumable without a journal. The fixed register
detail text keeps `register.jsonl` byte-identical when a purge is repeated or two purges hit one execution.

## Rejected alternatives

- **Edit `raw/` to add `raw/purge.py`.** Violates the ownership rule.
- **Wait for phase 12.** Phase 11 must ship all fifteen commands; `purge` is one.
- **Rewrite `executions.jsonl` and `corpus.json` in the purge.** They belong to derive/seal, which recompute counts and
  statuses from scratch (D-33); a second writer of those files invites drift.
- **Withhold only executions that cite the exact digest.** Members of a purged container derive from it; leaving them
  unflagged would let packaging release them.
- **Delete member objects or containers automatically.** The user asked for one object; automatic cascades are the kind of
  irreversible surprise the confirmation prompt exists to prevent. They are listed instead.
- **Search git objects in the cache.** Needs `git` subprocess work and rewriting packfiles; out of scope. Deleting a bare
  repository is a plain filesystem action the message points to.

## Downstream effects

No AER, SEM or PROV bytes change. A purged working corpus cannot be sealed as is: `verify`/seal will see the tombstone and the
missing object (U3/U4: `tombstoned`, never silently missing), and packaging withholds the executions with `release.withheld`.
The spec text of M.1.2/G.9.6/N.2.15 should note the module path `corpus/purge.py` and the `--yes` and `--cache-dir` options.
