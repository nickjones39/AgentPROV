# D-49: gate D at full scope validates stored AERs, read-only, in a plain process pool (phase 11, U10)

Status: implemented on branch `phase-11-u10`, for consolidation into DECISIONS.md by the orchestrator.
Code: `src/agentprov/migration/gate_d.py` (orchestration, report), `src/agentprov/migration/gate_d_worker.py` (one execution),
`gates.gate_d_validate`, `src/agentprov/cli/migrate.py` (`gate-d`). Tests: `tests/migration/test_gate_d.py`,
`tests/full_corpus/test_validation_all.py` (K.7.4 item 4, marker `full_corpus`).

## Decision

1. **Command.** `agentprov migrate gate-d [--scope golden|full] [--release] [--workers N] [--corpus DIR ...] [--limit N]
   [--accept-gap TREE ...] [--report PATH]` (also `migrate gate D`). `golden` runs the 19 v1 and 9 native golden AERs of
   `tests/golden/test_gate_d.py`, derives twice, requires identical bytes and the committed pins `gate_d_digests.json`.
   `full` needs `--corpus DIR`, once per tree.
2. **Inputs are stored AERs.** J.3.5 says "every AER produced by the migration". Gate D full reads them through `CorpusReader`
   (strict, chain-checked, no link followed) and never writes into a corpus: no scratch store, SEM and PROV stay in the worker's
   memory, and a `--report` path inside a corpus (or its `.partial`) is refused with exit 4. A test proves it with `fs_guard`.
   Corpora are classified into the J.3.5 trees from their index rows: `release` (`adprov.transcript_v1`, snapshot `release`),
   `converted` (same adapter, snapshot `converted`), `native` (`agentdojo.tracelogger`, source `agentdojo`, snapshot `2024-06`);
   anything else is validated but has no table. A corpus holding two trees, or two corpora of one tree, is a usage error.
3. **Per execution** (worker): tier 2 (AER validator, release mode, locators against the corpus raw store, profile digest
   against the package profile), tier 3 (SEM validator, release mode) and tier 4 (`validate_prov`, with the gate-D `migration`
   checks for the v1 trees), where any failed **or skipped** check fails the execution (MP-3), plus the dedicated J.3.5 checks over
   the derived document: every `used`/`wasGeneratedBy`/`wasAssociatedWith`/`wasInformedBy` cites a catalogue rule; `wasInformedBy`
   is `aprov.comm@1` with `apv:premise` in core or inference, and `PV-NE-7` (the Inference-6 closure) must pass; a ToolExecution
   uses only its request (or the captured initial state); no activity is used; `mentionOf` joins entities only; each request is
   a `hadMember` of its assistant message typed `prov:Collection`; for the v1 trees `aprov.use_context@1` is only in
   `inf.adprov-context_is_prefix-v1` and INFERRED; no relation time, no `"0"`/`""` time literal, every time attribute restates a typed
   AER `t` value; 0 `activity`/`artefact` records and 0 G-ACT/G-USE/G-GEN/G-ASSOC statements. The per-execution cross-counts
   (ToolExecution, requests, `NotDispatched` = listed `unexecuted_tool_call`, invocations generating an assistant message,
   user/system messages, `gen_result` on ToolExecutions) compare the PROV with the AER.
4. **Parent, per tree** (full scope, complete tree only): the aggregates are compared with the J.3.5 table (release and
   converted columns; the native import's matched executions take the converted column; the 7 Mixtral logs and the 207
   `outcome_only` records are counted apart and reported). Completeness is 17,664 / 18,027 / 18,241 executions. The report records
   per-execution wall time and statement counts (mean, p50, p95, max, the ten slowest, per-stage totals), a per-check status
   tally, and digest listings (AER, SEM, PROV per tree) in `outputs`, plus `<report stem>.md` and `<report stem>.executions.jsonl`
   beside the report. Re-derived digests are compared with the index row's and tallied (`rederived_vs_stored_digests`); a
   difference is information, not a failure (a regeneration batch that is not applied yet would show here).
5. **Scopes and the order of AD-07.** Full scope without `--limit` requires passing full-scope G0, A and B reports for this commit
   and lock (as gates A, B, E do) and its own passing report unblocks a full-scope gate E (`GATE_ORDER` already lists D).
   `--limit N` takes N evenly spaced executions per corpus and reports scope `sample`, role `diagnostic`; it skips the predecessor
   chain, the completeness checks and the table, and never satisfies `require_predecessors`.
6. **Gaps are explicit.** A tree without a corpus fails `inputs.<tree>.present` unless the caller passes `--accept-gap TREE`; the
   report then carries the gap in `details.gaps` and `notes`. No input is invented.

## Why a plain process pool, not the T1 job kind `prov`

The `prov` job already derives and validates, but (a) it cannot carry `migration=True` and returns no derivation report, so the
J.3.5 counts and never-emit checks would have to re-parse every 7,000-statement PROV document in the single-threaded parent;
(b) adding a job kind means editing `io/workers.py`, which phase 12 owns; (c) it needs the AER staged into a scratch store (a
write per execution). Gate D reads AERs that were validated and sealed when they were imported and `CorpusReader` re-verifies the
seal and the execution digest before use; nothing untrusted is parsed. The report states `isolation.mode: process-pool, grade:
null`. `--in-process` (debugging; refused with `--release`) runs the same function in the parent. Results are identical in
process and across worker counts (test).

## Rejected alternatives

- **Re-map the converted tree's transcripts inside gate D to obtain its AERs.** No stored v1 AERs of the converted tree exist
  (see below). Doing the mapping in gate D would make it a producer step, not a validation of existing AERs, and would have to
  run the T1 map pool with the baseline repository present. A later unit can add it as an input provider.
- **Treat the missing converted tree as `skipped`.** A skipped check is a failure (MP-3); a silent pass would hide the gap.
- **Fail the gate forever until the converted AERs exist.** Then gate E full could never run; `--accept-gap` makes the decision
  the reviewer's and visible in the report.
- **Use the converted column for every `native` execution.** The 7 Mixtral logs and the 207 empty logs are not in the converted
  tree (R-28); they are counted apart, as J.3.5 says.
- **Write the default report into `migration/reports` silently when `--report` is absent.** It is the documented default for the
  other gates (and where `require_predecessors` looks), so it stays; but `--report PATH` is the recommended form and nothing is
  ever written below `docs/reports/migration/` unless asked.

## Findings

- **No stored AERs of the converted tree exist.** The registry lists `adprov-v1/converted-legacy` as a compat oracle with
  `import_status=None` ("not released as a corpus"); `~/.agentprov/corpora` holds `adprov-v1-release*` (17,664, snapshot
  `release`) and `agentdojo-upstream-2024-06*` (18,241), nothing for 18,027 converted. Gates A and B map the converted
  transcripts into a temporary directory and delete the AERs. J.3.5's third column therefore has no input; the native corpus's 18,027
  matched executions are checked against that column. Closing the gap needs either an import of the converted tree as a corpus
  (a new capability) or an input provider in gate D that maps it (rejected above for now).
- **The AER side of the J.3.5 table reconciles exactly on the stored AERs** (read-only count over `adprov-v1-release-p10` and the
  native corpus, 2026-10-11): release 64,781 tool executions, 64,829 requests, 48 unexecuted, 64,897 assistant messages with a
  generator, 17,664/17,664 user/system messages, 1,417 executions without a tool execution, 0 activity and 0 artefact records;
  native matched (18,027): 68,620, 68,773, 153, 73,551, 21,658/18,027, 762, 0/0. The PROV side equals the AER side per execution,
  which the gate checks.
- Re-derived SEM and PROV digests equal the index digests on all 200 sampled executions.

## Downstream effects

None on AER, SEM or PROV bytes, golden digests, corpus manifests or manuscript numbers; new reports only. A full-scope gate D
report unblocks the CLI route of gate E (J.3.0).

## Running it (not done in this unit)

```
uv run agentprov migrate gate-d --scope full --release --workers 10 \
    --corpus ~/.agentprov/corpora/adprov-v1-release-p10 \
    --corpus ~/.agentprov/corpora/agentdojo-upstream-2024-06-p10 \
    --accept-gap converted --report ~/.agentprov/reports/gate-d-full.json
```

The full-scope run first needs passing full-scope G0, A and B reports for the commit (`--reports-dir`), or run
`AGENTPROV_GATE_D_CORPORA=<release>:<native> AGENTPROV_GATE_D_ACCEPT_GAPS=converted uv run pytest -m full_corpus
tests/full_corpus/test_validation_all.py`, which has no predecessor check. Measured on a 200-execution slice (100 per corpus, four
workers, shared machine): 57 s wall, mean 0.96 s per execution (tier 4 is about 90%); the long tail is real (R08, 7,199 statements:
22 s). For 35,905 executions that is about 9.6 CPU-hours: roughly one hour with ten workers, up to one and a half with the tail.
