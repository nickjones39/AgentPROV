# D-34: v0.1 index facets, generic cell, logical key, evidence classes, oracles (phase 11, U1)

Status: implemented on branch `phase-11` (U1), for consolidation into DECISIONS.md by the orchestrator.
Code: `src/agentprov/corpus/facets.py`, `src/agentprov/corpus/index.py` (`FacetMembers`, `logical_key`,
`check_corpus_json`). Tests: `tests/unit/corpus/test_facets.py`, `tests/unit/corpus/test_index_full.py`.

## Decision

1. **Scope.** The v0.1 index facets are the H.3.3 core facets only: `task`, `framework`, `model.requested`,
   `model.served`, the eight `n.*` counts, `generic_types` and `outcome`. Adapter facets (`x.<ns>.<name>`, e.g.
   `x.agentdojo.pipeline_dir`) and `--pipeline` are deferred. The index row validator already accepts namespaced
   `x.<ns>.<name>` members, so adding them later needs no format change.
2. **Pure function, in the corpus layer.** Facets, cell, logical key, `ev`, `oracles` and `completeness` are computed by
   `agentprov.corpus.facets` from the stored AER and SEM documents only (H.3.3(3)). Nothing comes from an adapter
   (`corpus/` is L5, below `adapters/`; invariant 1). The B2 completeness rule is re-implemented there
   (`index_completeness`, `completeness_of`), and a test pins it equal to
   `agentprov.adapters.runner.importer.index_completeness` over the full input cross-product, and pins the
   degenerate/loss code sets equal to the importer's.
3. **Facet values.**
   - `task`: the AER header `task`, verbatim (`null` if absent).
   - `framework`: the H.2.4 `fw` id of the single `benchmark` actor: `core = {distribution: code.dist, source: the
     recorded code.repo/commit/wheel_sha256 or null, source_tree_sha256: null (aer/0.1 records no tree digest),
     suite_set: actor.version}`. `null` when there is no benchmark actor, more than one, or when distribution, source
     and suite set are all unknown (an id over nothing would merge unrelated frameworks). A value declared in the
     actor's `unk` counts as unknown. `framework_identity()` returns the H.2.4 fields (without `executions`,
     `tool_definitions_sha256` and `system_prompt_sha256`, which belong to the manifest builder, U3).
   - `model.requested`: the sorted unique `model.requested` of the `llm_agent` actors (a judge's model is not the
     agent's). `model.served`: those actors' `model.served` plus `served_model` of model calls with `role: agent`
     (C.3.16 `model_served`); auxiliary calls are excluded.
   - `n.*`: record counts by kind. `generic_types`: sorted unique `type` of `activity` and `artefact` records.
   - `outcome`: one element per `judgement`, in AER order: `name`, `value`, `origin` from the judgement and `claim`,
     `holds`, `score`, `scale` from the SEM `outcome` annotation that targets it (R-18); `null` where absent. Several
     SEM profiles that annotate one judgement must agree (else `FacetError`); every SEM document must annotate this AER
     (`aer_digest` equal to the AER execution digest).
4. **Evidence classes (`ev`).** For each facet and each cell member, the **weakest** effective class
   (`aer.evidence.weakest`, C.6) of the AER/SEM fields it is computed from: a facet is only as reliable as its weakest
   input. A count's class is the weakest existence class (`ev`) of the counted records. A facet that rests on no field
   (empty array, zero count, absent task or framework), an unknown cell member and `repeat` of an import have no `ev`
   entry. Each `outcome` element carries its own `ev` map (member -> class, for its non-null members), in the style of
   H.2.4's `ev`, so an observed checker value (`O`) and an inferred polarity (`I`) stay distinguishable even though the
   row-level `ev["outcome"]` is their weakest. (H.3.4's example shows `"outcome": "O"` with SEM present; it is marked
   illustrative, and the weakest-input rule gives `D` or `I` whenever the polarity is derived or inferred.)
5. **Generic cell (H.7.4).** Member names follow the AER (as the `task` facet does): every recorded `task` member
   (`benchmark`, `suite`, `environment`, `task_id`, `attack_id`, `attack_target_id`, `defense_id`), `suite_set` (the
   benchmark actor's `version`, where C.3.1 puts the suite-set label), `model` (the agents' requested model; a sorted
   array if agents request different models), `attack_params_sha256` (`"sha256:" + sha256(JCS([{id, params}]))` over
   the header's `attack_parameter` instrumentation items, sorted by id; CAP-8), `repeat` (`null` for imports; the run
   ledger's repeat index for live executions, passed by the caller because the capture log does not hold it). The
   AgentDojo-family names of H.7.4(1) (`user_task`, `injection_task`, `attack`, `pipeline`) map onto these; `pipeline`
   is adapter data and arrives with the adapter facets.
6. **Unknown members and a null logical key.** A member the AER declares unknown (its pointer is covered by an `unk`
   key) is written `{"$unk": "<C.7.1 reason>"}`; a required member (`benchmark`, `task_id`, `model`) that is absent is
   `{"$unk": "not_recorded"}`; several benchmark actors give `suite_set: {"$unk": "ambiguous"}`; an `attack_parameter`
   item without `params` gives `attack_params_sha256: {"$unk": "not_recorded"}`. An absent optional member is not a
   coordinate (omitted). `logical_key` is `null` iff a member is unknown (or the cell is empty); otherwise it is
   `"lk_" + b32(sha256("aer-lk/1\n" + JCS(cell)))[:26]`, and the row validator recomputes it.
7. **Oracles.** `oracles` has one `{"gate_report": "sha256:…" | null, "status": "apv:RegressionOracle"}` entry per
   regression-oracle spec with output in `paths.prov` (only `adprov-v2.3-compat`; R-55), `{}` otherwise; the row
   validator enforces the correspondence with `paths.prov`.
8. **No floats in rows (H.1.4(3)).** A non-integral number copied from AER/SEM (a judgement value such as an Inspect
   score, an outcome `score`) is written `{"$dec": "<its JCS spelling>"}`: exact, deterministic, and float-free. The
   row decoder rejects any float or out-of-range integer.
9. **Facet schema.** `CORE_FACET_SCHEMA` gives the `FacetDecl` of each core facet: `from` is the JSON Pointer `/task`
   for the verbatim copy and a `corpus.facet_*@1` rule id for each computed facet (`corpus.facet_framework@1`,
   `corpus.facet_model_requested@1`, `corpus.facet_model_served@1`, `corpus.facet_counts@1`,
   `corpus.facet_generic_types@1`, `corpus.facet_outcome@1`; to be declared in `corpus/rules/corpus.rules.toml` by
   U3). `may_be_inferred` is true for every core facet (any input can be class `I`). `outcome` is declared with the
   type `object[]`, which H.3.3(1)'s type list lacks (it is an array of objects).
10. **Row kinds.** A row is either a working row (the importer's, unchanged) or a full row with all five members
    (`logical_key`, `cell`, `facets`, `ev`, `oracles`) and every stage recorded (`sem`, `prov`, `validation`
    present). Mixtures are rejected. The importer keeps writing working rows; full rows come only from phase-11 code
    paths (index rebuild in `derive`/`recompute`, sealing).

## Why

- H.3.3(3) requires facets to be re-derivable from AER and SEM, and invariant 1 forbids adapters from defining them;
  computing them in the corpus layer from the stored documents satisfies both and makes `verify --level chain`
  possible.
- The weakest-input rule is the conservative reading of C.6.5 ("nothing can raise a class") and of H.7.4(2) (a key is
  as reliable as its weakest member); it never over-states an epistemic status, which is the baseline defect H.3.3(4)
  addresses.
- Using `unk` to decide "unknown" uses the AER's own distinction between a known `null` and an unrecorded value,
  rather than guessing.
- `$dec` keeps scores exact without violating the no-float rule; dropping or rounding them would lose data.

## Rejected alternatives

- **Adapter-supplied facets and cells now** (each family declaring its `cell` and `x.*` facets through the registry).
  Deferred: it needs a declaration mechanism in the shared registry and per-family review; the generic cell already
  separates the cases H.7.6 names where the AER records the coordinates (e.g. Mandate vs AgentDojo by `suite_set`).
- **Strongest or majority class for `ev`.** Rejected: over-states facets built from mixed inputs.
- **Treating an unrecorded `instrumentation` as unknown attack parameters.** Rejected for v0.1: imported logs that do not
  record instrumentation (the Mandate and AgentHarm imports checked here carry `unk {"/instrumentation":
  "not_recorded"}`) could then never have a logical key; the member is omitted instead (limitation below).
- **Writing floats as strings, or rounding to integers.** Rejected: a bare string is indistinguishable from a string
  value; rounding loses data.
- **Including judge or auxiliary models in `model.*`.** Rejected: the facet describes the agent under test.
- **Failing a row when the logical key cannot be computed.** Rejected: H.7.4(3) says `null`.

## Consequences and limitations (measured read-only on samples of the p10 working corpora, 2026-10-11)

- `logical_key` is `null` for every sampled row of `agentdojo-upstream-2024-06-p10` (the benchmark actor's `version`
  is `unk not_recorded`, so `suite_set` is unknown), for about two thirds of `agentdojo-upstream-head-p10` (same
  reason), for a few `agentdyn-a-p10` rows (same reason) and for every `adprov-v1-release-p10` row (the declared
  `adprov.model_display_name@1` attack parameter is recorded `none`). ROPE, Mandate, the survey AgentDojo runs and
  AgentHarm get keys for every sampled row. An adapter-declared cell (deferred) can supply the inferred suite set
  (class `I`) where the family knows it; the generic cell does not infer.
- An execution whose header leaves `instrumentation` unrecorded cannot show an attack parameter in its cell; two runs
  that differed only in an unrecorded attack parameter would share a key. This is disclosed, not hidden.
- `completeness_of` on the p10 corpora differs from the stored index for the rows H.3.2(2) names (written before the
  B2 rule; e.g. 2024-06 and head samples): expected, and corrected by the next regeneration (regen batch B2).
- No AER, SEM or PROV byte changes; the importer's index rows are unchanged.
