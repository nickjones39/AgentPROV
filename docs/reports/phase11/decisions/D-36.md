# D-36: the claims/lint library is a new file `adapters/registry/claims.py` (phase 11, U3)

Status: implemented on branch `phase-11-u3` (U3); the new file in the shared registry package was approved by the user
on 2026-10-11. For consolidation into DECISIONS.md by the orchestrator.
Code: `src/agentprov/adapters/registry/claims.py` (new; no other `adapters/` file is edited), used by
`src/agentprov/cli/checks.py` (`validate --card`) and `src/agentprov/cli/package.py`, injected into
`src/agentprov/corpus/datasheet.py`. Tests: `tests/adapters/registry/test_claims.py`,
`tests/unit/corpus/test_datasheet.py`, `tests/cli/test_package_cmd.py`.

## Decision

1. The one claims/lint library of I.5.6, H.9(4) and N.2.5(7) is `agentprov.adapters.registry.claims`, a new module in the
   shared registry package (L6). It holds: the closed claim-tag vocabulary and the tagged I.4 must-not-claim items
   (`MUST_NOT_CLAIM`, `forbidden_tags`, `check_claim`, with the `asr` derivation rule, the coverage-phrase rule and the
   agent-execution scope rule); the registry-generated coverage phrase (`coverage_phrase`; `None` before Q.11a, which is
   read from the registry as the gated `supported` status of the `inspect.eval` part); the registered datasheet claims
   (`CLAIMS`, `evaluate_claims`); the text lint (`lint_text`: bare agnosticism term outside a design-goal block and
   counts or source names inside one; unqualified "reproducible"; the scope words "lossless" and "faithful" outside a
   line that carries a `{{claim:…}}`; a hand-written coverage phrase; a "Live Capture" title); the card lint
   (`lint_card`: front matter `mode`, no digit outside a placeholder except the allow-list, registered claims); the
   datasheet lint (`lint_datasheet`: the G.8.5 "Untrusted content" section); and `CHECKER`, the object injected into the
   datasheet renderer.
2. **Layering.** `corpus/` (L5) never imports it: `corpus.datasheet.render` receives `CHECKER` from its caller
   (`cli.package`; M.5.2(1)). `validate --card` calls `lint_card` directly from the CLI (L8).
3. **Card allow-list (H.9(3)), as built.** A token with a digit is allowed outside placeholders when it is a version id
   (`aer/0.1`), a SemVer or `v`-version, an ISO date or a year-month snapshot id (`2024-06`), a DOI, an arXiv id, a commit
   SHA (7 to 40 hex digits with at least one letter), a section or item number (`H.1.5(4)`, `§8.3`, `D-27`, `NC-ALL-13`,
   `N2`), a rule or profile reference (`ns.rule@1`), the names `W3C`, `sha1`, `sha256`, or an identifier inside a code
   span that contains a letter (model names such as `gpt-4o-2024-05-13` go in code spans). Every other number is a
   placeholder: `{{v:<pointer>}}` (a manifest value), `{{t:<table>}}`, `{{claim:<id>}}`, or, in a decided statement only,
   `{{f:<name>}}` (a figure with its cited source).

## Why

AD-10 row 9 merges the datasheet claims registry and the card linter into one library that also serves the README, the
paper and `agentprov stats`, so that every surface applies the same rules (Q.11b). The registry package is its home in
I.5.1; a new file keeps the existing registry modules untouched (ownership rule: append-only in `adapters/registry/`).

## Rejected

- A claims module under `corpus/` (it would need the registry, an L5 -> L6 import) or a second card linter.
- Detecting must-not-claim tags in free prose by keyword (unreliable); tags are declared on claims and macros, and the
  text lint covers only the phrase rules I.5.6 names.
