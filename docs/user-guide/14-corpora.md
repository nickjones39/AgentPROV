# 14. Corpora and where they come from

This chapter lists every corpus AgentPROV declares, with each part's format, pinned origin, licence, execution count,
status and caveats. The corpora themselves are not in the repository: they live under `AGENTPROV_HOME`, and
`agentprov stats --corpus <corpus>` counts a built one ([chapter 6](06-stats-and-render.md)).

## Where the data comes from

Every source was found by a systematic search with eligibility criteria fixed before screening
([`docs/reports/systematic-search/`](https://github.com/nickjones39/AgentPROV/tree/main/docs/reports/systematic-search)).
It covered code platforms (GitHub, GitLab, Codeberg, Hugging Face), the literature, and research-data repositories
(Zenodo, Hugging Face, DataCite, Figshare and others).

- **Licences.** Data with no licence, or with a licence that forbids redistribution, is excluded. The location of such
  data may be recorded with licence policy `reference`, but nothing from it is released. *(restricted)* marks a licence
  with a use clause, such as AgentHarm's "AI safety only" clause. Each copyleft source (AGPL or GPL) has its own
  corpus, and non-commercial data never mixes with permissive data.
- **Outcomes.** Data is never excluded for its outcome: a source, arm or part in which no attack succeeded is included
  like any other.
- **Pins.** Each part is pinned to exact bytes, and an import refuses anything else. A **git** pin names the
  repository, the commit, and usually the tree with its hash and expected file count. A **Zenodo** pin names the
  record (DOI), its version, and each file with its size and checksum. A **Hugging Face** pin names the dataset, the
  revision, and each file (or each part of a split archive) with its size and LFS sha256. A **URL** pin names the
  address and the file with its size and sha256.

The bytes go into the raw store unchanged, and each corpus carries the sha256 chain raw → AER → SEM → PROV
(`agentprov verify --level chain`).

## How to read the listing

- **Status** is the registry's gated status ([chapter 3](03-sources-and-import.md#the-source-registry)).
- **Corpus** is the sealed corpus id for a sealed part, otherwise the registry's corpus id. **Status** names a sealed
  corpus's version by its tag, `corpus/<corpus_id>/v<version>`, an annotated tag on the commit that sealed it.
- **Executions** is the count recorded in the repository, linked to the committed report it comes from, with the basis
  of the count: **sealed**, the executions a sealed corpus releases (after withholding), from its seal report; a **full
  import** through `agentprov import`; a **census** of the pinned bytes; a **trial import** into a scratch corpus;
  records **mapped in memory** without an import; or the specification (**spec**). A corpus of several parts gives its
  released count on one part, and the others say so.
- **Caveats** come from the source profiles and the registry: what is withheld, redacted or not yet read.
- The second table gives each source's project page and the paper that describes it, linked by its arXiv id or DOI
  where the profile records one. A paper marked *found by web search* was matched to the source later, and
  [`tools/readme_corpora.toml`](https://github.com/nickjones39/AgentPROV/blob/main/tools/readme_corpora.toml) records
  how.

The listing is generated by `tools/gen_readme_corpora.py` from the registry, the source profiles and the committed
reports; a test checks that it is current. It never reads a corpus. A branch that adds a source, part, pin or count
adds the part to `tools/readme_corpora.toml` and runs `uv run python tools/gen_readme_corpora.py --write`; a conflict
in the block is resolved by running it again, never by hand.

  *derived* (class D): the rule that verifies AgentDojo's checker lists only the commit of the June-2024 snapshot, so
  logs from later AgentDojo commits cite its unverified twin (decision D-359). The checker's code is the same at those
  commits, so re-importing with a widened rule (Option B) was considered and set aside: the user's final choice
  (2026-10-28) is to keep the corpora as built and disclose the I class in their datasheets. Utility outcomes stay D.

  built, so recompute or re-derive each one at the commit that built it, not at `main`
