# AgentPROV v0.1.0

AgentPROV is an execution-provenance framework for LLM-agent security research. It reads agent runs, either released
benchmark logs or runs it captures live, and turns them into a canonical execution record (AER), semantic annotations
(SEM) and W3C PROV bundles (core, inference and assessment). It validates each stage and packages the result as
hash-chained corpora whose provenance can be recomputed without running a model again. Every derived statement names
its evidence class, the rule that produced it and the record field that justifies it.

- Website: https://w3id.org/agentprov/
- User guide: https://w3id.org/agentprov/docs/
- Software on Zenodo: https://doi.org/10.5281/zenodo.23786079
- Corpora on Zenodo (one collection): https://doi.org/<UMBRELLA_DOI>

## What is in v0.1.0

- **The `agentprov` command-line tool and library** (Python 3.14): import, derive, validate, verify, recompute, render,
  statistics, seal and package. Pipeline formats: `aer/0.2`, `sem/0.1`, `capture/0.1`, `agentprov-prov/0.1`,
  namespace `apv 0.2.0`, corpus layout `agentprov-corpus/0.2`.
- **Import adapters** in an in-repository registry, mapped onto one versioned rule catalogue. Coverage:
  adapter-based core; demonstrated on 48 sources in 13 formats (single-agent, tool-calling traces).
- **Live capture** (`agentprov-capture`, `capture/0.1`) with the AgentDojo, AutoDojo and AgentDyn backends, and an
  Inspect harness that runs AgentHarm and imports Inspect's own log of the run. Live capture works and is tested in v0.1. No live results are claimed, and live corpora cannot be sealed until v0.2.
- **The desktop app** for macOS, Windows and Linux: a read-only corpus viewer (graph, PROV-JSON, AER, SEM, register,
  validation and raw views), a job runner with the exact command shown before it runs, live-run setup with its cost
  estimate, and the packaging steps for sealing and a deposit draft.
- **`agentprov-zenodo`**, which creates unpublished Zenodo drafts only. Publishing is always done by hand on Zenodo.
- **The specification** (`docs/architecture/`) and **the user guide** (`docs/user-guide/`, published on the website).

Each bundle comes with its `bundle-report.json` (its checks, interpreter, glibc floor, signature and sha256). The
release also carries the sdists and wheels of `agentprov`, `agentprov-capture` and `agentprov-zenodo`. Live runs need
macOS or Linux; they are not available on Windows in v0.1.

### First launch

- **macOS:** the app is signed ad hoc, not notarised, so macOS refuses the first launch. Open System Settings ›
  Privacy & Security and click **Open Anyway**.
- **Windows:** the bundles are not code-signed. When SmartScreen warns you, choose **More info**, then **Run anyway**.
- **Linux:** unpack the archive and run `AgentPROV/AgentPROV`. The folder has a desktop-entry installer. It needs
  the X11 libraries listed in the user guide (chapter 8).

### Check what you downloaded

Every release file is listed in `SHA256SUMS` (sha256, two spaces, file name). Check the list's signature, then the
files:

```bash
ssh-keygen -Y verify -f allowed_signers -I <signer> -n file -s SHA256SUMS.sig < SHA256SUMS
```

```bash
shasum -a 256 -c SHA256SUMS --ignore-missing
```

`allowed_signers` holds the public key of the signing account (the same key is on the maintainer's GitHub profile).
The tag `v0.1.0` is signed with it too.

## Corpora

The corpora built with this release are on Zenodo as one collection (https://doi.org/<UMBRELLA_DOI>), one record per
licence class. Each corpus has a datasheet, its licence class and a root digest. `agentprov verify --level chain`
checks a downloaded corpus from its raw bytes to its PROV bundles. Run at the commit that built the corpus (its source
snapshot, below), `agentprov recompute --dry-run` recomputes the provenance and reports any difference.

## Source history and building commits

This repository starts a new history at v0.1.0. Its tree equals development commit `<R>` minus the files listed in

licence keeps them private). The listing digest of both trees is `<LISTING_SHA256>`. A second commit changes only

The corpora record the development commits that built them. Those commits are preserved as source snapshots in the
software record (https://doi.org/10.5281/zenodo.23786079), with a manifest (`BUILDING-COMMITS.json`) that checks each
snapshot's stage code digests against the corpora.

## Known limits of v0.1

- Live corpora cannot be sealed yet (planned for v0.2). The live capture path is tested, and no live results are
  claimed.
- PROV output grows with the square of the model calls in a run; see `docs/roadmap.md`.
- Model-provider terms for redistributing model outputs were not assessed; each datasheet says so.
- The restricted-use AgentHarm test fixtures stay in the development repository; the tests that need them skip in this
  one.
- The macOS app is not notarised and the Windows bundles are not code-signed (see First launch).
- MCPHunt (`mcphunt`): Recomputing this corpus needs agentprov with D-1001 or later: the sealed `corpus.json` does not
  record `mcphunt@3`'s raised ingest limit (`max_json_element_bytes` = 64 MiB), so earlier versions, including its
  building commit `f8b5d62b`, refuse with `corpus.derive.limits_mismatch`; D-1001 rebuilds the limit from the profile
  and accepts it only when it matches the recorded `limits_sha256`.
