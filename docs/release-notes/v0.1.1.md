# AgentPROV v0.1.1

AgentPROV is an execution-provenance framework for LLM-agent security research. It reads agent runs, either released
benchmark logs or runs it captures live, and turns them into a canonical execution record (AER), semantic annotations
(SEM) and W3C PROV bundles (core, inference and assessment). It validates each stage and packages the result as
hash-chained corpora whose provenance can be recomputed without running a model again. Every derived statement names
its evidence class, the rule that produced it and the record field that justifies it.

- Website: https://w3id.org/agentprov/
- User guide: https://w3id.org/agentprov/docs/
- Software on Zenodo: https://doi.org/10.5281/zenodo.23848609
- Corpora on Zenodo (one collection): https://doi.org/10.5281/zenodo.23814758

Each bundle is built from the tag `v0.1.1` on a GitHub-hosted runner of its own operating system and architecture, so
none is built under emulation. Each build runs the bundle checks and starts the app once; the clean-machine runs of
v0.1.0 were not repeated for v0.1.1. The release also carries the sdists and wheels of `agentprov`, `agentprov-capture`
and `agentprov-zenodo`, and each bundle's `bundle-report.json` is in the software record on Zenodo. Live runs need
macOS or Linux; they are not available on Windows in v0.1.

### The command line

The command-line program and library are on PyPI from v0.1.1: `pip install agentprov` (Python 3.14.8 or later), with
`agentprov-capture`, and `agentprov-zenodo` through the `zenodo` extra. Live runs need the repository checkout, because
the benchmark backends are separate projects that the package does not contain.

### First launch

- **macOS:** the app is signed ad hoc, not notarised, so macOS refuses the first launch. Open System Settings ›
  Privacy & Security and click **Open Anyway**.
- **Windows:** the bundles are not code-signed. When SmartScreen warns you, choose **More info**, then **Run anyway**.
- **Linux:** unpack the archive and run `AgentPROV/AgentPROV`. The folder has a desktop-entry installer. It needs
  the X11 libraries listed in the user guide (chapter 8).

### Check what you downloaded

Every release file is listed in `SHA256SUMS` (sha256, two spaces, file name). Check the list's signature, then the
files:

```bash
ssh-keygen -Y verify -f allowed_signers -I 58574515+nickjones39@users.noreply.github.com -n file -s SHA256SUMS.sig < SHA256SUMS
```

```bash
shasum -a 256 -c SHA256SUMS --ignore-missing
```

`allowed_signers` holds the public key of the signing account (the same key is on the maintainer's GitHub profile).
The tag `v0.1.1` is signed with it too.

## What is new in v0.1.1

- **Help in the desktop app.** Help › Docs shows the user guide inside the app. Help › Assistant is a chat that answers
  how-to questions with a model you choose in Settings › Assistant: a local server (oMLX, MLX, LM Studio, Ollama,
  Splash, Strata, llama.cpp, vLLM or any OpenAI-compatible one, with its loaded model found by *Refresh*) or an API
  provider whose key is in Settings › Keys. Each message runs the new `agentprov assist` command, which sends the
  passages of the guide, the command help and the code's module descriptions that match the question; the answer lists
  its sources. The app itself still opens no network connection and never holds a key. Both work in the downloadable
  app without a source checkout: Docs shows the guide bundled with the app, and the Assistant uses an `agentprov`
  installed with `pip` (set in Settings › General) when no checkout is set. Settings pages that need the command-line
  program say so when it is missing, instead of staying greyed out.
- **A macOS Intel bundle**, and every bundle built natively on GitHub-hosted runners.
- **The command-line program on PyPI** (`pip install agentprov`).
- **The Zenodo uploader** sends a file upload again when it fails in transit.
- **Tooltips in the desktop app.** Every control, column header and toolbar icon says what it does, shown while it
  applies.
- **Windows fixes.** In v0.1.0 every worker process stopped at start-up on Windows, so `import`, `derive` and
  `validate` failed there unless run with `--in-process`; they now work. Imports large enough to spill to disk work on
  Windows too, and so do purging, packaging with withholding and the withhold scan, which could not delete the
  read-only stored objects there. Scratch folders are
  removed after a run without making a source corpus's objects writable, and dates after the year 3000 render as on
  other systems.
- **Fixes from a code review of the parts earlier reviews had not covered** (30 findings): a defence endpoint off this
  computer now counts as a paid API run, with its consent text and cost caps; per-cell call bounds count a defence's
  own calls; stop requests sent just after a job starts are honoured; Settings › Keys asks before deleting a key; the
  public export and the release workflows check what they publish. Findings whose fix would change corpus results are
  recorded, not fixed.
- **The AgentDojo-PROV importer** refuses malformed transcripts (a turn without a role, a time out of range, a
  placeholder in a task identity) instead of failing later (fuzzing findings); valid transcripts convert exactly as
  before.
- **Security updates of locked dependencies:** certifi, setuptools, filelock, dnspython, pyasn1, nltk and pillow move
  to their fixed releases; every other locked version is unchanged.
- **Continuous integration** runs the full test suite on GitHub-hosted runners again (Linux x86_64 and arm64, macOS,
  Windows), each platform's tests split over several runners; tests that need what Windows lacks are skipped there
  with the reason.

The full list of changes is in the decision records D-1010 (the Help section), D-1011 (the builds, CI and the fixes),
D-1012 (PyPI), D-1020 (CI split over runners) and D-1030 (Help and Settings without a checkout) under `docs/architecture/decisions/`, and the review's findings, with what was fixed and what was
only recorded, are in `docs/reports/review-uncovered/findings.md`.

The formats are those of v0.1.0 (`aer/0.2`, `sem/0.1`, `capture/0.1`,
`agentprov-prov/0.1`, namespace `apv 0.2.0`, corpus layout `agentprov-corpus/0.2`), and the corpora sealed with v0.1.0
are unchanged.

## What is in v0.1

- **The `agentprov` command-line tool and library** (Python 3.14): import, derive, validate, verify, recompute, render,
  statistics, seal and package.
- **Import adapters** in an in-repository registry, mapped onto one versioned rule catalogue. Coverage:
  adapter-based core; demonstrated on 48 sources in 13 formats (single-agent, tool-calling traces).
- **Live capture** (`agentprov-capture`, `capture/0.1`) with the AgentDojo, AutoDojo and AgentDyn backends, and an
  Inspect harness that runs AgentHarm and imports Inspect's own log of the run. Live capture works and is tested in v0.1. No live results are claimed, and live corpora cannot be sealed until v0.2.
- **The desktop app** for macOS, Windows and Linux: a read-only corpus viewer, a job runner with the exact command
  shown before it runs, live-run setup with its cost estimate, the packaging steps, and now the Help section.
- **`agentprov-zenodo`**, which creates unpublished Zenodo drafts only. Publishing is always done by hand on Zenodo.

## Known limits of v0.1

- Live corpora cannot be sealed yet (planned for v0.2). The live capture path is tested, and no live results are
  claimed.
- PROV output grows with the square of the model calls in a run; see `docs/roadmap.md`.
- The macOS app is not notarised and the Windows bundles are not code-signed (see First launch).
- The Assistant's answers are model output: check them against the user guide.
- The job runner and the settings pages of the downloadable app need the command-line program: a source checkout or
  an `agentprov` installed with `pip`, set in Settings › General.
- On Windows, when the command-line program runs from a Python virtual environment, a worker's memory cap is not
  enforced (the environment's `python.exe` starts the interpreter as a child, and the watchdog measures the parent).
  Time and CPU limits still apply.
