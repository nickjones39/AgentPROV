# AgentPROV v0.2.1

AgentPROV is an execution-provenance framework for LLM-agent security research. It reads agent runs, either released
benchmark logs or runs it captures live, and turns them into a canonical execution record (AER), semantic annotations
(SEM) and W3C PROV bundles (core, inference and assessment). It validates each stage and packages the result as
hash-chained corpora whose provenance can be recomputed without running a model again. Every derived statement names
its evidence class, the rule that produced it and the record field that justifies it.

v0.2.1 is a patch release: desktop-app fixes and additions, Run Live's suggested caps and Inspect tasks, and the release
CI findings of v0.2.0. No corpus format, catalogue,
profile or vocabulary version changes, and no AER, SEM or PROV byte changes.

- Website: https://w3id.org/agentprov/
- User guide: https://w3id.org/agentprov/docs/
- Software on Zenodo: https://doi.org/10.5281/zenodo.23996923
- Corpora on Zenodo (one collection): https://doi.org/10.5281/zenodo.23814758

Each bundle is built from the tag `v0.2.1` on a GitHub-hosted runner of its own operating system and architecture, and

### First launch

- **macOS:** the app is signed ad hoc, not notarised, so macOS refuses the first launch. Open System Settings ›
  Privacy & Security and click **Open Anyway**.
- **Windows:** the bundles are not code-signed. When SmartScreen warns you, choose **More info**, then **Run anyway**.
- **Linux:** unpack the archive and run `AgentPROV/AgentPROV`. The folder has a desktop-entry installer. It needs
  the X11 libraries listed in the user guide (chapter 8).

### Check what you downloaded

Every release file is listed in `SHA256SUMS` (sha256, two spaces, file name). Check the list's signature, then the
files:

```bash
ssh-keygen -Y verify -f allowed_signers -I agentprov-release -n file -s SHA256SUMS.sig < SHA256SUMS
```

```bash
shasum -a 256 -c SHA256SUMS --ignore-missing
```

`allowed_signers` is `src/agentprov/update/data/allowed_signers` in the source archive: it holds the public key of the
release key `agentprov-release` (D-1065), which signs `SHA256SUMS` from this release on and which `agentprov update`
checks too. The tag `v0.2.1` is signed with the maintainer's own key, the one on their GitHub profile.

## What is new in v0.2.1

### Updates bring the whole software up to date (D-1130)

- **The app carries its own `agentprov`.** The downloaded app is also the command-line program, so it runs imports,
  derives, validation and every other job without a checkout or a separate install. In a terminal it is `AgentPROV
  --cli` (on macOS `/Applications/AgentPROV.app/Contents/MacOS/AgentPROV --cli info`). Updating the app updates it.
  Settings › General › **agentprov to run** chooses Automatic (a checkout, else an installed `agentprov`, else the
  app's own) or always the app's own copy. Live runs still need a checkout of the repository (its `backends/`
  projects); Run Live says so when the app's own copy is in use.
- **Download and Install… updates every part it can, after one confirmation.** Besides the app, it updates the
  `agentprov` program the app runs. A pip, uv tool or pipx install gets the release's own wheels (`agentprov`,
  `agentprov-capture`, and `agentprov-zenodo` when installed), checked like the app: the signature on `SHA256SUMS`
  first, then each sha256. Its own installer then installs exactly those files with `--no-deps --no-index`, so nothing
  is fetched from PyPI. A checkout is fast-forwarded (`git pull --ff-only` from the project's repository on `main`, then
  `uv sync --frozen --group docs`) only when it has no changes or untracked files and `main` has no commit `origin`
  lacks; nothing is ever discarded. The dialog names each part it replaces (its versions, how it was checked, what is
  kept to go back to) and each part it cannot update, with why and the command to run yourself.
- **In a terminal:** `agentprov update download --package --allow-network`, then `agentprov update install --package
  --confirm`; for a checkout, `agentprov update install --checkout --confirm --allow-network`. `agentprov update
  install` alone still changes nothing: it prints the upgrade command and says which of these applies.
- **What is not kept:** the app keeps its previous version beside it for `agentprov update rollback`. A package
  install's previous version is not kept; the output gives the command that reinstalls it. A checkout's old commit
  stays in git.
- **`agentprov` in a Terminal.** **Install Command Line Tool…** (on macOS in the AgentPROV menu, on Linux and Windows
  in Help) puts a small launcher named `agentprov` in `~/.local/bin` that runs the app's own copy. It needs no
  administrator rights and never replaces an `agentprov` installed with pip, uv tool or pipx. The app is named by its
  full path, so updating the app updates the command. **Uninstall Command Line Tool** removes it. In a terminal:
  `AgentPROV --cli launcher install`, `agentprov launcher status`, `agentprov launcher remove`.
- **Stale backend environments are rebuilt after an update.** `agentprov backends rebuild-stale` finds every backend
  environment the updated checkout no longer accepts, rebuilds each in turn as `backends build` does and checks it
  offline; a failure names its command and the next backend follows. It never rebuilds one a running live job uses,
  never removes an environment's defence assets (such an environment is named with the command that rebuilds it with
  them) and leaves earlier environments as they are. In the app, Runs › **Rebuild Stale Environments…**, and the
  update starts it once the program part of a checkout has updated (its confirmation says so first).
- **Checked before release.** An independent review of the update found, and this release fixes: the app's own
  `agentprov` now carries the core's source files and package metadata, so the corpora it writes record the same code
  digests and library versions as a pip install (the app build checks it; a damaged app refuses those commands rather
  than record false ones); a checkout update keeps your installed extras, refuses when a new commit would overwrite an
  ignored file or when the `agentprov` doing it is not the checkout's own; a package upgrade reads no `pip.conf` or
  `uv.toml`, upgrades a `pip install --user` install in place, and is refused while a job runs from any of its files;
  a missing release-keys file refuses the update instead of falling back to the checksum alone; on Windows a rollback's
  helper is always the running app; the Terminal command refuses an app opened from a temporary place; and the app
  reports every part's outcome, never installs after the program it runs was changed during the downloads, and never
  stops an install part of the way through.

### The desktop app

- **The update notice tells an out-of-date `agentprov` program apart from an out-of-date app** (D-1070). The app runs
  the `agentprov` of the checkout or package install named in Settings › General. When only that program is older than
  the newest release, the notice now says "The agentprov this app runs is out of date", names the versions, and offers
  **Update agentprov…**, which updates that program as above (D-1130) or shows its upgrade command, instead of
  downloading the app's bundle, which could not change that program. When the app itself is behind, Update Now works
  as before.
- **Run Live finds the backend when the app is opened from the Finder.** The app's short calls of `run`, `backends`
  and `migrate` now start in the configured checkout, as its jobs already did. Before, an app started from the Finder
  ran them from `/`, `run --catalogue` exited with `backend.repository_missing`, and the Suites and Attacks lists
  stayed empty.
- **Run Live never shows blank Suites and Attacks rows.** On opening, it draws the catalogue of the last successful
  check in this app session at once, or "Loading the suites from the backend…" the first time. The check every two
  seconds redraws only when the answer differs and keeps what you ticked meanwhile.
- **Run Live starts Inspect tasks** (D-1120). With the `inspect-agentharm` backend, Run Live reads the backend's task
  catalogue and shows the task, its parameters (a menu or a bounded number for each), the samples of a split (the first
  N or a list of ids), the per-sample limits and the judge models, instead of the AgentDojo suites and attacks. It says
  before Start what the command line would refuse, and the command card, the estimate and Start use the same arguments.
- **Run Live suggests the caps from the quote** (D-1090). `agentprov estimate` now proposes `--max-calls` and
  `--max-cost-usd`: the quote's 90th-percentile figures plus a margin (Settings › Estimate › Run caps, 20 % unless set)
  and room for what a run reserves before a cell starts, since a cap at the quote alone often let no cell start. The
  text form prints "Suggested caps: …". In Run Live both caps follow the quote until you type one; "Use the quote's
  figure" goes back. `agentprov run` keeps any caps you give it. The suggested cost cap prices the quote's tokens as
  the run counts them (every input-side token, cached or not, at `--price-in`), so a cached-heavy quote does not give a
  cap the run then meets, and the room covers the preflight probe's retries.
- **Run Live's plan window says why it has no plan** yet: what the form still needs, that the estimate is being made,
  or why it failed, where it was blank or kept an earlier plan.
- **Tune… is turned off, with the reason in its tooltip,** when the model's weight size cannot be known (a scripted run,
  or an API model with no folder or weight size under Advanced), since a host preset sizes the concurrency from the
  weights. A local model of unknown size gets a plain explanation naming Settings › Local models.
- **Building cost figures from your corpora shows its progress:** `agentprov priors build` reports batches read of a
  total, and Run Live shows a progress bar with about how long is left. The priors it writes do not change.
- **The Viewer's graph zooms with the mouse wheel,** anchored under the pointer; a trackpad scroll still pans, and a
  pinch or ⌘/Ctrl with a trackpad scroll zooms.
- **Dropdowns and shortened cells show their whole text:** every menu's list is as wide as its widest item (on macOS
  "Observed only" in the Viewer's evidence filter was cut), and an item still wider gets its whole text as a tooltip.
- **Reviewed before release.** A code review of all of 0.2.1's work found, and this release fixes: Run Live's estimate
  for a keyed API run (it went out without the caps, so no quote came back and Start stayed blocked), its estimate
  from an app opened in the Finder, a reopened dialog stuck on "Catalogue: loading…", and a typed Inspect text
  parameter that looked like TOML; About › Updates losing the app's "Quit…" line when the program part followed; a
  checkout update missing a renamed file that would overwrite an ignored one; Uninstall Command Line Tool refused for an
  app in a temporary place; a restore command that zsh refused (unquoted extras) or that missed `--user`; and
  `backends rebuild-stale` calling a defence-asset block "a missing input".

### Release CI findings

The first two were found by the v0.2.0 release CI; a trial run of the full CI with both fixes in passed on every job,
the Windows shards included. The third was found by the v0.2.1 release CI.

- **The macOS memory watchdog counts compressed and swapped-out pages** (D-1080). On macOS, where the polled watchdog is
  the only memory cap, a job's sample is now the larger of its resident size and its physical footprint. Before, a job
  whose pages the system compressed or swapped out could run past its cap when the host was short of memory.
- **The tier-4 round-trip cache is used on Windows again** (D-1081). A worker and its parent now name the Python build
  the same way (`sysconfig.get_platform()`), a library file that cannot be read makes a process skip the cache instead
  of hashing a placeholder, and a job whose context differs from its parent's is reported on stderr part by part.
  Cache entries made by 0.2.0 are missed once. The cache only speeds validation up: outcomes, reports and digests of
  AER, SEM and PROV bytes do not change.
- **An AgentDojo-PROV transcript whose tool name is empty or a placeholder is imported in full** (regen-batch row
  190). The adprov mapper now keeps such a name (an empty `function`, `none`, `-`) as written and declares it
  ambiguous, as the AgentDojo and Inspect mappers already do; before, the whole transcript ended as an adapter defect.
  The CI's thorough fuzz run found it; it dates from before 0.2.0, and no sealed corpus holds such a name.

### Version changes

All five packages move to 0.2.1: `agentprov`, `agentprov-capture` (its `session.start` writer version too),
`agentprov-zenodo`, the desktop app `agentprov-gui` and the backend harness `agentprov-backend`. The format ids stay
`aer/0.2`, `sem/0.1`, `capture/0.1`, `agentprov-prov/0.1`, `apv 0.2.0` and `agentprov-corpus/0.2`, and no catalogue or
profile version moves. The `aer` code digest of every family and the `validation` code digest move (regen-batch row
189: `host.py` and `validate/cache.py` are in those stage scopes), and so does the adprov adapter's (row 190), so a
corpus imported or validated with 0.2.1 records those digests differently from one made with 0.2.0; the records of a
well-formed source are byte for byte the same.

### Known issues in sealed corpora

The five defects listed in the v0.2.0 release notes (AU-RA-4, AU-RA-5, AU-RB-2, AU-RC-3, AU-RC-4) are still in the
corpora sealed before 0.2.0. They were fixed in 0.2.0, no reported value depends on them, and the sealed versions stay
derivation-reproducible as built (F-8). See `docs/release-notes/v0.2.0.md` for the affected corpora and counts.

## What is in v0.2

- **The `agentprov` command-line tool and library** (Python 3.14): import, derive, validate, verify, recompute, render,
  statistics, estimate and priors, seal and package.
- **Import adapters** in an in-repository registry, mapped onto one versioned rule catalogue. Coverage:
  adapter-based core; demonstrated on 48 sources in 13 formats (single-agent, tool-calling traces).
- **Live capture** (`agentprov-capture`, `capture/0.1`) with the AgentDojo, AutoDojo and AgentDyn backends, and an
  Inspect harness that runs AgentHarm and imports Inspect's own log of the run. Live capture works and is tested in
  v0.2. No live results are claimed, and live corpora cannot be sealed yet.
- **The desktop app** for macOS, Windows and Linux: the corpus Viewer, the job runner with the exact command shown
  before it runs, Run Live with its cost quote and run controls, the packaging steps, and Help.
- **`agentprov-zenodo`**, which creates unpublished Zenodo drafts only. Publishing is always done by hand on Zenodo.

## Known limits

- Live corpora cannot be sealed yet. The live capture path is tested, and no live results are claimed.
- PROV output grows with the square of the model calls in a run; see `docs/roadmap.md`.
- The macOS app is not notarised and the Windows bundles are not code-signed (see First launch).
- The cost quote is an estimate: token counts are approximated where the source did not record them, and batch and
  cache discounts are not assumed.
- The Assistant's answers are model output: check them against the user guide.
- The update's Windows paths are not tested on Windows by this project's tests: the app's own `agentprov` printing to
  a Command Prompt or PowerShell window (`AgentPROV.exe --cli`), the helper that replaces an app whose own `agentprov`
  ran the install, and pip replacing a running `agentprov.exe`; and the `agentprov.cmd` launcher that Install Command
  Line Tool… writes (it runs `AgentPROV.exe --cli %*` from a batch file, so cmd waits for it and passes its exit code
  back) has not been run on real Windows either.
- After upgrading a checkout, rebuild the stale backend environments (`agentprov backends rebuild-stale`; the app's
  update starts it) so that live runs use the current capture and backend code. A change to `backends/shared` between
  releases without a re-lock is not detected by it: rebuild that backend with `agentprov backends build`.
- On an externally managed Python (one with `EXTERNALLY-MANAGED`, where `pip.conf` sets `break-system-packages`), the
  update plan can call a pip install updatable and the confirmed install then fails, since the upgrade reads no
  `pip.conf`; nothing is changed. Upgrade such an install with its own command.
- The app's own `agentprov` does not use the tier-4 round-trip cache (it ships the metadata of only some of the
  libraries the cache context names), so its validation is slower; outcomes and digests are the same.
