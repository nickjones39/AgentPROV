# AgentPROV v0.2.0

AgentPROV is an execution-provenance framework for LLM-agent security research. It reads agent runs, either released
benchmark logs or runs it captures live, and turns them into a canonical execution record (AER), semantic annotations
(SEM) and W3C PROV bundles (core, inference and assessment). It validates each stage and packages the result as
hash-chained corpora whose provenance can be recomputed without running a model again. Every derived statement names
its evidence class, the rule that produced it and the record field that justifies it.

- Website: https://w3id.org/agentprov/
- User guide: https://w3id.org/agentprov/docs/
- Software on Zenodo: https://doi.org/10.5281/zenodo.23970107
- Corpora on Zenodo (one collection): https://doi.org/10.5281/zenodo.23814758

Each bundle is built from the tag `v0.2.0` on a GitHub-hosted runner of its own operating system and architecture, and
each build runs the bundle checks and starts the app once. The 0.2.0 desktop app was tested on macOS; the clean-machine

### First launch

- **macOS:** the app is signed ad hoc, not notarised, so macOS refuses the first launch. Open System Settings ›
  Privacy & Security and click **Open Anyway**.
- **Windows:** the bundles are not code-signed. When SmartScreen warns you, choose **More info**, then **Run anyway**.
- **Linux:** unpack the archive and run `AgentPROV/AgentPROV`. The folder has a desktop-entry installer. It needs
  the X11 libraries listed in the user guide (chapter 8).

### Check what you downloaded

Every release file is listed in `SHA256SUMS` (sha256, two spaces, file name). Check the list's signature, then the
files:

```bash
ssh-keygen -Y verify -f allowed_signers -I agentprov-release -n file -s SHA256SUMS.sig < SHA256SUMS
```

```bash
shasum -a 256 -c SHA256SUMS --ignore-missing
```

`allowed_signers` is `src/agentprov/update/data/allowed_signers` in the source archive: it holds the public key of the
release key `agentprov-release` (D-1065), which signs `SHA256SUMS` from this release on and which `agentprov update`
checks too. The tag `v0.2.0` is signed with the maintainer's own key, the one on their GitHub profile.

## What is new in v0.2.0

### The desktop app

- **One visual and form style for the whole app** (D-1060). Every screen is built from one set of components: grouped
  sections in cards, plain labels with a short caption under them (the command-line flags move to the tooltips),
  only the rows that apply, one Advanced disclosure, and the results (cells, cost, the command) kept in view. Wherever
  the command line can do what a screen does, the screen shows the exact command in a card with Copy, built by the same
  code that builds the job. Run Live, New Job (two columns, with a "What happens" card), Settings (a sidebar of grouped
  panes instead of 13 tabs), Package (the nine steps as a stepper), Runs, Logs, System, Docs, the Assistant, Licences,
  About and the Zenodo drafts form all follow it, in light and dark.
- **The Viewer in three panes** (D-1060). At the left, the corpora grouped by state (Sealed, Working, Being written,
  Unreadable) with a filter box and Open Folder…; in the middle, the corpus header with its state and verification
  badges, filter chips with + Add filter, the executions table and the terminal command for the view; at the right, an
  inspector with the execution's views (Graph, AER, SEM, PROV-JSON, Register, Validation, Raw, Index Row). Both side
  panes collapse to a labelled strip (View › Show/Hide Corpora ⌥⌘1, Show/Hide Inspector ⌥⌘I). The filters build the
  same `agentprov stats --select` arguments as before.
- **Run Live quotes what a run will cost** (D-1062): a USD figure at the median and an upper figure (the sum of the
  per-cell 90th percentiles), with the calls, tokens and time, for any model you choose. It is marked as an estimate
  only and says what it rests on. `agentprov priors build` counts the executions of your own sealed corpora into local
  priors, which the estimate prefers to the shipped ones; `agentprov priors show` describes both. Prices can refresh
  once a day from OpenRouter when Run Live opens (`agentprov prices status`, `prices refresh --if-stale`; the setting
  `prices.auto_refresh`).
- **A live run can be paused, resumed, stopped or cancelled** from the Runs page (D-1061). The header shows the run's
  state, its billed calls and the spend's upper bound against the caps. **Cancel Run…** stops the run and marks it so it
  is never resumed: `agentprov jobs cancel ID` (a resume then refuses with `jobs.resume.cancelled`). Nothing is deleted.
- **Dev runs and batches can be stopped:** Stop Dev Run… and Stop Batch… in the GUI, `agentprov batch stop ID --steps`
  on the command line.
- **The Assistant opens as a tab beside the page you are on** (D-1040) and knows which page that is (D-1041; only the
  page's name is sent, never what it shows).
- **Tooltips** appear just beside the pointer (they were drawn far below it with a large macOS pointer size), every
  Package step has its own, and Settings › Appearance › Show tooltips turns them off.
- **Windows platform limits** (D-1064): live runs, the live preflight, live dev runs and the CPU queue
  options are refused on Windows with the reason, and the app disables them with a note. Each message says the
  feature works on macOS and Linux, then why it does not on Windows.

Earlier reviews kept every defect whose fix would change corpus results as a record only. For 0.2.0 they are fixed:
the 16 open findings of the 2026-11-01 review (UC-2, UC-12, UC-16 to UC-22, UC-37 to UC-43) with the excluded UC-44,
and the 12 recorded findings of the 2026-11-05 audit. Each group is a row of the regeneration batch list
(`docs/reports/analysis/regen-batch.md`) that states its prediction, checked read-only against the 52 sealed corpora:

- **Row 173, the importer:** a lowered `--max-json-depth` limits the inputs only; `--fetch` applies the same name and
  symlink checks as `--input`; a listing pin vouches only for the bytes it hashed; an interrupt no longer waits for the
  in-flight PROV batch; a purged object is never mapped or stored again; an archive member over the size limit is that
  candidate's `ingest.size.file`, never an aborted import. *On re-import:* the `aer` stage code digests of every family
  move; no record of a sealed corpus changes (none holds a triggering input).
- **Row 174, the agentdojo, Inspect and adprov adapters:** a deny-listed tool name in a capture is `unk ambiguous`
  instead of losing the session (UC-12); the capture mapper runs the lone-surrogate pass (UC-40); out-of-range
  durations, times and counts stay verbatim instead of reaching typed fields (UC-39); malformed shapes no longer crash
  the mappers (UC-42). *On re-import:* the adapter code digests of agentdojo (35 sealed corpora), inspect (6) and adprov
  (1) move; valid sources map byte for byte as before.
- **Row 175, DTap:** the redactor rewrites `$utf16` strings (UC-37); the not-inlined pass keeps every citation pointer
  valid (UC-38); a counter above 2^53 - 1 is not copied (UC-39); the lone-surrogate pass (UC-40); the judge-only path
  runs the not-inlined pass (UC-41). *On re-import:* every DTap AER header declares catalogue `dtap` 4 and `dtap-bench`
  4, so all AER, SEM and PROV bytes of `dtap-bench-w2c` change; no execution count, verdict or record body changes.
- **Row 176, the eight wave-2 families** (mcphunt, qwencode, agentops, openhands, autogen, wirelog, credleak,
  geminicli): out-of-range counts and times are kept verbatim and the checks become unverifiable (UC-39); the
  lone-surrogate pass (UC-40); strings over 1 MiB are not inlined (UC-41, six families). *On re-import:* the AER, SEM
  and PROV headers of the nine corpora of these families change; no record content or count changes.
- **Row 177, live capture:** the executor-gate recorder matches calls by identity (UC-2) and keeps the results of calls
  a gate ran before it raised (UC-17); defence code and weights load from the bytes that were checked (UC-18); the

  (UC-19, UC-20; `capture/0.1` keeps its id, amended in C.13); Anthropic sessions with a thinking budget declare what is
  sent (UC-21); T0's staging scan holds only real secrets (UC-22) and reads inside a staged zip such as an Inspect

  captures.
- **Row 178, provenance, raw store, statistics and datasheets:** an assessment inferred from an unknown premise keeps
  its method set instead of refusing the execution (UC-16); escaped lone surrogates in member labels are refused with a

  register and `counts.issues_by_code` cover the released set only (AU-BND-6, AU-BND-4). *On re-import or re-seal:* the
  `prov` digest of every corpus and the `aer`, `expand` and `sem` digests move; `DATASHEET.md` changes for every corpus

- **Row 179, the agentdojo family:** a string over 1 MiB is not inlined (UC-41); a loss issue cites its rule under

  instead of `known_incomplete` (AU-RA-4, AU-RA-5); the capture mapper cites through the same policy (AU-RA-1); two

before it is a drift report (H.8.4(5)), not a new version.

### Behaviour changes

- **`recompute` and `verify --level rederive` exit codes** (D-1050, AU-BND-5). The software version a stage records
  (`engine: agentprov@X`) is no longer a declared version, so a changed output with unchanged declared versions is an
  `unexplained_change` and exits 1, as H.8.4(2) says; before, every release bump explained every difference.
  `recompute --dry-run` of a sealed corpus also exits 1 when its index rows do not re-derive (as `verify --level
  rederive` already did), unless a declared version differs (then only with `--strict`).
- **A corpus derived or recomputed from a sealed corpus cannot be sealed** (D-1051). `package` refuses it first with
  `package.refused.derived` (exit 4). A new corpus version comes from re-importing the source; a sealed corpus is
  reproduced by recomputing at its building commit.
- **`verify --level chain` reports a stored raw object without an origin row** (`raw.origin.missing`), and `package`
  refuses such a working tree (`package.refused.raw_origin`), as left by a killed import (AU-IMP-7).
- **`--json` writes one document to stdout,** the summary, for every command; a command's own payload goes to stderr
  (AU-CLIA-11). `settings list/get`, `batch list`, `devrun list` and `assist --show-context` wrote two before.
- **`validate --release` adds every applicable tier** to a `--tiers` list, with a notice naming the tiers it added
  (AU-CLIA-14).
- **`validate --corpus` accounts for withheld raw objects** (D-1069): a check that needs the bytes of an object the
  sealed corpus's `WITHHELD.json` lists is skipped, not failed with `aer.blob.missing`. In dev mode the executions of
  `ast-survey-agentharm-rg2` and `fragfuse-agentharm-w2` and a few of `dtap-bench-w2c` failed before; they now pass
  with the skip and the counter `aer_withheld`, and fail `--strict` as a skip does. No corpus changes.
- **`import` checks its output guards earlier:** an existing or sealed `--corpus`, an overlap with the inputs and a
  git work tree are refused before a pin is read or fetched, in a dry run too (AU-CLIA-12).
- **`import --retry-failed` refuses `--limit` and `--sample`** (exit 2): a retry drops every failed row before
  re-mapping, so a cap left rows without an index entry (AU-IMP-1). The job form refuses the combination too.
- **Live-run call caps count the billed retries** (D-725 addendum, AU-LIVE-1, AU-FR-2): a cell reserves 384 billed
  calls under the presets' `gateway_compat` element (8 replies a step), 144 under the AutoDojo native element and 48
  otherwise, and a MELON cell 864 under `gateway_compat`. A capped preset run needs `--max-calls` of at least
  384 × `--jobs` to start all its jobs.
- **Live-run stops:** the first Ctrl-C, SIGTERM or `jobs stop` stops every worker at once (AU-LIVE-2); cells killed in
  flight are charged on resume (`live.caps.unledgered_cells`, AU-LIVE-3); a stop or drain sent while a job waits in the
  CPU queue is acted on (AU-RT-3).
- **The shipped estimate priors are rebuilt** with the fixed generator (AU-TRG-6): 54 of 509 rows change; the
  any-model rows now count every execution.
- Smaller fixes from the 2026-11-05 audit (76 fixed, each with a regression test): a malformed settings file no longer
  breaks `validate`, `import`, `derive`, `recompute` or `verify` with a usage error; `purge`, `fetch` and
  `info --matrix` no longer misreport, and `inspect` no longer crashes on a record field of an unexpected type;
  `verify --against-pins` never writes its cache inside the corpus it verifies.

- **AU-RB-2 and AU-RA-5: tool-call parts state `apv:dispatchStatus apv:NotDispatched` at class D in the core bundle**
  where the class-I twin applies, so the statement belongs in the inference bundle. A trailing call with no result
  cites `agentdojo.unexecuted_trailing_calls@1` as given instead of its `_unverified` twin: 48 tool-call parts in 47

  0.2.0 does not state. Its exposure classes are unchanged.

## What is in v0.2

- **The `agentprov` command-line tool and library** (Python 3.14): import, derive, validate, verify, recompute, render,
  statistics, estimate and priors, seal and package.
- **Import adapters** in an in-repository registry, mapped onto one versioned rule catalogue. Coverage:
  adapter-based core; demonstrated on 48 sources in 13 formats (single-agent, tool-calling traces).
- **Live capture** (`agentprov-capture`, `capture/0.1`) with the AgentDojo, AutoDojo and AgentDyn backends, and an
  Inspect harness that runs AgentHarm and imports Inspect's own log of the run. Live capture works and is tested in
  v0.2. No live results are claimed, and live corpora cannot be sealed yet.
- **The desktop app** for macOS, Windows and Linux: the corpus Viewer, the job runner with the exact command shown
  before it runs, Run Live with its cost quote and run controls, the packaging steps, and Help.
- **`agentprov-zenodo`**, which creates unpublished Zenodo drafts only. Publishing is always done by hand on Zenodo.

## Known limits

- Live corpora cannot be sealed yet. The live capture path is tested, and no live results are claimed.
- PROV output grows with the square of the model calls in a run; see `docs/roadmap.md`.
- The macOS app is not notarised and the Windows bundles are not code-signed (see First launch).
- The cost quote is an estimate: token counts are approximated where the source did not record them, and batch and
  cache discounts are not assumed.
- The Assistant's answers are model output: check them against the user guide.
- After upgrading a checkout, rebuild the backend environments (`agentprov backends build`) so that live runs use the
  fixed capture and backend code.
