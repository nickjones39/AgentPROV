- **D-701 (2026-10-22, `agentprov prices` and `agentprov estimate`; part of D-700; user decision 2026-10-22: the shared
  code moves into the core).**
  - **What.**
    - The GUI's price, estimate, usage and priors modules move unchanged in behaviour to `agentprov.estimate`
      (`prices`, `cost`, `usage`, `priors`, `plan`). Their data moves to `src/agentprov/estimate/data/` (`prices.json`,
      `estimate_priors.json`, and a stand-in script). The builders move to `tools/estimate/`.
    - The format ids lose their `gui-` part: `agentprov-prices/0.1` and `agentprov-estimate-priors/0.1`. The shipped
      rows are unchanged.
    - Refreshed snapshots now live in `$AGENTPROV_HOME/prices/openrouter-<date>.json`, and overrides in
      `$AGENTPROV_HOME/prices/overrides.json` (`agentprov-price-overrides/0.1`, under a resource lock). Old GUI
      locations are not migrated; nothing had been released.
  - **`agentprov prices`:**
    - `list [--endpoint] [--format]` gives every endpoint's resolved prices (`agentprov-prices-list/0.1`).
    - `get ENDPOINT MODEL` gives the price one estimate would use, or nothing.
    - `set ENDPOINT MODEL --input --output [--cached-input] [--cache-write] [--as-of]` stores an override. A refused
      value is exit 2.
    - `unset ENDPOINT MODEL` removes one.
    - `refresh --allow-network` (exit 4 without it) or `refresh --from-file RESPONSE [--fetched DATE]` writes a dated
      snapshot.
    - The fetch goes through `agentprov.raw.fetch.UrllibTransport`, still the core's only `urllib.request` importer.
      It fetches one URL with no key, redirects only to `openrouter.ai`, needs HTTP 200 and accepts at most 16 MiB.
      The response is parsed strictly and keeps ids and prices only; its sha256 is recorded and the bytes are not
      kept.
  - **`agentprov estimate SOURCE <run options> [--stats-corpus DIR]… [--format text|json]`:**
    - It takes run's options less `ESTIMATE_OMITS` (the run-only outputs, preflight, consent, staging, conformance
      and the host-preset options); one `add_run_options` serves both commands, so new run options reach the
      estimate too.
    - It plans in-process with `run --dry-run --plan-json` and reads `run --catalogue` for tool-definition sizes
      (if that fails, it warns and goes on).
    - Cell statistics come from up to 16 `--stats-corpus` (200 sampled AER files each, counts only), else the
      shipped priors, else `settings` `estimate.default.*`. Prices come from `agentprov prices`.
    - A real model is planned with its key only with `--keychain`, `--env-stdin` or `--env-file`. Otherwise it uses
      the scripted stand-in and warns that settled units of a resumed real-model corpus are not subtracted.
    - The model id comes from `--model-id` only; `.env` is never read for it. Without one, the estimate shows no
      cost and says why.
    - The output is `agentprov-estimate/0.1`: plan summary, p50/p90/worst cost (decimal strings), calls, time,
      per-suite and per-attack groups, sources, warnings and the text lines. The text lines are the wording both
      forms print.
  - **GUI.**
    - Run Live calls `agentprov estimate … --format json` (with `--stats-corpus` for the open corpora and
      `--keychain` when allowed) and shows the CLI's lines and numbers. Model completion and the price line come
      from `prices list`.
    - Settings › Prices calls `prices list|set|unset`, and Settings › Estimate calls `settings list|set
      estimate.default.*`. Refresh model prices is the `prices refresh --allow-network` job (R2).
    - The GUI no longer holds price, priors or estimate code, `gui/tools/fetch_prices.py`, or the incoming-response
      import.
  - **Cost.** Each estimate spawns two backend workers (plan, catalogue): about 10 s warm on the scratch AutoDojo
    environment (28 s cold), against about 10 s for the dry run alone before.
  - **Rejected:**
    - a GUI-computed estimate beside a CLI one (two implementations);
    - `run --dry-run --estimate-json` (estimate is not a run mode, and its run-only options would need refusals);
    - keeping the overrides in `settings.json` (a closed scalar schema; overrides are records);
    - the stdlib-only fetch tool (a second network path in the core).
  - **Class 0.** `estimate/` and `cli/` are outside every stage closure. The shipped tables do not feed AER, SEM or
    PROV.
  - **Tests:**
    - `tests/estimate/test_estimate.py` (moved);
    - `tests/cli/test_prices_cmd.py` (fake transport, hostile response, refusals);
    - `tests/integration/test_estimate_cmd.py` (fake backend: scripted, stand-in, override, no price, usage errors);
    - `tests/boundary` (`estimate` at layer 2);
    - GUI `test_g3_live.py` (panes and dialog against a fake CLI) and `test_cli_parity.py`.
  - **With the live pilot (D-721, D-725, D-726; train-2 land 2026-10-22).**
    - The caps (`--max-calls`, `--max-cost-usd`, `--price-in`, `--price-out`) are **estimate options**, not omitted.
      A keyed dry plan of an API endpoint needs them (D-721 refuses an uncapped API run before any key is read), so
      `estimate` passes them through to its dry plan.
    - `estimate` also compares them with its numbers: a cap below the p90 cost or calls is a warning, because the run
      would stop starting cells at the cap.
    - The estimate's own prices (D-701) stay the source of its cost. `--price-in`/`--price-out` only price the run's
      cap.
    - `--i-consent-to-local-run` is in `ESTIMATE_OMITS`, with the API-cost consent: no estimate is a consent.
