- **D-600 (2026-10-21, bug pass bugpass-perf-10, pre-check PC-redcode-exec-openhands-01/02,
  PC-autogen-guard-placement-01, CC-13: native secret-shape rules in the release scan; user decision 2026-10-21:
  approved, class 0).**
  - **Context:** gitleaks is the release scan's one secret scanner (G.9.4), and it runs at `--max-archive-depth 0`
    (D-450), because its own extraction is not bounded by the G.3 limits. So it never reads an archive member. The
    path scan reads members decoded (D-491), but until now it searched them only for the home path, the host name and
    account paths (D-457). The corpus pre-check of 2026-10-21 found a Hugging Face token shape in one member of
    redcode-exec-openhands's supplementary zip (PC-01; the batch never opened that zip, PC-02) and a Langfuse key pair
    in one not-selected member of the autogen-guard-placement deposit zip (PC-01). The release scan would have passed
    both with no finding.
  - **Decision:**
    - The path scan (`tools/release_scan.py`) gains native secret-shape rules (`SECRET_SHAPES`), applied to every file
      it reads and to every decoded archive member through the D-491 `member_scan` hook. They use the same locators and
      the same fail-closed `home-path-unscanned` finding as the other path-scan rules.
    - Rule ids are gitleaks 8.30.1's own where it has the rule, so a `[withhold]` policy's `scan_rules` and the builder
      backstop (D-236) name one id for both detectors:
      - `github-pat` (`ghp_`), `github-oauth` (`gho_`), `github-app-token` (`ghu_` and `ghs_`) and
        `github-refresh-token` (`ghr_`), each followed by 36 of `[0-9A-Za-z]`;
      - `github-fine-grained-pat` (`github_pat_` and 82 of `[0-9A-Za-z_]`);
      - `huggingface-access-token` (`hf_` and 34 of `[A-Za-z0-9]`; gitleaks' rule takes letters only and needs a
        terminator, so the native rule is the wider of the two).
      gitleaks has no Langfuse rule, so two ids are AgentPROV's: `langfuse-secret-key` and `langfuse-public-key`
      (`sk-lf-` or `pk-lf-` followed by a UUID, 8-4-4-4-12 hex digits, either case).
    - Boundaries: a shape must not follow a letter, digit or `_`, and must not be followed by a character of its own
      body. A longer token that holds a shape is not a hit.
    - The D-457 route: a literal is found with a plain byte search, then the shape is matched anchored there. Every part
      has a fixed length, so a match is bounded (`_SECRET_SPAN` = 100 bytes, which the chunk carry covers) and never
      backtracks. A shape is judged only when the byte after it is in the window, so a token cut at a chunk boundary
      is judged in the next window. The end of the file is the last bytes once more with a NUL after them, as in D-457.
    - No entropy threshold applies (gitleaks uses one): a low-entropy shape is a finding, to be triaged.
    - A finding records no value: path, rule and line only, fingerprint `<path>:<rule>:<line>`. It is untriaged and
      goes through the existing triage values (`real`, `synthetic-benchmark`, `false-positive`; no new value, so
      `agentprov.release` is unchanged).
    - A native finding whose fingerprint gitleaks also reported (a token in a stored file, same rule id, same line) is
      dropped (`native_findings`), so nothing is reported twice. A member finding (`<path>#<locator>`) never collides.
    - `PATH_SCAN_VERSION` becomes 4.
  - **Census** (count-only script, members read in memory, no value or member name printed). The rules were run over
    the pinned snapshots:
    - redcode-exec-openhands's `agent-execution-decisions-supp.zip`: 3,397 file members; 1 member with
      `huggingface-access-token` on 2 lines (PC-01's two `export` lines); no other shape.
    - Its six trajectory zips: 5,460 file members; 0 hits.
    - autogen-guard-placement's deposit zip: 109 file members; 1 member with `langfuse-secret-key` and
      `langfuse-public-key`, one line each. The synthetic sk-shaped string beside them, with its impossible key
      length, is not a hit.
    - No GitHub shape anywhere.
    The withholding itself is D-602 and D-603.
  - **Rejected:**
    - raising gitleaks' `--max-archive-depth`: its extraction is not bounded by the G.3 limits (D-450), and it reads
      to disk;
    - a second scanner (trufflehog was dropped, AD-10 row 19);
    - AgentPROV-own ids for the GitHub and Hugging Face shapes: a policy would then need two ids for one secret;
    - one combined `github-pat` id for every GitHub prefix: gitleaks names them separately, and its findings on stored
      files would then not deduplicate against the native ones;
    - native rules on archive members only: a member and its stored copy (a selected member) would then be scanned
      differently.
  - Byte class 0 (`tools/` and docs). No corpus byte changes. A scan document written afterwards records path scan
    version 4 and may hold new untriaged findings, so triage files for corpora that hold such shapes need review.
