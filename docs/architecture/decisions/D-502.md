- **D-502 (2026-10-14, core review A, regen item 67 / finding CA-8; user decision 2026-10-14). The accounting fix keeps
  `aer.acc.reported_counts@1`.**
  - **Problem.** L.1.2 increments a rule's `@n` whenever its output can differ for any input. Item 67 changes the
    rule's output for a scope that has both a cached agent call and a source-reported `usage.calls`.
  - **Decision.** No `@2`. The rule's released statement ("held assistant messages plus the emitted lost calls") and
    C.20(1) already exclude cached calls, so the code was the defect, not the rule. No shipped mapper writes a cached
    call together with `usage.calls`, so no stored or regenerated execution's output differs. This is a recorded
    exception to L.1.2, not a precedent for changes that alter any stored output.
  - **Rejected:** minting `@2` (catalogue `aer` version 2 with v1 archived, `adprov/artefacts.toml` and C.16 citations
    updated; every AER's seal would cite `@2`, so every AER digest would move for an input no mapper produces).
