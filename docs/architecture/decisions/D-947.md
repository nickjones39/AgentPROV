- **D-947 (2026-10-29, the index-only umbrella deposit, `package --index`; built in the release-preparation session
  from the orchestrator's brief; D-941 L-5 is its design, user-approved "i approve your recommendation"; addendum to
  D-790, D-870 and D-880).** D-941 L-5 chose an umbrella record that holds no corpus. `package --deposit` needs at
  least one corpus archive, and the uploader took only such directories, so D-880 left the umbrella open.
  - **Decision (as built):** `agentprov package --index OUT --part RECEIPT [--part ...] --corpus DIR [--corpus ...]
    --metadata release.toml --release-date YYYY-MM-DD [--dry-run]` (`agentprov.release.index.build_index`, offline,
    H.10.7). It writes `README.md`, `COLLECTION-INDEX.json` (`agentprov-collection-index/0.1`), a byte copy of each
    corpus's `DATASHEET.md`, `deposit-metadata.json` (`agentprov-deposit/0.1`, one licence, CC-BY-4.0) and
    `DEPOSIT-MANIFEST.json` of format `agentprov-index-manifest/0.1`, kind `index`. The manifest is the closed-world
    list of the documents with their sizes, sha256 and md5. There are no archives.
    - **Parts:** each `--part` is the uploader's receipt (0.2, `complete`, a reserved DOI and record id; all of one
      target; nothing twice). The part's deposit directory is read **beside the receipt** (its `draft_dir`), not given
      as an input. Only its `DEPOSIT-MANIFEST.json` is read, and it must be the manifest the receipt uploaded: its
      digests equal the receipt's entry, and the receipt's file list equals its archives and documents.
    - **Corpora:** the `--corpus` directories are exactly the sealed corpora of the parts, and each is in exactly one
      part. Each root digest is recomputed from `checksums.sha256`. `corpus.json` and `DATASHEET.md` must match their
      checksum entries. The id, version, content digest, root digest, licence class and datasheet must equal the
      part's. The chain verification and the release scan stay the part deposit's (H.10.1(3)).
    - **`COLLECTION-INDEX.json`:** one row per part (record name, title, reserved DOI, record id, deposition id,
      communities, licence class, the part manifest's sha256), each with its corpora (id, version, title, content and
      root digests, licence class, archive names, datasheet digests); the target; the index's own licence.
    - **Related identifiers:** `release.toml` `[[related]]` plus `HasPart` each part's reserved DOI. This is the pair
      `--cross-link` writes, so linking again changes nothing.
    - **The uploader** accepts kind `index`. The closed-world and digest checks are the same. In place of archive-mode
      `verify` it runs `agentprov.release.index.check_index_deposit`: formats and kind, distinct reserved DOIs, each
      corpus once, the datasheets against the index's digests, and CC-BY-4.0. It refuses `--root-digest` and an index
      built from another target's receipts. The consent screen adds one line naming the kind. The phrase, the
      allowlist, the receipt, `--community`, `--resume` and `--cross-link` (the index as `--umbrella`) are unchanged.
      No request kind is added; there is no publish call.
    - **GUI:** a `package_index` form (D-654 forward parity: `--index` and `--part` are form fields, listed in Runs ›
      New Job). *Create Zenodo drafts…* (D-880) still takes the umbrella on its first line. An index umbrella is named
      alone there, with no root digest. The GUI recognises it by its manifest's format and kind. The complete parts
      after it are skipped, and the cross-link step runs.
    - **`agentprov verify`** of an index directory reports `deposit.manifest.invalid` with the reason (no corpus
      archive; verify each part with the digests the index lists).
  - **Rejected:**
    - the part deposit directories as separate inputs (`--part RECEIPT=DIR`): the receipt already names its directory
      and lives beside it (D-790), so a second input could only disagree with it;
    - the index manifest as `agentprov-deposit-manifest/0.1` with a `kind` field: archive-mode `verify` and an older
      uploader would read it as a corpus deposit. Their refusals (no archive, no `CHANGELOG.md`) would be accidental.
      A format of its own fails closed by design. Corpus deposits keep 0.1 and their bytes;
    - recomputing the chain verification or the release scan of every corpus at index time: hours for the largest
      corpora (D-941 table 2), and both are already a precondition of the part deposit the receipt shows complete;
    - the index's reserved DOIs left to `--cross-link` only: the umbrella's metadata would not say what it holds
      until the cross-link ran;
    - `--root-digest` checked against the index's rows: it would anchor nothing, since the rows are in the same
      deposit;
    - a GUI action that builds the index between the part creates and the umbrella create: a new step in the D-880
      dialog, more than a form.
  - **Byte class 0:** `agentprov.release`, `agentprov.cli` (`package`, `deposit`), `zenodo/`, `gui/`, tests and docs.
    These files are in no stage scope. All 69 stage code digests (`expand`; `aer` per family, adapter and engine;
    `sem` per semantics family and profile; `prov`; `validation`; `views`; `compat`) are identical before and after.
    `tests/unit/test_stage_scopes.py` passes. `builder.py` and `metadata.py` are unchanged. A two-corpus deposit
    built from the test fixture before and after the change has the same sha256 for each of its 16 files, and
    `test_index.py` checks that a part deposit stays byte-identical. The sealed corpus format (`agentprov-corpus/0.2`)
    is unchanged.
  - **Open (for the user):** the index copies each corpus's datasheet into a CC-BY-4.0 record, also for the copyleft
    corpora (D-941 table 2 placed the datasheets in the umbrella). The datasheet is AgentPROV's generated text, but it
    quotes each corpus's restriction texts. `tools/zenodo_collection_trial.sh` still trials an umbrella that holds a
    corpus. Nothing of D-947 has run against the sandbox.
