- **D-664 (2026-10-22, kernel-enforced egress for sandbox-exec runs; user-approved with D-660 to D-669, design note
  `docs/reports/inspect-harness/design.md` §3.2; this entry is the record of what landed in the rebuild window; the
  D-660 to D-669 block arrives with the Inspect harness branch).**
  - **Containment.** The T2 profile denies every outbound connection except to two loopback ports given as parameters
    (`EGRESS_PORT`, `LOOPBACK_PORT`; G.4.10). For a remote endpoint both ports are T0's egress proxy
    (`cli/live/egress.py`). The proxy tunnels TLS through CONNECT, undecrypted, to the exact host and port pairs of
    the run's endpoints, forwards plain HTTP to a LAN model server's pair only (below), and refuses everything else.
    A loopback endpoint is reached directly through `LOOPBACK_PORT`.
    `PROFILE_SHA256` is `34018a40…`, so every environment re-probes once.
  - **Probe.** The probe checks:
    - the egress port: allowed;
    - `::1` on `LOOPBACK_PORT`: allowed;
    - another loopback port: denied;
    - `192.0.2.1:443`: denied.
  - **Transports.** The recording transports take the proxy from `AGENTPROV_EGRESS_PROXY`, through D-656's validating
    `egress_proxy()`. Without it they stay direct.
  - **Record (pre-round review R3-6).** The proxy writes its summary into the working manifest's `live` block as
    `live.egress`, or `null` when no proxy ran (scripted runs, loopback endpoints, operator-declared containment). Its
    shape is `{"kind": "connect_proxy", "allow": [<host:port>...], "tunnels": {<host:port>: <count>}, "forwards": {<host:port>: <count>}, "refused": {<kind>: <count>}, "refused_targets_distinct": <count>, "refused_targets_capped": <bool>}`.
    - `allow` and the `tunnels` keys are the pairs T0 itself put on the allowlist.
    - `refused` counts refusals per closed kind: `not_allowed`, `allowed_host_other_port`, `method`, `malformed`,
      `oversize`, `busy`.
    - `refused_targets_distinct` counts distinct refused targets with a BLAKE2b digest keyed per proxy and held in
      memory only. `refused_targets_capped` says that count saturated at 10,000.
    - No string the worker chose is ever recorded, and no digest of one (R1-7: a CONNECT target could otherwise carry
      a planted value past T0's fail-closed secret scan).
  - **Boundary.** `socket` is imported in `cli/live/` only by `egress.py`, which also holds the probe's loopback
    listeners (M.5.3).
  - **LAN forward mode (D-698 follow-up, 2026-10-22).** For a run with `--allow-lan-endpoint` and an `http://` base URL
    on a literal private address, `endpoint_target(..., allow_lan=True)` accepts the address (through
    `agentprov_capture.endpoints.is_private_lan_host`; IP literals join the allowlist in canonical form). The proxy
    then forwards plain-HTTP requests in absolute form, for that exact pair only:
    - methods `GET`, `POST`, `HEAD` and `OPTIONS`;
    - the request line rewritten to origin form, and `Host` regenerated from the pair (RFC 9112 3.2.2);
    - `Connection: close` in place of the hop-by-hop headers, and `Proxy-*` headers dropped;
    - the other headers passed as bytes, and the body as exactly its `Content-Length` bytes;
    - one request per connection: nothing after the body is read, and CONNECT to the pair is refused (LF-2).

    `live.egress.forwards` counts the forwards per pair. Every other request is refused with a closed kind:
    - `not_allowed` or `allowed_host_other_port`: a target off the list (or another port of a listed host);
    - `method`: another method, a request that is neither CONNECT nor an absolute-form forward, and CONNECT to a
      forward pair;
    - `malformed`: a head that does not parse, or is unsafe as below; a target with userinfo; a body framed other
      than by a single `Content-Length`;
    - `oversize`: a head over 8 KiB, or a body over 64 MiB;
    - `busy`: more than 64 open exchanges.

    An https LAN server is tunnelled through CONNECT, as any allowed pair; it is never a forward pair.
  - **Hardening before the first real LAN run (rebuild-window final re-check LF-1 to LF-5 and nits, 2026-10-22,
    class 0).**
    - **LF-1.** A head is refused (`malformed`) when a line holds a bare CR, LF or NUL, the method or a header name
      is not an RFC 9110 token (which also refuses folded lines and space before the colon), or the target is not
      visible ASCII. A bare LF had let a lenient server read a second, smuggled request.
    - **LF-2.** CONNECT to a forward pair is refused (`method`), so the forward rules cannot be bypassed through a
      raw tunnel. A forward passes exactly the `Content-Length` body; `Transfer-Encoding` and duplicate or malformed
      lengths are refused, and bytes after the body are never read.
    - **LF-3.** A malformed absolute form (a bad bracketed host, a bad port) is a `malformed` refusal, never an
      exception. Any unexpected error is counted the same way and logged nowhere, so no worker-chosen text reaches
      a traceback on T0's stderr.
    - **LF-4.** `stop()` cancels open exchanges before it waits for the server, with each step bounded (5 s).
      Before, a silent upstream held it for 30 s and left the exchange piping.
    - **LF-5.** G.4.10, the MN M.5.3 boundary table and this entry describe the forward mode.
    - **Nits.**
      - Brackets enclose an IPv6 literal only.
      - Zone ids are refused, and they fail `is_private_lan_host`.
      - An IP literal is an endpoint only on the LAN path (a remote https endpoint is named; an IPv4 literal had
        passed the name pattern by accident).
      - Schemes are compared in any case (`egress.forward_pairs`).
      - `Host` is regenerated from the pair (RFC 9112 3.2.2).
      - `provision_dataset` follows no symlink below the cache root or the environment.
  - **Class 0.** `cli/` is in no stage digest.
