- **D-203 (2026-10-12, deferrals part A: import-side blob storage; user-approved with the merge of part A).** A profile's `[import] blobs` globs name
  files that hold blob payloads AER records reference by digest (`$blob`, C.11.5; FooBench's screenshot). They are
  stored before mapping with their pinned origins (store-first; one the pin does not vouch for is
  `raw.origin.blob_mismatch`), never mapped and never registered, and every map job is offered, as `blob:<hex>`, the blob
  files in its primary's directory or below (the capture family's contract, D.10.4a), so a mapper can check a declared
  size; AER-V21 finds them in the raw store and the seal lists the referenced ones (`seal.blobs`). Blobs are raw evidence
  (C.11.5): a blob a mapper derives from an artefact (Inspect's condensed requests, DTap's long strings) needs an origin
  kind `aer/0.1` does not have and is left to the `aer/0.2` design (part C).
  - **Rejected:** offering every blob to every job (job inputs grow with the square of the tree); finding blobs by
    hashing every non-candidate file (reads every file of a tree); listing blobs as unit artefacts (a unit would claim
    blobs it never references).
