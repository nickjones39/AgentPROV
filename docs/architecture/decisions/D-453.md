- **D-453 (2026-10-14, bug pass bugpass-perf-10: a partial decoded scan of zips with no central directory; user
  decision 2026-10-14: approved as a follow-up).** 10p stores 186 `.eval` members cut at 256 KiB with no central
  directory, which `expand` rejects, so the decoded scan reports them unscanned.
  - **Decision:**
    - A new bounded T1 reader, used only when `expand` rejects an archive structurally. It walks the local file headers
      in order. Stored entries are read by size; deflate entries are streamed through zlib up to their end or the
      truncation, under `max_member_bytes` and the ratio limits. Nothing is stored. On a bad header it resyncs to the
      next local header.
    - Encrypted entries, other methods and stored entries of unknown size stay unscanned.
    - The object counts as `scanned_partial` (a seal-report count, nothing stored). The same job kind will also scan a
      tar's header fields and padding, which `expand` does not return.
  - **Soundness:** every byte is raw-scanned anyway. The walk decodes everything a local-header reader can reach, a
    superset of what any central-directory reader recovers. Content past a cut does not exist, and compressed bytes
    that no valid header introduces are presented as content by no zip reader.
  - **Sequencing:** it needs one `JOB_KINDS` entry in `io/workers.py` (in no digest; owned by the bf19-bf15 follow-up),
    so it is built on a fresh branch from main after that lands, with a full suite. Byte class 0.
  - **Rejected:** treating these archives as documents (fail open); decoding in the sealing process (G.4).
  - **Built (2026-10-21, branch `bugpass-d453-d454`, with D-454).** T1 job `zip_local` (`corpus/zip_local.py`, one
    `JOB_KINDS` entry). `withhold_scan` runs it when `expand` rejects a zip whole with `ingest.archive.format`, `.cd` or
    `.overlap` and the zip has a local header at offset 0, at any nesting level. Decoded entries are members like
    `expand`'s (names and data scanned, archives queued); a deflate stream that breaks gives what it decoded and the
    walk resyncs. `DecodedScan.partial`, the plan's `partial` and the seal counter `scanned_partial`. The tar header
    fields and padding are not part of this build (still not read). Byte class 0 (`corpus/`, `io/workers.py`).
