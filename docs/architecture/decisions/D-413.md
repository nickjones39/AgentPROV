- **D-413 (2026-10-14, pipeline-perf; reviewed by the runner and deferrals sessions; user-approved 2026-10-14).**
  `validate --corpus` runs tiers 3 and 4 in T1 `validate` jobs (the G.4.2 kind, until now absent; `sem` stays folded into
  `prov`).
  - **Parent:** reads and verifies every document and runs the AER tier, as before. It hands each job the exact
    verified buffers by digest from a private scratch store (0700, removed in a `finally`), and records the rows in
    index order.
  - **One code path:** `_read_row` (parent), `validate_documents` (shared by both paths) and `_finish_row` (the verdict
    rules, unchanged).
  - **Failure:** a stopped or crashed job fails its row with the check id `validate.worker`; the limit code goes to a
    notice.
  - **CLI:** `--jobs` (0 = the host default) is now real for corpus mode. `--in-process` keeps every tier in the CLI
    process (AD-10 row 17).
  - **Cap:** the `validate` pool alone gets the 4 GiB `prov` cap; the global `KIND_RSS_BYTES` is unchanged. The largest
    stored PROV document (3.98 MiB) peaks about 11× under the cap.
  - **Design and tests:** `docs/reports/pipeline-perf/validate-jobs-design.md`; differential tests in
    `tests/corpus/test_validate_jobs.py`.
  - **Status:** built on branch `pipeline-perf-d413`. It lands after the clone byte-diffs of the validation reports.
  - **Rejected:**

    - a new global `KIND_RSS_BYTES` entry (it changes every pool's recorded caps).
