- **D-196 (2026-10-12, phase 10i: injected failures and payloads; user-approved 2026-10-12).** An `injected_failure` result (2,093; 715 in
  scope) is generated by a harness `agentops:fault_injection` activity, **not** by a tool execution: the server
  fabricates it without running the tool (code, I). Its constant `latency_ms` is kept in `ext` and never read as a
  duration. An `injected_payload` result (2,011, all in scope) gets an `injection_payload` fixture (actor `att`, content =
  the field, O). The tool execution generates the tool output, and a harness `agentops:payload_injection` activity
  derives the delivered message from that output and the fixture. The `"\n\n" + payload` suffix holds byte for byte in
  2,011/2,011 cases (D); the attribution of the two parts is I. The semantics profile `agentops.tools@1` keys its
  injection markers by the sha256 of the 15 observed payloads, with class labels from the code catalogue.
  - **Rejected:** a `tool_execution` for injected failures (false: the tool never ran); treating the poisoned text as
    plain tool output (it would hide the harness as the payload's source).
