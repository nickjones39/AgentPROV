- **D-529 (2026-10-14, `import --sample` for dev test runs; designed by the CLI robustness session on the GUI build's
  request D-544, relayed by the orchestrator; user decisions 2026-10-14: approved; 2026-10-15: containers and
  multi-execution files are expanded or listed in full and only N mapped; it lands early and alone, for the corpus
  pre-check and the GUI dev runs).**
  - **Synopsis:** `agentprov import ... --sample N --sample-mode first|spread|random [--seed S]`. The mode defaults to
    `first`; `--seed` is required for `random` and only there; the option is exclusive with `--limit` and refused with
    `--release`, because a sample is a partial corpus and never released.
  - **Selection happens in the runner** (`adapters/runner/importer.py`, `_plan_sample`), once, before the batch loop,
    from the full list of the import's executions. Membership therefore never depends on `--batch-size`, `--jobs` or
    the resume order (cf. CD-7), and a resume selects the same set.
    - **Whole files:** sample key = the label; only the chosen files are read and stored.
    - **Containers:** every container is stored and expanded, and a `plan_only` container job lists the reader's
      planned units; sample key = `label!/member`. Pass 2 maps each container with every member as input (the plan
      needs them) and a `units` list, so only the chosen units are mapped.
    - **Multi-execution files:** each file is stored and mapped once to list its items (`summarise_unit_frames` heads);
      sample key = `label#<source key>`. Pass 2 re-maps only the files holding a chosen item and seals only those
      items. A file with no item (aborted, not of the dialect) is one unit, kept whole if chosen.
    - Pass 1 keeps its stored files and expansions for pass 2, so nothing is stored twice.
  - **Modes** (`select_sample`): `first`, the first N keys in sorted order; `random`, the N smallest
    `sha256(utf8(S) || 0x00 || utf8(key))` (no PRNG state); `spread`, strata in sorted order taken round-robin, each
    in key order. The stratum comes from a reader hook `sample_stratum(key) -> str | None`. Each hook lands
    as its own family-only branch after this one, as invariant 5 and the new-family guards require: `inspect.eval`
    (the `.eval` log), `autogen.runs` (`phase<N>[/<arm>]`) and `credleak.cell` (`<section>/<channel>`), each from its
    own documented path grammar. A reader without the hook refuses `spread` (exit 5,
    `import.sample.unsupported`); nothing is guessed from paths.
  - **Recording:** the working manifest gets `partial: true` and `selection.sample = {n, mode, seed, candidates,
    selected, stratum}`, written only when used; the summary counts `sampled_out`; `package` refuses a partial corpus. A
    recompute that re-maps a sampled corpus replays its recorded sample, so NEW holds the same executions. Ordinary
    imports are byte-identical (no new manifest key or counter, no new job param).
  - **Byte class 1** (regen-batch item 102): `adapters/runner/` moves the `aer` stage's `engine_code_sha256`, and each
    hook branch moves its family's `adapter_code_sha256`. A sampled unit maps to exactly the AER, SEM and PROV bytes
    it has in a full import.
  - **Rejected:**
    - CLI-side selection of input files (it samples files, not executions, and cannot see members, items or arms);
    - a PRNG such as `random.Random(seed).sample` (its algorithm is not a stable contract, and the result would depend
      on order);
    - stratifying by path components the reader does not define (a guess);
    - sampling container members by raw member rows (a log's header member is not an execution and is needed to plan).
    - Build sequenced by the orchestrator: after D-414, D-460 and `claude/derive-bugpass`, on a held branch, with regen items from `reserve_id`.
  - **Pre-round review addendum (2026-10-22; report `docs/reports/pre-round-review/report.md`, re-check RC-4; regen
    items 153 and 154; commits `f3e39ec9`, `5ed5e3f8`).** Two pass-1 behaviours change for multi-execution readers:
    - **PR-9, sampled-out files are no longer collapsed.** Pass 1 used to apply the D-202 collapse (or the resume count)
      to a file that another snapshot (or an earlier run) holds sealed whole as soon as it was stored, before the draw:
      a sampled-out file was then listed under the sampled snapshot, with a `dedup.collapsed` entry. Pass 1 now only
      lists such a file under its `<id>#` key (`<id>` is the candidate's sample identity, its label or, for a D-530
      pinned object, `label\x00pinned`). The collapse or resume is applied after the draw, and only when that key was
      drawn. A full import still collapses as before (D-202).
    - **PR-11 #3, a file whose rows are refused is one unit in pass 1.** A file whose rejected rows fail validation
      (D-321) is sealed whole in pass 2. Pass 1 now lists it under its `<id>#` key too, instead of its items. Before,
      the first run drew over the item keys and a resume over the `<id>#` key (NF-34), so a `random` or `spread` resume
      could draw another set.
    - Byte class 1 through `importer.py` (the `aer` engine digest). A sampled corpus is never released, so no kept corpus
      changes.
