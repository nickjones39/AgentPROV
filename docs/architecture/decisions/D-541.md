- **D-541 (2026-10-15, core review C finding CC-16 follow-up; user decision 2026-10-15: approved, delegated to the
  orchestrator and confirmed directly by the user). `agentprov.api.rows(corpus, "lineage")` is built.**
  - **Rows (MN M.6; O.3.5 F5).** One row per edge, columns `from_node`, `to_node`, `relation`, `n`, `basis`, read
    from a sealed manifest's `sources[]` (snapshots and the `[lineage]` recorded at sealing) and `raw/origins.jsonl`
    only. Nodes are registry source ids (`<source>/<part>` for a declared part) and upstream artefacts
    (`repo@commit`; `zenodo:<doi>/<file>`, `hf:<dataset>@<revision>`, `<corpus>@<version>`):
    `snapshot_of` (`n` the snapshot's candidates, basis `corpus.json`); the declared `built_on`, `vendored`,
    `cited_by`, `owns`, `excludes` (`n` null); each declared duplicate with its relation (`n` the raw objects whose
    origin path its `path` glob matches, basis `profile [lineage]; raw/origins.jsonl`); and a within-corpus
    `byte_identical` edge (`n` the objects held under more than one origin) when there are any. Sorted by
    `(from_node, relation, to_node)`.
  - **Unavailable.** A corpus whose manifest records no `sources[].lineage` (a working corpus) raises
    `ApiUnavailable`. This closes the `rows(corpus, "lineage")` deviation that D-48 listed in the `agentprov.api`
    docstring.
  - **Tests.** `tests/cli/test_api_lineage_rows.py` on the sealed fixture `mini-mit` (three duplicates entries, a git
    snapshot), plus a variant with the lineage removed; `test_unavailable_parts_say_so` keeps its working corpus.
  - **Rejected:** reading the profile files at query time (the corpus must be self-describing at its sealed
    versions); counting collection manifests or per-execution lineage documents (deferred, AD-10 rows 5-6).
  - **Downstream:** new API behaviour, no corpus bytes.
