  After sealing, the 8 round-1 corpora's release scans left their `gitleaks` and `account-path` findings untriaged
  (8,445 in 6 corpora), and the deposit builder refuses an untriaged finding (G.9.4). They were reviewed by class, never
  by value. A triage file lists them by fingerprint, so a tool must turn the class decisions into entries.
  - **Decision (as built):** `tools/release_triage.py` (outside `src/`, like `release_scan.py`):
    - It reads the corpus's untriaged scan document (same root digest, pinned scanners) and runs the pinned gitleaks
      again, redacted, for the key names only. Its fingerprints must equal the document's, or nothing is written.
    - Each `gitleaks` finding gets a class (rule, key name, origin), by check 4b's method. `upstream-data`: a 16+
      character token of the line, or a private-key header, occurs in the benchmark's own suite data (`--suites`).
      `benchmark-input` or `model-generated`: by the AER record's `k` and `role`. A PROV, SEM or raw copy follows its
      execution's AER findings: their one origin; or n-th copy to n-th AER finding when the counts are equal (with the
      key, then the rule alone); or, failing both, n-th copy to n-th AER finding in line order, which is check 4b's own
      rule. Otherwise `unclassified`. When several report entries fall on one line, their key names are joined sorted
      with `+`, since gitleaks' report order is not fixed.
    - Each `account-path` finding gets the ordinals of the account names on its line, numbered by first appearance in
      label order (the post-check's method). Names stay in memory, and no name or digest of one is written.
    - A reviewed decisions file (`agentprov-triage-decisions/0.1`) maps `[[secret]]` classes and `[[account]]`
      ordinals to `synthetic-benchmark`, `model-generated` or `false-positive`, never `real`. Each row carries the count
      its review saw (`findings`, or an ordinal's `hits` by area); any other count writes nothing. A line with several
      ordinals takes the first of their triages in the order model-generated, synthetic-benchmark, false-positive.
    - The output is `<corpus>.release-triage.toml` beside the sealed tree, next to `<corpus>.release-scan.json` (D-609).
      A path inside the tree is refused. The decisions files of round 1 are kept in the repository
      (`docs/reports/release/pre-release-checks/triage-decisions/`): they hold rules, key names, origins, ordinals and
      counts only.
    - `--report` prints the classes and counts that a reviewer needs to write a decisions file. `--list-secrets` prints
      one line per distinct gitleaks value: a 16-hex HMAC-SHA256 under a random per-run key, plus the value's rules,
      keys, origins and counts. The values come from an unredacted gitleaks run read from standard output (never a
      file). `--show` adds them, fenced by `quote_untrusted`, and only when standard output is a terminal.
    - `release_scan.run_gitleaks` and `parse_gitleaks_report` gain the optional `matches` sink and `redact=False` for
      this tool. With their defaults the scan is unchanged.
