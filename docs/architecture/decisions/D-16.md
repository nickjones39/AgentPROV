- **D-16 (2026-10-08, a request-less tool execution gets no exposure assessment; spec conflict, implementation ruling).**
  D.12.2 and K.6.4 list "exposure assessment with subject `x:te5`" for FooBench's text-parsed action (phase 7), but EF
  E.7.3, which owns the assessment mapping, says a `tool_execution` without a request part has no generating invocation
  and therefore no context premise in `aer/0.1`: no exposure is emitted and the count is reported. EF governs. `te5`
  gets no `apv:ExposedTo` (nor taint); the derivation report counts it, and K.6.4 asserts the absence as a named gap.
  - **Why:** exposure is a claim about the context of the invocation that generated the request. `te5` records only
    `requested_by: "agent"`; nothing links it to the assistant message it was parsed from, so any context would be
    guessed, which invariant 2 forbids. The role and integrity labels of `te5` are still emitted.
  - **Rejected:** taking the context of the nearest earlier invocation of the requesting actor (an order-based guess);
    adding a `parsed_from` link (an `aer/0.1` change after the freeze, D-14). Revisitable in `aer/0.2` with an explicit
    source link for text-parsed actions.
