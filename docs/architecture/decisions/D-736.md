- **D-736 (2026-10-22, a local model's identity leaves out load and serving state; finding from the live pilot's Part L;
  design approved by the orchestrator).**
  - **Finding.** On LM Studio, `identity_sha256` changed with the model's load state (same files: `671beca3…` unloaded,
    `95d6f4a5…` loaded), because `server_identity` held the loaded instance's `loaded_instances`, `parallel` and
    `context_length`. The identity feeds the configuration digest (D-693), so a run started cold and resumed warm
    would have been refused as mixed configuration (G5). The LM Studio server version was not recorded.
  - **Fix.** Per server kind, the native facts that describe load or serving state go to a new `observed_state` member,
    recorded but outside every identity digest (`localmodels.STATE_FIELDS`): LM Studio `loaded_instances`, `parallel`,
    `context_length` (the loaded instance's setting); llama.cpp `total_slots`. Ollama's `context_length` is the model's
    own and stays in `server_identity`. Ollama's `show_sha256` (a raw-response digest) leaves `server_identity`; the
    response stays cited in `listing.responses`. `identity_sha256` and the per-cell `server_side_sha256` (A14) now hash
    the same model facts.
  - **Server version.** `server.version` with a new `server.version_source`: Ollama `GET /api/version`, vLLM
    `GET /version`, llama.cpp `GET /props build_info` (moved from `server_identity`). LM Studio exposes no version over
    HTTP (checked on 0.4.23: `/api/v0/version` and `/api/v1/version` answer an error object), so its version is
    `null` with `version_source: "not exposed by the server"`, never guessed. LM Studio's own `/lmstudio-greeting`
    (`{"lmstudio": true}`) joins its fingerprint evidence when the server answers it. **Rejected:** the version from
    the macOS app bundle (Info.plist) or from running `lms version`: that is the installed application, not the running
    server's statement, it differs per OS, and `lms` would need a reviewed subprocess (SEC-11).
  - **Format.** `agentprov-local-model/0.2` (the member set changed: `observed_state`, `server.version_source`; state
    fields moved). D-31 criterion: a format recorded only in scratch corpora bumps rather than changing in place, so
    `agentprov-local-model/0.1` stays in `formats.py`, marked superseded. The live pilot's two Part L corpora carry 0.1
    records and the old (load-state-dependent) digest; they are finished and are not resumed.
  - **Class 0.** `cli/live/localmodels.py`, `formats.py`, the test stub and tests: no capture, backend, AER, SEM, PROV
    or validation change, no env rebuild, no stage digest moves (`regen_pins --check`). New local-model sessions carry
    the 0.2 record in their `agentdojo/local_model` note and in `live.local_models`, and their configuration digest
    differs from a 0.1-era run of the same model.
