- **D-360 (2026-10-13, fixture-tree caps; user decision in the orchestrator session, implemented on branch `fixture-cap`).**
  The fixture tree's total cap rises from 8 MiB to **16 MiB**, and each **source** (a top-level directory of
  `tests/fixtures/`) gets a budget of **512 KiB**, larger only with a recorded reason. The caps live in
  `tests/FIXTURES.json` (`agentprov-fixture-caps/0.1`): `caps` (total, per file 1 MiB, per source), `oversize_files`
  (path and reason; the two complete `.eval` logs) and `source_exceptions` (source, `budget_bytes`, reason). Existing
  exceptions on 2026-10-13: `inspect` 3,049,864 B, `agentdojo_prov_v1` 1,071,984 B, `openhands` 1,025,419 B, `capture`
  566,153 B, each with a budget rounded up to the next 64 KiB. One checker, `agentprov.testing.fixture_caps`, is used by
  `tests/golden/test_golden_index.py` and `tests/repo/test_fixture_caps.py`; stale or unreasoned entries fail too. Spec
  K.4.1(5).
  - **Why:** several new families arrived in parallel and the 8 MiB tree held 7.59 MB; a per-source budget keeps any one
    source from taking the headroom, and a reason makes every exception reviewable.
  - **Where the file lives:** beside the tree, not in it: `.claude/settings.json` closes `tests/fixtures/**` to agents'
    reads (K.4.1(4), R-42), and the caps are policy, not fixture content, so agents must be able to read and edit them.
  - **Rejected:** keeping the caps as constants in a test (the reasons would be spread over test files); a budget per
    file only (one source could still fill the tree).
