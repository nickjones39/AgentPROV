- **D-186 (2026-10-12, phase 10h: raw objects with account paths in a public release; user decision 2026-10-14: option (c)).** Redaction

  - **Addendum (2026-10-13, after the withholding merge D-230–D-237):** option (b) no longer needs a new mechanism.
    A profile `[withhold]` rule with scope `object` (D-235) withholds the raw objects that hold an account path and
    keeps their executions released. `WITHHELD.json` keeps their pinned origins and stage digests, so they can be
    recomputed from the public pin (D-230). The rule patterns can match the path structure without naming an account
    (for example `/home/[^/]+/\.cache/inspect_evals`). A derived hit still withholds the execution (D-235), so (b)
    works only after D-182 has removed the paths from the AER. Today that would withhold kexin's 18 checkpoint logs
    and fragfuse's 25 traceback/metadata samples as executions. The choice among (a), (b) and (c) stays the user's.
  - **Decision (user, 2026-10-14): option (c).** Raw objects that hold a workstation account path ship as they are,
    since the same bytes are public at the pinned origin. No `[withhold]` rule is added for account paths in raw and
