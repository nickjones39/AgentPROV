- **D-604 (2026-10-21, bug pass bugpass-perf-10: third-party account paths inside content; principle; user decision
  2026-10-21: approved, tool output only).**
  - **Context:** D-182 redacts workstation account paths in harness-written fields only. Its rejected alternatives
    (`docs/reports/phase10h/redaction-design.md` §8) keep model output and benchmark content verbatim. D-186 (c) ships
    raw objects as they are, because they are public at the pin. The pre-check of 2026-10-21 found third-party account
    paths inside execution content: tool and environment output (a shell's working directory, a traceback, a listing)
    in whistlebench, credleak, openagentsafety and agentops. Model-authored text can repeat such a path. D-457 makes
    the release scan report them. They cannot be released without either withholding whole executions or editing
    evidence.
  - **Decision (principle; the family branches apply it: D-601 whistlebench, D-605 credleak, D-606 openagentsafety,
    D-608 agentops. D-607, dtap, is a decision of its own: a structural pattern limited to a profile `labels`
    allowlist of salted labels, over every AER string):**
    1. A third-party account path inside **tool or environment output** is redacted in the derived records (AER, SEM,
       PROV) as D-182 redacts harness fields. A salted label stands in its place. The pointer is tagged `D` and cites
       the family's versioned redaction rule. An info issue is sealed. The original, or a digest of it, is never
       recorded.
    2. **Model-authored text stays verbatim.** A path the model wrote (an assistant message, a tool call's arguments)
       is never redacted: that would falsify what the model did.
    3. The **raw objects** that hold the path are withheld at **object scope** (D-235, `personal_data`). Their
       executions stay released, and `WITHHELD.json` keeps their pinned origins and stage digests.
    4. An **execution whose derived record still holds the path** (because the model wrote it) is withheld at
       execution scope through D-235.
    5. It departs from D-182 §8 ("never redact benchmark content") and from D-186 (c) for these sources only. Every
       other source keeps D-182 and D-186 as they are.
    6. **The label's limit (user decision 2026-10-21: keep the deterministic `{span12}`, disclose the limit).** A label
       is a 12-hex digest of the span salted with the public profile id, so a short or common name can be recovered by
       guessing candidates. It hides the name from a reader, not from someone who guesses. The datasheet states this
       (statement `redaction-labels-guessable`), and so does the release decision (G.9.6). The release scan does not
       report a label as an account (`acct-<12 hex>`, `REDACTION_LABEL` in `tools/release_scan.py`).
    7. **Raw residue ships as pinned (user decision 2026-10-21).** Where a raw file still holds a third-party account
       in a form no exact withhold rule can target (byte patterns cannot use the labels, so a broad rule would also
       catch other names and, through D-235, withhold executions whose derived records keep benchmark names), the raw
       file ships as pinned (D-186 (c)); its derived records are redacted; the corpus's datasheet discloses it. The
       release scan's `account-path` findings on such files are triaged `pinned-account`, which the deposit builder
       accepts for an `account-path` finding in `raw/` only (`release.refused.scan_pinned` anywhere else, since a
       derived record must be redacted). Applies to credleak's raw cells (bare name), DTap's raw trajectories,
       WhistleBench's raw samples and openagentsafety's raw trajectories and state files. Item 3 (object-scope
       withholding) still applies where an exact structural rule exists (interbolt D-456, D-608, D-609, fragfuse,
       kexin). EnvironmentOptim's raw logs ship as pinned under D-510 (user decision 2026-10-21).
  - **Consequences:**
    - The redacted records differ from a verbatim mapping. Each redaction is visible (a `D` pointer, the rule id, the
      info issue), so the AER still says what was observed and what a rule changed (invariant 2).
    - The family's adapter or profile digest moves, so each family branch is a class-1 regeneration item with its own
      byte-impact table.
    - Released executions recompute only from the withheld raw's pinned origin, which `WITHHELD.json` names (D-230).
    - The datasheet discloses the redaction, the withheld objects and the withheld executions.
    - The release scan's `account-path` findings on withheld objects are covered by `WITHHELD.json`. Findings on
      released derived records must be 0 for the target accounts (the residue each family census records).
  - **Rejected:**
    - **Full content redaction** (redact model-authored text too). It edits the record of what the model said and
      did, which is the evidence the corpus exists for, and it breaks the D-182 rule that model output is never
      redacted.
    - **No content redaction, withholding the executions instead.** Every execution whose tool output holds a path
      would be withheld. For these sources that can be a large share of their executions, lost for a path that a
      label can stand in for without loss to any analysis of agent behaviour.
    - **Shipping as is (D-186 (c) extended to derived records).** It publishes third-party account names in
      AgentPROV's own records, which D-457 and the user decision of 2026-10-15 rule out.
  - Byte class 0 for this entry (a principle). Each applying branch records its own byte impact.
