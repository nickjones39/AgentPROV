- **D-1000 (2026-10-29, the project website: a landing page at the root and the user guide under `/docs`; proposed by
  the landing-page session for the owner's yes in the orchestrator's window; byte class 0, docs and site only).** The
  owner asked for a landing page with downloads, the logo, an interactive demonstration of the desktop app and a
  w3id address, on GitHub Pages beside the MkDocs guide (D-760).
  - **What.** `site/` is the landing page's source: static HTML, CSS and a little JavaScript, self-hosted (no font
    files, no CDN, no analytics, no cookies, no request to another host; a `Content-Security-Policy` meta tag says so).
    MkDocs now builds the guide into `_site/docs` (`site_dir`; `site_url` `…/AgentPROV/docs/`), and
    `.github/workflows/pages.yml` (still `workflow_dispatch` only, D-431) copies `site/` to `_site/` and uploads
    `_site`. `/_site/` replaces `/site/` in `.gitignore`. The guide's header logo leads back to the landing page
    (`extra.homepage`). The design note is `docs/reports/site/design-note.md`.
  - **Content rules.** The page's copy passes the shared claims lint (`claims.lint_text`, as the README and the
    datasheets do) and the O.1.2 phrases it does not cover; the coverage line is the registry-generated phrase; live
    capture is worded as a tested capability with no live results (D-991, U-18). The app tour uses real screenshots of
    v0.1.0 on the synthetic test corpora, taken by `gui/tools/screenshots.py` (light and dark), and describes only what
    user guide chapter 8 documents. Downloads use `github.com/nickjones39/AgentPROV/releases/latest/download/<asset>`
    with the v0.1.0 plan's asset names, including `AgentPROV-0.1.0-source.tar.gz` (F-5). `tests/repo/test_site.py`
    checks all of this, and lists the release-day placeholders (DOIs, the paper and Zenodo links).
  - **w3id.** A patch for `perma-id/w3id.org` (`ids/agentprov/`) adds two rules before the catch-all:
    `w3id.org/agentprov/` and `w3id.org/agentprov/docs/…` redirect to the website; no `/ns` or `/exec` rule changes.
    It is prepared in `docs/reports/site/w3id/` and not submitted: the owner decides when (recommended: release day,
    once the website is live; go-live step 7).
  - **Rejected:** a separate directory name for the landing page with the guide kept at the root (the owner asked for
    the landing page as the address and the guide at `/docs`); a static site generator for one page (a build step and a
    dependency for no gain); a web font (a licence and a file to ship; the platforms' own faces read well and cost
    nothing); embedding a video of the app (large, not accessible, and stale at the next change); taking over the whole
    `w3id.org/agentprov/` catch-all (it would move every non-`/ns` path away from the vocabulary site).
