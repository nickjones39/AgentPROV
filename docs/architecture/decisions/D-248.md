- **D-248 (2026-10-13: pax `x` extended headers through a closed allowlist; D-192 part 2; user-approved 2026-10-13).** `_walk_tar`
  reads an `x` header's records as data, bounded by the new limit `max_pax_header_bytes` (64 KiB), parsed strictly;
  `path`/`size` apply to the next entry under the names guard and the member gate; `mtime`, `atime`, `ctime`, `uid`,
  `gid`, `uname`, `gname`, `SCHILY.xattr.*`, `LIBARCHIVE.xattr.*` are ignored; every other key (`linkpath`,
  `hdrcharset`, `GNU.sparse.*`, `comment`, ...), a `g` global header, two `x` headers in a row, an `x` next to a GNU `L`
  and an `x` without its entry refuse the archive. `tarfile` stays unused. Spec G.3.5.
  - **Why:** AgentOps-Bench's `tar.gz` carries 7,270 `x` headers (`mtime` and macOS `com.apple.provenance` xattrs, D-192);
    `tarfile` itself writes `x` headers for any non-ASCII name.
  - **Reverses D-57's** "rejected: pax support" under the same bound it asked for.
  - **Rejected:** accepting every key and ignoring the unknown ones (a key such as `GNU.sparse.map` or `hdrcharset`
    changes how the entry's bytes or name must be read; silence would mis-read them); `linkpath` (links are rejected
    members anyway, and its value would be unchecked text); global `g` headers (they change every later entry).
