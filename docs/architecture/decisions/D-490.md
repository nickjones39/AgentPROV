  - **Problem.** `release/verify.py` checked each `documents[]` file only against the deposit manifest, which nothing
    anchors. A forged `DATASHEET-<id>.md` (the human-facing licence, restrictions and untrusted-content statement,
    REP-3) passed `verify --release --root-digest`, and so did an extra document whose name matched the grammar

       per `corpora[]` entry; anything else is `deposit.manifest.invalid`.
    2. The copy is compared with the `DATASHEET.md` read from that corpus's archives. That file is covered by the
       archived checksums and the root digest.
    3. Without mixed licence classes the copy must be byte-equal. With them it must be the sealed text, a newline and
       the builder's note. **Amended by D-620 (2026-10-22):** the note is rebuilt in full and compared byte for byte,
       not only its header.
    4. A mismatch is `deposit.document.datasheet`.
    5. `README.md`, `CHANGELOG.md` and `deposit-metadata.json` stay covered only by the deposit manifest (H.10.3).
