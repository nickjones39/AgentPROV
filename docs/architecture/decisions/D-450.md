- **D-450 (2026-10-14, bug pass bugpass-perf-10, finding BF-18: archives are read decoded for the `[withhold]` byte
  rules; user decision 2026-10-14: approved).** A byte rule was searched only in every stored raw object's bytes as
  stored, and the AD-12 closure followed only `selected` member rows. A canary inside a deflated (or tar.gz / tar.zst)
  member was never seen, above all in a member the profile did not select: it is never decompressed at import (R-40)
  and has no object of its own. Neither backstop saw it either: `chain` and the deposit builder rescan the same stored
  bytes, and gitleaks runs with `--max-archive-depth 0`. So the container was released. The shipped profiles reach this:
  geminicli D.23.7 (key-shaped values in `claude_code` files the profile does not select, inside the zstd tar) and
  credleak D-265 (collector logs the profile does not select, inside the zip).
  - **Decision:**
    - **Seal-time decoded scan** (`agentprov.corpus.withhold_scan`; G.9.5 is the precise statement). When the policy
      has byte rules, the stored archives are read in decoded form. Recognition uses the first 512 and last 64 KiB
      bytes only. A zip at offset 0, a gzip or zstd tar and a split archive (through its parts) are opened. Any other
      archive or compressed-stream shape fails closed (unscanned). The bytes are copied by digest into a scratch store
      under `$AGENTPROV_HOME/tmp` and expanded by the bounded `expand` job in T1 (the G.3.5 gate, default limits).
      Every member's label and contents are scanned, and nested archives are read depth first. A member is deleted
      once read; at most `max_total_bytes` of decoded members are stored per root.
    - **Withholding.** A match withholds the archive object (basis `profile_rule`, new detector
      `agentprov-withhold-decoded/1`), at object level, and only when no other cause withholds it already, so an
      archive withheld by the closure keeps basis `container`. Its D-315 group and the archives that hold it follow.
    - **Fail closed.** An archive that cannot be read decoded refuses the seal (`corpus.withhold.unscanned`, exit 4)
      unless it is withheld for another cause. The reasons are the recognition above, a limit, a rejected or unexpected
      member, bytes after a zip's end record, nesting beyond the allowance, a missing split part, bytes that do not
      match their digest, or a worker pool that cannot start (isolation, the interpreter guard; never a crash).
    - **Backstops.** `withhold.rescan` (`verify --level chain`, the deposit builder) does the same over the released
      tree. A match is reported for the archive's label. An archive that cannot be read decoded goes to an `unscanned`
      collector: the builder refuses it (`release.refused.withhold_unscanned`). Without the collector it is reported as
      a match of the reserved rule id `<unscanned>`, which no valid rule id can equal, so `chain` fails until it maps it
      to a code of its own. That `verify.py` change is routed to ingest-formats-3 with BF-19 (`withheld.container`),
      because that branch owns the file.
    - **`release_scan.py` keeps `--max-archive-depth 0`, and now says why.** gitleaks' archive extraction is not bounded
      by the G.3 limits, so it never runs over third-party archives. AgentPROV's bounded path reads them instead.
  - **Rejected:**
    - relying on the release-time gitleaks scan (it does not open archives, and should not; D-289 also notes that many
      canaries have no recognisable shape);
    - decoding in the sealing process (archives are parsed only in T1, G.4);
    - withholding the executions of an archive whose decoded members match (they cite their own selected members, which
      are scanned as stored; withholding them all would drop every run of a deposit for one unselected file);
    - a label-based guess of which members are archives (a misnamed archive would pass unread; the first bytes decide);
    - skipping archives that cannot be read (silent release of unread bytes).
  - **Downstream:** byte class 0. No AER, SEM or PROV byte and no stage code digest moves: `corpus/` and `release/` are
    in no digest, and `raw.members` (EXPAND_MODULES) is used, not changed. `WITHHELD.json` of a future seal can now list
    an archive with the new detector. A seal can now be refused where it used to pass: a policy with byte rules over a
    corpus that stores an archive that cannot be read decoded (D-452 and D-453 narrow this; D-454 withholds the rest).
    Sealing, `chain` and the builder spend T1 time decoding the stored archives when the policy has byte rules, and a
    seal does it twice (the planner, then the seal's own `chain` run). An independent review of the first version found
    fail-open shapes (a prefixed zip, an uncompressed tar, 7z), unbounded scratch use and a crash on degraded
    isolation; all fixed before the gate. Tests: `tests/unit/corpus/test_withhold_scan.py` (scanner, planner, rescan;
    the geminicli and credleak shapes with the shipped policies) and
    `tests/adapters/geminicli/test_withhold_e2e.py::test_a_key_in_an_unselected_member_withholds_the_tar_d450` (import,
    seal, `chain --release`, deposit).
