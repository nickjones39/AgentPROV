- **D-526 (2026-10-14, progress 0.2 as built; refines D-393).**
  - **`seq`** is assigned when an event is queued, up to the file's level, so a gap is a drop. The `run` line is
    reserved `seq` 0.
  - **Run id:** a UUIDv7 per process.
  - **The `run` header** holds pid, command, mode, dry run, jobs, the corpus root and the summary path (escaped and
    home-redacted), the software version and `segment`.
  - **`heartbeat`** is an absolute snapshot from the producer-side counters. It is written every `--progress-interval`
    (default 2 s, 1..3600), at each `stage` end and before `end`.
  - **Rotation** past `--progress-max-bytes` (default 8 MiB, at least 64 KiB) renames the file to `PATH.1` and starts
    the new file with a `run` line and a heartbeat.
  - **Stages:** `package`, `verify` and `backends build` emit `stage` events and keep their unit events.
  - **Rejected:**
    - assigning `seq` at write time (drops would be invisible);
    - heartbeats on stderr's plain or tty renderers (display noise; those renderers keep their own status line);
    - more than one rotated file (design §5.3 bounds disk use to two segments).
