- **D-162 (2026-10-12, proposal P-1 implemented: orphan execution files fail `chain` on a sealed corpus; user-approved
  2026-10-12).** On a sealed corpus (tree or archive), every file present whose H.1.3 role is `aer`, `sem` or
  `prov` must be a path an index row names (`aer`, `sem[profile]`, `prov[spec]`); otherwise `index.orphan` (failed).
  This narrows the D-39/D-63 boundary: an orphan added with regenerated checksums is no longer detected by the root
  digest alone. Working trees are not checked (they need not be closed-world until sealed), but sealing runs `chain` in
  release mode, so a working tree that holds orphans is now refused at sealing. Of the existing working corpora under
  `~/.agentprov/corpora`, only `agentdyn-a-p10.pre-integration.partial` holds orphans (388); the current `*-p10.partial`
  trees hold none.
  - **Rejected:** reporting orphans `unverified` (they are bytes in a sealed deposit that no digest chain covers, the
    exact gap P-1 names); checking working trees too (an interrupted import or a dropped SEM profile can leave stale
    files there legitimately until sealing).
