- **D-655 (2026-10-22, GUI G3: the keychain helper process; refines D-395's GUI part).**
  - **Why.** `keyring` 25.7's dependency `jaraco.context` imports `urllib.request` (and with it `socket`, `ssl` and
    `http.client`) at module level. The GUI process loads no network module (S11).
  - **What.**
    - `keyring` (MIT; gui/ only, user yes 2026-10-22) is imported only by `agentprov_gui/keychain_helper.py`, run as
      `python -I -m agentprov_gui.keychain_helper` with an environment allowlist.
    - The helper builds an allowlisted back-end directly (macOS Keychain, Windows Credential Locker, Secret Service,
      KWallet; it must be `viable`) and never calls `keyring.get_keyring()`, which would read `keyringrc.cfg`, its
      `keyring-path` sys.path insertion, `PYTHON_KEYRING_BACKEND` and the entry points.
    - For a launch, its `emit` op writes the one key line into a pipe whose read end becomes the `run --env-stdin`
      job's stdin. The GUI process never reads a stored key back.
    - A typed key is registered with the log redaction before it is handed to the helper.
  - **Rejected.** Tolerating `jaraco.context` in S11 (it weakens a static rule for a whole dependency tree); the
    `security` command line (takes the secret in argv when storing); a GUI-held key buffer (the GUI would then hold
    every key).
  - **Class 0.** GUI only. **Tests:** `gui/tests/test_keychain_helper.py`, `gui/tests/test_g3_live.py`.
