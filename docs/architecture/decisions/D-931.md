- **D-931 (2026-10-28, a source profile may raise its `map` jobs' memory cap: `[import] map_rss_bytes`; MCPHunt
  declares 4 GiB; user-approved 2026-10-28 in the wave-2 session, "fix the memory cap so its 1,254 missing traces
  import"; core byte class 0 or 1 by scope, family byte class 1).** The wave-2 import of `mcphunt` · `head` sealed 3 of
  its 35 trace documents whole as `map.adapter_defect` (`worker.limit.rss`), so their 1,254 traces were missing.
  - **Measurement** (read-only, through the queue: the runner's `_job_map_stream` in one process on each failing stored
    object, with the profile's limits and its pinned `hf` origin; sizes and RSS only):
    - `mitigation/minimax_m3_rv1.json` (55 MB, 147 traces, the largest 46.9 MB, a 43.6 MB `result_full`): peak 1,686
      MiB. Phases: `sniff_stream` 33 -> 724 MiB; `parse_stream` to its first item 1,182 MiB; the 46.9 MB trace 1,641 MiB.
    - `main/deepseek_v4_flash.json` (111 MB, 723 traces, the largest 20.5 MB): peak 1,615 MiB.
    - `mitigation/gpt54_m0.json` (43 MB, 384 traces, the largest 25.6 MB): peak 1,322 MiB.
    - The parent's watchdog kills at `cap - margin` (G.4.3). On this host the margin is 163 MiB (the default 4 GiB/s
      allocation rate; D-825 kept it), so the 2 GiB map cap triggers at 1,884 MiB, and these three documents, plus the
      worker's own footprint and frame encoding, cross it. The other 32 documents stay under it.
  - **Decision.** `[import] map_rss_bytes` (an integer from the default map cap to `RSS_CAP_CEILING`, 16 GiB; checked at
    profile load) raises the cap of the source's `map` jobs only. The importer carries it on every map job of the import
    (`Job.limits`, which the pool already honours), and the `--size-hints` admission charge reads a job's own limits.
    `mcphunt` declares 4 GiB, 2.4x the measured worst peak. Every other source keeps the default, so its default
    parallelism is unchanged.
  - **Bytes.** Worker limits enter no digest and no output: a test imports the same logs with and without a cap and
    compares the AER bytes. The core change (`adapters/profiles.py`, `runner/importer.py`, `cli/import_.py`) and the
    `mcphunt` profile value are two commits on two branches, because the mcphunt new-family guard keeps a family branch
    off `runner/`; the family branch rests on the core one. The `mcphunt` profile v2 is recorded by the failed wave-2
    tree `mcphunt-w2.partial` (a scratch record), so it is archived byte-exact (`2c2989b20669…`) and the profile is
    bumped to v3 (D-31).
  - **Rejected.**
    - A raised default map cap for every source (`KIND_RSS_BYTES["map"]`): it halves the default map parallelism of
      every import on small hosts for one source's documents.
    - Reworking the reader's sniff and parse passes to hold less (the sniff holds about 13x the document): a larger
      change of the strict streaming loader for the same outcome, and D-222 already bounds the carve.
    - Raising the watchdog's allocation rate or margin (a host calibration question, D-825), or splitting documents
      (the stored object is the pinned unit).
