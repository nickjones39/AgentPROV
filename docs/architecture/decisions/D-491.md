- **D-491 (2026-10-14, core review B finding CB-16; user decision 2026-10-14: approved, confirmed in the review session;
  build after D-450 lands). The release scan reads unselected archive members for the home path and host name.**
  - **Problem.** `tools/release_scan.py` `path_scan` (R-51, G.9.4) searches stored bytes only, and gitleaks runs at
    `--max-archive-depth 0`. So a home path inside an unselected compressed member of a stored container gets through
    with no finding, for example Inspect `_journal/start.json`, the geminicli zstd tar or the credleak zip. Selected
    members are scanned as their own objects.
  - **Rule.**
    1. Archive objects are recognised by their magic bytes.
    2. Their not-selected members are streamed through the same needle search, reusing D-450's decoded-member scan
       (`corpus/withhold_scan`) in a bounded job with no extraction to disk.
    3. A hit is reported as `<label>#<member index>`, so the fingerprint stays value-free.
    4. An archive that cannot be decoded within the limits is an untriaged `home-path-unscanned` finding, so the scan
       fails closed.
    5. `PATH_SCAN_VERSION` is bumped.
  - **Rejected:** raising gitleaks' archive depth (it has no home-path rule and does not read zstd tars).
  - **Downstream:** none in stored bytes (`tools/`); a release scan of a container corpus may list new findings to
    triage.
