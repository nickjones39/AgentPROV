- **D-990 (2026-10-29, the deposit builder reads a corpus's release-scan document under its own bounded JSON limit,
  1 GiB; user-approved 2026-10-29 in the orchestrator's window, "Yes: build the class-0 fix that raises the deposit
  builder's release-scan document limit"; byte class 0).** The offline build of round 1's part deposits (collection
  layout R1, R7) was refused (`release.refused.scan`, "the release scan is larger than the file limit"):
  `release.builder` read `<corpus>.release-scan.json` with the 64 MiB raw-input JSON limit, and the scans of three
  sealed round-1 corpora are larger (`agentdyn-a` 167 MB, `agentdojo-upstream-head` 134 MB, `adprov-v1-release` 81 MB).
  A scan grows with its findings, so wave-2 corpora would meet the same refusal.
  - **Decision.** As D-935 did for stored PROV documents: `release.builder.RELEASE_SCAN_JSON_BYTES` (1 GiB, about six
    times the largest scan today) and `release_scan_limits()`, which raises only `max_json_bytes` and never lowers a
    caller's limit. The deposit builder parses the scan under it; the strict loader, depth and digit limits stay as they
    are, and raw source input keeps 64 MiB. Test in `tests/unit/release/test_builder.py`.
  - **Other readers of the scan document:** `tools/release_triage.py` (C-3, D-920) reads it without a size limit, so it
    never refused; `release.index` and `release.verify` do not read it; the desktop app's package page checks only that
    it exists. None needed a change.
  - **Rejected:** putting the constant in `ingest.limits` beside D-935's (that module is in the prov and validation
    stage scopes, so the change would be byte class 1 for every corpus); a CLI option for the limit (a release check
    should not be tunable at the terminal); splitting the scan document (a format change for a size limit).
  - **Byte class 0:** `agentprov.release` is in no stage digest scope; no AER, SEM or PROV byte and no corpus manifest
    changes. A deposit built before this change is unaffected (it was refused or under the limit).
