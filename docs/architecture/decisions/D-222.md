- **D-222 (2026-10-21, deferrals: a carve reads its string by byte span; user-approved 2026-10-21; found by phase 10m's
  MCPHunt real-data trial).** A carve of a region of 8 MiB or more (`raw.carve.SPAN_MIN_BYTES`) first goes through
  `agentprov.ingest.jsonspan.string_value_at`. A byte-level walk (strings matched whole, as in `ingest.jsonstream`)
  follows the pointer to the string token. The **envelope**, the region with that token replaced by a placeholder that
  carries the region's own SHA-256, and the token alone are each parsed by `strict_json_loads`, and the pointer must
  resolve to the placeholder in the parsed envelope. The region is valid exactly when both parses succeed, so the strict
  rules are unchanged. Anything the path cannot prove falls back to the whole parse, so the carved bytes and every
  refusal are the same. A `Carver` keeps no parsed copy of such a region.
  - **Why:** `mitigation/minimax_m3_rv1.json` (52.7 MiB) has a 46.9 MB trace with a 43.6 MB `result_full`. Re-parsing
    the trace's byte range while the reader's parsed copy was alive (and keeping it cached) stopped the map job at
    `worker.limit.rss` (2 GiB), so the document sealed as one degenerate AER. On a synthetic document of that shape,
    the carve's traced peak falls from 661 to 165 MiB (ASCII) and from 807 to 406 MiB (with a 4-byte character), and
    the memory kept after it from 99 to 42 MiB and from 214 to 42 MiB.
  - **Byte-neutral:** no locator, origin, AER, PROV or format changes. `ingest/` and `raw/` are in no stage
    `engine_code_sha256`, so no digest moves. Verify and re-map carve through the same function.
  - **Rejected:**
    - a second, streaming JSON parser for carving (a parser differential on untrusted bytes; the strict loader stays
      the only judge);
    - a raised map cap only (it moves the limit; MCPHunt documents reach 110.9 MB);
    - carving an escape-free string's bytes directly (a second validator of JSON string rules, for little gain on
      escape-heavy tool results).
