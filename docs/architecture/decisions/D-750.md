- **D-750 (2026-10-22, G5 desktop bundles for macOS, Windows and Linux; user decisions typed in the orchestrator's
  window, relayed).** The plan is `docs/reports/gui/g5-cross-platform.md`.
  - **Targets and build hosts.**
    - macOS arm64 only (no Intel Macs): built on the development Mac, ad hoc signed (D-657).
    - Linux x86_64 (`ubuntu-22.04`, glibc 2.35 floor), Linux aarch64 (`ubuntu-24.04-arm`) and Windows x86_64
      (`windows-latest`): GitHub runners through one manual-dispatch workflow (`bundles.yml`).
    - Windows ARM64: a Windows ARM runner, if one is available to the repository and PySide6 publishes `win_arm64`
      wheels. Both are checked later, with the user's yes for the lookup. Meanwhile the x86_64 bundle runs under
      Windows 11's x64 emulation.
    - No runner is dispatched while private-repository Actions billing fails: builds start once the repository is
      public or billing is fixed.
  - **Released untested.** A build proves `build_bundle.py`'s build-time checks (layout, excluded Qt modules, Qt as
    separate files, the LGPL texts and notices, on Linux the `xcb` plugin and the glibc floor) plus an automated
    `--smoke` start of the GUI and the preview helper on the runner. Every non-macOS bundle is labelled "not tested on
    a clean machine" in the release notes and the guide. Windows ships unsigned (SmartScreen: More info, then Run
    anyway; this amends design §13's Authenticode line); Linux ships as a `.tar.gz`.
  - **Done before the first release:** P-3 (the job queue refused cleanly on Windows), P-4 (Run Live offers only the
    OS's containment; `dedicated-user` and `vm` labelled declared, not enforced; the record already reads
    `declared_by: "operator"`), P-7 (per-OS bundle checks and packages, tested on fixture trees).
  - **Deferred to the Mac Studio:** P-1 (keychain reason per OS), P-2 (Windows job control: control file by default,
    breakaway fallback), P-5 (Windows long-path warning), P-6 (native-toolbar setting hidden off macOS), the UTM VMs
    and the two-level clean-machine test, which removes the "untested" label. A first implementation of P-1, P-2,
    P-5 and P-6 is held on branch `gui-g5-held`.
  - **The user's own:** the Windows licence and the VM product question, publishing the repository or fixing billing.
  - **Rejected:** building x86_64 targets in emulated VMs on Apple silicon (hours per build, timings meaningless);
    holding every non-macOS bundle until clean-machine testing (the user chose release with the label); Authenticode
    or notarisation purchases.
