- **D-23 (2026-10-11, lone surrogates in source text are handled in the adapter layer, never by a format change; user
  decision, implemented with the regeneration batch).** A lone UTF-16 surrogate in source text (escaped `\ud83d` from a
  truncated emoji, or in an object key) currently makes the whole execution a degenerate `adapter_defect` AER, because
  `aer.canon.encode_value` emits `$utf16` and the typed `text` field rejects it (escaping audit F-01,
  `docs/reports/analysis/research/A4-escaping.md`). No record of the current corpora is affected (0 degenerate units).
  The fix keeps `aer/0.1` frozen: no `$utf16` in typed text fields, no `aer/0.2`. The implementer chooses the best
  approach within these constraints when the batch is built; the preferred design is a shared adapter-layer helper
  that replaces each lone surrogate in text and keys by U+FFFD and discloses it (a D-class rule, e.g.
  `ingest.lone_surrogate_replaced@1`, with the JSON pointer and a reference to the unchanged raw bytes), so nothing is
  lost (the raw store keeps the original) and the execution is mapped instead of degenerate. It is implemented in the
  regeneration batch (`docs/reports/analysis/regen-batch.md`) because the new rule changes a rule catalogue, whose
  digest every PROV document carries.
  - **Why:** a single malformed character should not discard an otherwise observable execution, and a replacement is
    defensible only when it is disclosed and the original stays recoverable.
  - **Rejected:** `aer/0.2` with `$utf16` allowed in text (every AER digest of every corpus changes for a case absent
    from the data); silently dropping or replacing the character (undisclosed loss, invariant 2); a separate catalogue
    cited only when the rule fires (avoids one regeneration but adds machinery for an edge case; reconsider only if the
    batch is otherwise empty).
