  - **Context:** the credleak deposit's tool output holds one named workstation account (account #1; the name is never
    recorded) in `home/<account>/` paths of 313 runs in 67 cells (319 runs in 68 cells counting the bare path). Raw
    pointers: `turns/*/toolCalls/*/output` 382 strings, model-authored `input/command` 38, `input/file_path` 1,
    `assistantResponse` 4. The canary and key rules withhold 176 of the 313 runs (182 of the 319). 137 runs and 18 cells holding the path
    would be released, and the family had no redaction mechanism. D-604 (principle): redact such paths in tool and
    environment output only, keep model-authored text verbatim, withhold raw objects holding the path at object scope,
    and withhold through D-235 an execution whose derived files still hold it.
  - **Decision (built, regen-batch item 138, spec D.19.15):**
    - `adapters/credleak/redact.py` is a family copy of the D-476 grammar (no cross-family import). It reads a closed
      table `[[family.credleak.redact]]` `{id, scope, pattern, replacement, leaf?, note?}` whose one scope is
      `tool_output`: the `output` of a `toolCalls[]` entry, which the mapper copies into the tool result message.
    - The redaction runs on the source value before encoding, so every AER copy is the label: the string, member names,
      the `ext.lex` order lists and pointers, and `$utf16`-wrapped strings. This is the BF-21 property, by construction.
    - Each redacted pointer is tagged `D` and cites `credleak.value_redacted@1` (new, class D) scoped to it.
      `ext.credleak.redacted` lists `{p, rule: "<profile>@<version>#<rule id>"}`, and the info issue
      `credleak.value_redacted` counts the pointers. Source locators keep naming the raw field.
    - The profile rule `account_path` is path-anchored: `home/` or `Users/`, with or without a leading slash, not after a
      name character. A negative look-ahead skips release_scan's `ACCOUNT_ALLOWLIST` names within the name class (29,
      case-insensitive, trailing dots ignored; a test keeps the lists equal) and dots-only names. The name is 1 to 64 name
      characters ending at the first character that cannot be part of a name.
    - The replacement is `acct-{span12}`: the span is the name, and the salt is the profile id.
    - The mapper wires it in (`_Build._call`; the count and issue come in a post-step of `run`). Model-authored text
      (tool-call input, assistant text) and the scripted user message are never rewritten.

  - **Part 1: withholding (built; user decision 2026-10-21: the generic structural rule).** Two object-scope pattern
    rules in `[withhold]`, `account-path-home` (`home/[A-Za-z0-9._]{1,64}[^A-Za-z0-9._\-]`) and `account-path-users`
    (the same after `Users/`), each with `reason = "personal_data"` and its own `public_note`. The table keeps `secret`
    (parse_policy allows a reason per rule).
    - The byte grammar has no alternation or look-around, so the rules cannot exclude generic names. They write nothing
      about the account into Git.
    - The name class leaves out `-`, so the redaction labels `acct-<12 hex>` never match (tested).
    - A raw cell holding such a path is withheld at object scope. A derived file that still holds one holds it in
      model-authored text, because the tool-output copies are redacted, and withholds its execution (D-235).
