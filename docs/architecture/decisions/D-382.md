- **D-382 (2026-10-13: `[import] nested`).** A key of the closed `[import]` table: `[[import.nested]]` entries
  `{id, pattern, under?, note?}` plus raises. Only `max_member_bytes` and `max_ratio` (the nested archive's own member
  gate) and `max_depth` (the deepest level opened at or below it) can be raised. Each raise must be at least the global
  default and at most a fixed constant in `ingest/limits.py`: `NESTED_MAX_DEPTH` 3, `NESTED_MAX_MEMBER_BYTES` 2 GiB,
  `NESTED_MAX_RATIO` 1,000. They are validated at profile load (`nested_raises`, `raw.members.nested_selection`):
  closed keys, unique ids, `under` chains without cycles, F-08 patterns, and each entry's level within its chain's
  allowance. The raises are not `IngestLimits` fields. They travel in `Selection.children`, so `limits_sha256` and
  `corpus.json` `limits` are unchanged. `selection_sha256` gains `children` only when there are any, so every existing
  digest is unchanged. A child's pattern takes precedence over `include`. A tar holds a selected member whole (D-57),
  so a size raise is not honoured under a tar parent (`ingest.archive.size`). `[import] nested` in a profile whose input
  is not an archive is refused at import (exit 5). It stays disjoint from D-323's `[import] limits` allowlist.
  - **Rejected:**
    - raising the global `max_member_bytes` or `max_archive_depth` (the brief: the global limits never change);
    - a load-time check that an include and a nested pattern overlap (glob intersection is not decidable in general;
      precedence is defined instead).
