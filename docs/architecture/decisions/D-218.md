- **D-218 (2026-10-13, deferrals: carved blobs; user-approved 2026-10-13).** A mapper may store a string value of its
  primary artefact as its own raw object (C.11.5): `MapContext.carve(loc, transform)` re-derives the bytes from the
  artefact (`agentprov.raw.carve`: a key locator, the strict bounded loader, transform `utf8` or `base64` for a `data:`
  URI's payload) and returns a `$blob` reference. The map job returns the bytes as members (role `carved`); the parent
  stores them with the object-level origin `carved {from, loc, transform}` before validating the AER, after checking
  that they hash to the header and that `from` is one of the job's primary inputs (else `adapter.carve_mismatch`, a
  failed job). `rawtree`, `withhold` and `derive` treat a carved object as derived, like an archive member; `verify
  --level chain` checks that its source is stored, and a re-map carves it again. No AER schema change; no stored corpus
  moves until a mapper uses it (regen-batch item 29).
  - **Rejected:** taking the bytes from the mapper (an unverifiable claim about the source); re-carving in the parent
    or in `verify --level chain` (parsing untrusted bytes in T0, invariant 3: re-carving stays in the T1 re-map);
    storing the JSON-escaped source span instead of the value (the reference would not be the content).
  - **Addendum (2026-10-14, check-and-hold):** the parent no longer stores carved blobs before validation. It checks and
    holds them (spooled), validates each AER against the store plus the held blobs, and stores exactly those that a
    written AER lists in `seal.blobs`. A unit that falls back to a degenerate AER, a file sealed whole (D-321 refused
    rows, D-323 abort) and a filtered unit leave no carved object. `MapContext.carve` parses each source region once
    per unit (`raw.carve.Carver`). Byte-neutral.
