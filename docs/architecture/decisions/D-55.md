- **D-55 (2026-10-12, phase 12b: a declared, bounded memory cap per job kind; `prov` gets 4 GiB; user decision).**
  `io/workers.py` declares `KIND_RSS_BYTES = {"prov": 4 GiB}`; `WorkerLimits.kind_rss_bytes` carries it and every cap
  (default, per kind) is validated into [64 MiB, 16 GiB]. A job runs under the cap of its kind
  (`WorkerLimits.for_kind`). The default worker count uses the largest cap (`max_rss_bytes`; user choice (a)); a
  defaulted Linux `RLIMIT_AS` is `max(4 GiB, largest cap + 1 GiB)`, an explicit one is kept. The pool's isolation
  record names the caps (`memory_caps`). G.4.3.
  - **Why:** the 2 GiB cap is sized for parsing untrusted bytes (64 MiB × 24); a `prov` job reads a sealed AER and its
    memory grows with run length in tier 4. Measured in real workers on 14 DTap runs chosen by steps, size and the LFS
    objects (`docs/reports/hardening/prov-rss.md`): 0.6–1.4 GiB up to 17 MB of PROV, 1.9–2.5 GiB at 24–30 MB (four runs
    the 2 GiB cap kills), about 80–90 MiB per MB of PROV. 4 GiB covers every measured run that completes today.
  - **User decisions (2026-10-12):** default 4 GiB, ceiling 16 GiB, worker count from the largest cap; a recorded
    per-run override up to the ceiling (CLI flag and its record in the corpus producer block are routed to the
    orchestrator: `cli/` and the importer/`derive` are not phase 12b's).
  - **Not solved by a cap:** PROV-JSON over 64 MiB fails tier 4 at parse (`pv.prov_structure.not_json`; the validator
    loads it with the default `max_json_bytes`), and one over 256 MiB exceeds the per-member output cap
    (`worker.limit.output`; DTap `pii-4`, 1,557 steps). Both are routed (validator owner) with the measurements.
  - **Rejected:** one larger cap for every kind (weakens the containment of parsers); counting workers from the 2 GiB
    default (12 × 4 GiB can exceed a 32 GB host); an unbounded or RAM-relative cap (not declared, host-dependent output).
  - **Effect:** no output byte changes; which executions are registered `worker.limit.rss` changes (fewer).
