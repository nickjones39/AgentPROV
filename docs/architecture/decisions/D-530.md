  - **Addendum (2026-10-22, pre-round review and re-check; fixes requested by the orchestrator, regen item 155).**
    Behaviour changes, each with a regression test:
    - **PR-4 (class 1).** An archive context is checked against its pin (sha256 and size) before it is stored (CB-20). A
      swapped archive is refused (`raw.object.mismatch`), and neither its bytes nor its pinned origin are recorded.
    - **PR-5 and RC-2 (class 0, plus one class-1 hunk).** A re-map leaves out the per-unit inputs that are absent on
      purpose (a context archive, a context-tree file, a pinned LFS object; BF-20, CB-6), and the executions that need
      them are reported unverified (`StoredRawTree.drop_absent`).
      - The corpus-file comparison also accounts the labels of every raw object those executions referenced. The pointer
        of a purged LFS object stays and disposes its sibling judge file by path subject, so `recompute` and
        `verify --level rederive` exit 0.
      - The NF-25 resume check applies to resumes only. A re-map rebuilds its inputs from the source, and may leave out
        those absent on purpose.
    - **PR-8 and RC-5 (class 1; D-529 sample keys).**
      - A pinned object shares its LFS pointer's label, so a sample keys it as `label` + `"\x00pinned"` (labels never
        hold control characters). Its items are `label\x00pinned#<source key>`. Every other candidate keeps its D-529
        key, so a sample of a corpus without pinned objects is unchanged.
      - A pointer with a pinned object yields no execution and never competes in the draw. It passes exactly when its
        object does, so a sampled import writes the full import's rows for its sampled units (MCPHunt multi files,
        DTap).
    - **PR-11 #4 (class 0).** A url context pin resolved from the fetch cache takes `retrieved_at` from the cache's
      acquisition record, as a primary url input does (D-455).
    - **Second re-check (2026-10-22, all class 0, `corpus/`):**
      - **RC-14, RC-16.** The RC-2 mask holds only labels used exclusively by absent-dependent executions, each as its
        JCS string. A change to an input that a verified execution shares is never hidden, and a non-ASCII label
        matches its rows.
      - **RC-13.** A re-map also leaves out the inputs used only by absent-dependent executions. Those executions are
        unverified, as BF-20 has it for an absent primary, and a purged trajectory's judge file is not mapped as a new
        execution.
      - **RC-13.** Corpus files are compared as multisets: a duplicated row counts, the order does not.
      - **RC-13.** A purged context archive's role is recorded in the re-mapped snapshot's `context_skipped` (D-221).
