- **D-234 (2026-10-12, withholding: the source-profile `[withhold]` policy; user-approved 2026-10-13; includes a one-line edit of
  `adapters/profiles.py`, cleared by the orchestrator).** A source profile may declare `[withhold]`:
  - table keys: `reason`, `public_note` (one line, at most 200 characters), and optionally `scan_rules` (release-scan
    rule ids);
  - `[[withhold.rules]]` entries: each has an `id` and either a literal `marker` (4 to 256 characters, a tag such as
    `(token:`, never a secret value) or a bounded `pattern`, plus an optional `scope` (`executions`, the default, or
    `object`) and optional per-rule `reason` and `public_note`.

  At sealing, every stored raw object and every derived file (AER, SEM, PROV, view) of every execution is scanned in
  1 MiB chunks with overlap. A raw hit withholds the object, and with scope `executions` also the executions that cite
  it. A derived hit always withholds that execution and its primary object, because the value came from the raw
  evidence, perhaps in another encoding. Only rule ids are kept, never a match.
  - **Pattern grammar:** atoms (an ASCII literal, escaped punctuation, `\d`, `\w`, `\s`, a character class), each
    with `?`, `{n}` or `{m,n}` (n ≤ 256). There are no groups, alternation, `.`, `*`, `+` or anchors, so every match has
    a known maximum length and matching cannot backtrack badly on untrusted bytes.
  - **Reading the policy:** sealing, `chain` and the deposit builder all read it through `policy_of_profile`, from the
    in-package profile or from its digest-checked copy under `rules/`.
  - **Loader:** `adapters/profiles.py` admits `withhold` in `_TOP_LEVEL`, a one-line cross-folder edit the
    orchestrator cleared. That file is in no `code_sha256`, so no digest moves. It does not validate the table, because
    adapters/ sits below corpus/; `corpus/withhold.py` validates it. No shipped profile declares one yet, so the
    end-to-end tests inject a policy at `policy_of_profile`: the T1 import worker reloads the profile by id from the
    package. The first shipped profile that declares `[withhold]` (expected: Zenodo 22737462, phase-10e rank 5) must
    replace that injection with a real end-to-end test.
  - **Why:** D-146 asks for a canary policy in the profile (as DTap option B). A literal or bounded scan is offline,
    deterministic and testable without gitleaks.
  - **Rejected:** a policy in the corpus spec (it is source knowledge, the same for every corpus of that source);
    unrestricted regular expressions (catastrophic backtracking on hostile bytes; chunk overlap unknown); running
    gitleaks at sealing (`corpus/` runs no subprocess; G.9.4's scan is the backstop).
