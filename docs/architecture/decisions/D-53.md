- **D-53 (2026-10-12, phase 12b: Hugging Face dataset repositories are git pins with their own cache namespace).**
  `raw/fetch.py` `_split_repo` returns `(host, namespace, repo)`. On `huggingface.co` exactly
  `https://huggingface.co/datasets/<owner>/<name>[.git]` is accepted, with namespace `("datasets", <owner>)`, so the
  depth-1 cache is `git/huggingface.co/datasets/<owner>/<name>.git` and the history store and index follow the same path
  (D.16.18 item 13; MN N.1.11 item 5). Every other host keeps the one shape `https://<host>/<owner>/<repo>`.
  - **Why:** the DTap `runs` and `tasks` pins are Hugging Face dataset repositories; without this they could not be
    fetched, seeded or used by `--verify-against-pin`, and `fetch --references` raised on loading the `dtap-bench` profile.
  - **Refused on `huggingface.co`:** `spaces/`, `models/`, a dataset path with fewer or more parts, and a two-part path
    whose owner is `datasets`, `models` or `spaces` (case-insensitive): a model repository `datasets/<x>` would otherwise
    sit beside the dataset directories in the cache.
  - **Rejected:** a host-independent three-part shape (it would admit arbitrary nesting on every host); keying the cache
    by a hash of the URL (the readable layout of N.1.11 item 5 is relied on by the seeding tools and the reports).
  - **Effect:** no AER, SEM or PROV byte changes; `fetch.py` is not an `expand` module, so no `fn_digest` moves.
