- **D-501 (2026-10-14, core review A finding CA-22; user decision 2026-10-14: option 1; held for the regeneration
  round as regen item 86).** Adapter-declared assumptions go on `apv:adapterAssumption`.
  - **Problem.** `apv:assumption` is an `owl:ObjectProperty` with `rdfs:range apv:Assumption`, but E.10 item 11 and D-17
    require adapter-declared assumptions (`<ns>:<Name>`) to be strings, because documents declare no adapter prefixes.
    The vocabulary contradicted the documented output (`repro/CA-22_A3-2`).
  - **Rule.** New `apv:adapterAssumption` (`owl:DatatypeProperty`, `rdfs:range xsd:string`). Core assumptions stay QNames
    on `apv:assumption`. E.1.5 items 3 and 6 and the linkage validator treat the new property like `apv:assumption`. The
    linkage check follows the document's `apv:vocabularyVersion`: a 0.1.0 document keeps the old rule (adapter strings
    on `apv:assumption`), and 0.2.0, absent or unknown versions get the strict rule. A test checks every emitted
    predicate's declared kind and range against its object (`tests/unit/prov/test_vocab_output_consistency.py`).
  - **Rejected:** declaring adapter prefixes and emitting adapter assumptions as QNames (it reverses E.10 item 11 and
    D-17, and needs a stable namespace IRI per adapter); weakening `apv:assumption`'s range (a change of meaning, apv
    1.0.0).
  - **Downstream:** as D-500 (the same bump), for PROV documents with an adapter assumption.
