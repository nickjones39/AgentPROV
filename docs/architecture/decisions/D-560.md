- **D-560 (2026-10-15, phase 10i follow-up; user decision 2026-10-15, relayed by the orchestrator and confirmed by the user in the phase-10i session): archive inputs register the members a profile `exclude` entry matches.**
  - **Problem.** The `expand` selection of an archive input is the profile's include globs only (R-40). A member that an
    `exclude` entry names is therefore a `not_selected` row of `raw/members.jsonl`, and it gets no register entry.
    The snapshot reports `selection_excluded: 0`. Found by the AgentOps-Bench trial: its 3,842 out-of-scope run files
    had no `select.out_of_scope` entries, so D-143/D-191 ("recorded as excluded") held only through the member rows.
  - **Decision.** The runner registers every `not_selected` member that matches an `exclude` entry, with that entry's
    code, owner and note, exactly as for a directory input. The snapshot's `selection_excluded` counts it, and D-191
    holds as written.
  - **Rejected:** accepting the member rows as the record and amending D-191 (it loses the per-file code that tells
    out-of-scope from not-an-execution); selecting excluded members only to register them (it decompresses data that
    is never used, against R-40).
