- **D-810 (2026-10-23, an e-mail detector for the release scan; user-approved with conditions 2026-10-23; design
  `docs/reports/release/release-scan-email-design.md`).** The Zenodo sandbox trial found a fictional benchmark e-mail
  address in a deposit that the release scan did not report: the scan had no e-mail rule.
  - **Decision (as built):**
    - A native path-scan rule `email-address` (stored files and decoded archive members), path-scan version 4 to 5. Findings
      carry no address, local part or domain. The pattern is bounded (fixed repetition counts), so hostile input is matched in
      linear time.
    - Triage is per corpus, not per line. A line is cleared only when every address on it is. (1) RFC 2606 and RFC 6761
      reserved names only (`example.com`, `example.net`, `example.org`, `.example`, `.test`, `.invalid`, `.localhost`; never
      `test.com` or another registered domain): the tool triages them `false-positive`, `basis: reserved`. (2) A **persona
      file** of the corpus's own spec, `[scan] personas = [{path, sha256}]`: `synthetic-benchmark`, `basis: persona`.
      Everything else stays untriaged and stops the builder; `real` still needs withholding; a human triage entry decides
      its fingerprint over a rule.
    - **Digests, not addresses (user condition).** A persona file (`agentprov-personas/0.1`) holds
      `"sha256:" + hex(sha256(address))` of the ASCII lower-cased `local@domain` (nothing else normalised), grouped by the
      upstream file the address appears in, with the source id, repository and pinned commit (or DOI). No address is ever
      written in the repository: it will be public, and some benchmarks' text (AgentHarm) must not be quoted. One shared file
      per benchmark is referenced by path and sha256 from each spec. Sealing copies it to `rules/personas/<name>` (checksummed,
      so in the root digest), refuses one that is missing, differs from the spec's digest, does not parse or is not referenced.
      The spec's digest (`files.spec`) covers the reference, so the list is bound to the sealed manifest.
    - The scan reads the list from the sealed tree (spec checked against `files.spec`, each file against the spec) and records
      `personas.spec_sha256`; the builder refuses a `persona` basis unless it equals the corpus's `files.spec`
      (`release.refused.scan_personas`), a basis that does not fit its triage or rule (`release.refused.scan_basis`), and a
      scan of another path-scan version. The D-236 backstop is unchanged: a `[withhold]` policy naming `email-address`
      accepts only `false-positive` findings of it.
    - **File-name entries (user decision 2026-10-23, no denylist).** A persona-file group `class = "file-name"` lists
      file-name-shaped matches (`icon@2x.png`) by digest; cleared as `false-positive`, `basis: file-name`, only for the
      corpus whose spec names the file, with the builder's spec-digest check as for personas. Used for the four such matches
      of `adprov-v1-release` (2) and `agentdyn-a` (2) (`corpora/personas/<corpus>.file-names.personas.toml`, referenced from
      those specs). A denylist of extensions is rejected: it would hide a real address at a country domain (`.py`, `.md`).
    - **No domain entries** (user condition, revisited after the counts of the helpers): the format has none. A public mail
      provider's address is cleared only by an exact entry.
    - Helpers: `tools/release_scan.py --list-addresses DIR...` (one line per distinct address: digest, domain class, findings,
      corpora, layers; never an address) and `tools/scan_personas.py` (digests against the benchmark's own upstream data,
      offline, git plumbing with `GIT_NO_LAZY_FETCH=1`, run logs excluded; writes the evidence entries; never an address).
  - **Byte class 0, proved:** `corpus/personas.py` (new), `corpus/spec.py`, `corpus/package.py`, `corpus/layout.py`,
    `release/{builder,metadata}.py`, `cli/package.py`, `tools/`, tests and docs; none is in a stage scope. A before/after
    computation of 43 stage digests (`aer` and `adapter_code_sha256` per family, `sem` per family, `prov`, `validation`,
    `compat`) moved none. No stored corpus is touched; no corpus is sealed, so none carries a spec without `[scan]` that
    would need a change.
  - **Triage classes by where an address first appears (user decisions 2026-10-23, built `afd1d731`).** A persona file's
    groups have a `class`: `upstream-data` (in the benchmark's own published files at its pinned commit; upstream run
    outputs, any `runs/`, `results/`, `logs/`, `res/` or `analysis/` directory, are excluded), `benchmark-input` (first
    appearance in benchmark-supplied input of an execution: a user or task message, a tool result, an injection, an
    environment or defence message; evidence: execution id, record id, JSON pointer, actor kind), `model-generated`
    (model output only, other domain: kept, its own triage, never `synthetic-benchmark`, disclosed), `withhold` (model
    output only, at a public mail provider: sealing withholds the executions that hold one, reason `personal_data`,
    ledger `agentprov-withheld/0.4`; `verify --level chain` and the deposit builder re-apply the rule) and `file-name`.
    Observed groups (`benchmark-input`, `model-generated`, `withhold`) name their `corpus_id`, and sealing refuses one of
    another corpus (`package.refused.persona`; owning corpus only). `tools/scan_origins.py` classifies the not-found
    addresses from the AER and writes the observed groups.
  - **Persona files committed (2026-10-28):** `corpora/personas/` (un-ignored in `.gitignore`), five upstream-data files
    per benchmark source, seven `<corpus>.observed` files and the two file-name files; each spec references its own
    (`[scan] personas`). 83 addresses withheld, 187 executions (0.15 %); counts in the design note, sections 10, 12 and 14.
  - **Byte class 0, re-proved 2026-10-28** after merging `afd1d731` (ledger 0.4, `corpus/{withhold,withheld,verify}.py`):
    the 43 stage digests at the branch head equal those of `main` `57b4a4df` (against `1b0a6e9c` only
    `adapter_code:inspect` differs, from `main`'s own commits).
  - **The not-in-AER group (user decision 2026-10-28, built; path-scan version 5 to 6).** The 77 addresses (69 distinct)
    that no AER held sat in no AER or PROV pointer path (design note section 11). (1) 38 were a defect of the rule: a JSON
    escape before an address (`\n`, `\u003c`; doubled in PROV `apv:args`) read as part of its local part. A local part
    right after an odd run of backslashes no longer begins with `n`, `t`, `r`, `b`, `f` or `uXXXX`, after an even run not
    with `n`, `t`, `r` or `uXXXX`; the finding is unchanged and its digest is the decoded address's, which the seal-time
    address rule (same function) now also sees. (2) An archive the decoded scan read is judged by the e-mail rule through
    its members only, not its stored bytes (2 chance matches in compressed `.eval` data). (3) A persona class
    `withhold-object` (evidence: the raw object's sha256; owning corpus only): an address in no AER and only in raw
    objects no execution indexes; the same address rule withholds those objects, no execution is affected. Used for 37
    addresses in 40 not-imported part-c objects of `agentdyn-a`. Regenerated lists: no unclassified address in any
    corpus; withhold unchanged (83 addresses, 187 executions). Class 0 (43 stage digests unchanged against `57b4a4df`).
  - **Datasheet wording (decided 2026-10-28 by the orchestrator on the user's instruction; design note section 13).**
    Four `known_issues` statements: benchmark-scenario addresses (amended: "They belong to the benchmark's scenarios, not
    to anyone the runs involved, and were not checked one by one", the claim kept to the evidence), model-generated
    addresses kept, model-written public-freemail addresses withheld (never for the outcome), and `agentdyn-a`'s
    uncited raw objects withheld. One row per corpus with fixed figures re-counted from each sealed corpus; no `{{v:...}}`
    placeholders (they would change corpus bytes). The rows are added to `corpora/datasheet-statements.toml` at sealing,
    not before. All four pass the card lint.
  - **Rejected:** a denylist of file extensions (a real address at `.py`, `.md`, `.sh`, `.rs`, `.zip` would pass unseen); a blanket allowlist of freemail or fake-looking domains; suffix or pattern rules; triage by local part;
    auto-triage by fixture; one global persona list; addresses in the repository (digests only); recording the matched
    address; a `[scan]` table in the source profile (class 1: `adapters/profiles.py` is in the `aer` closure).
