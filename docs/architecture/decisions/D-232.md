- **D-232 (2026-10-12, withholding: purge to release, P-3; user-approved 2026-10-13).** Every object listed in `raw/tombstones.jsonl`
  is withheld: basis `purge`, with the reason and date from the tombstone. So are the executions that cite it or, for a
  container, one of its members (the set `purge` gave `release.withheld`). An archive that holds a withheld member is
  withheld at object level (basis `container`). Its other members, stored as their own objects, stay. Release-mode
  `chain` accepts a tombstone exactly when `WITHHELD.json` lists the object (counter `tombstoned_withheld`). Otherwise
  it still reports `raw.tombstoned` (tombstoned, failing release mode). A `release.withheld` register entry that no
  tombstone, `withhold` snapshot or profile rule explains refuses the seal (`corpus.withhold.unexplained`, exit 4).
  - **Why:** G.9.5 and H.1.2 already say a purged object is withheld from a new version. The acceptance is tied to
    `WITHHELD.json`, so a forged tombstone over an object that the ledger does not list still fails.
  - **Rejected:** accepting every tombstone in a sealed corpus (it hides a deleted object, the SEC-15 forgery row);
    inferring withholding from the register alone (an unexplained entry would withhold with no recorded cause).
