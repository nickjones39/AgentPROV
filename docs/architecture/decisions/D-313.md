- **D-313 (2026-10-13, RW-1: the issue code is checked against the catalogues the corpus records; layering).**
  `parse_policy` checks an issue rule's form (`<namespace>.<code>`, at most 128 characters) and, when given a lookup,
  that the code is declared. Sealing, `chain` and the deposit builder read the policy through `load_policy`: the
  profile's policy, then `check_issue_codes` against `declared_issue_codes(catalogues)`, where `catalogues` are the
  namespace versions the corpus records (`derivation.json` at sealing, `rule_catalogues` of a sealed manifest). The
  lookup reads the catalogue as package data through `agentprov.aer.rules.load_catalogue` (AD-14), which never imports
  an adapter family (D.2.1). `corpus/` already does the same in `package.py`, `derive.py` and `authority.py`, so
  `corpus/` does not import `adapters/` (M.5.2(1)). An unknown code, a namespace the corpus does not use or an unshipped
  version refuses the seal (`corpus.withhold.policy`, exit 4), fails `chain` (`withheld.policy_invalid`) and refuses the
  deposit (`release.refused.withhold_policy`).
  - **Rejected:** injecting a lookup from the CLI, as `derive.py` gets `Catalogues`: that injection exists for source
    and semantics profiles, which go through the adapter registry; catalogue reads already sit in `corpus/`, and threading a
    callable through `seal`, `verify` and `build_deposit` would add a way to skip the check; validating the code in
    `adapters/profiles.py` at load time: the loader does not validate `[withhold]` (D-234), and `chain` and the builder
    read the digest-checked profile copy under `rules/`, not through the loader; a structural check only: a misspelt
    code would silently select nothing and release every flagged execution.
