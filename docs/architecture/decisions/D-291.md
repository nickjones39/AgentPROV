- **D-291 (2026-10-13, phase 9b: the A9 preflight is decided from the reply; user-approved 2026-10-13).** `run_probe` no longer reads
  "roles accepted" from a 2xx status. `runner.roles_verdict` reads the recorded (redacted) response body of the last
  reply: `accepted` only when the reply follows the instruction that only the system message carries (call
  `get_probe_value` with the key `q7f3-probe`, structured or as text); `refused` on a non-2xx status, a 2xx body with an
  `error` object, or a role refusal in its text; `unconfirmed` for a 2xx that shows neither (the roles may be ignored
  silently; also no choices, `finish_reason: error`, a non-JSON body); `unknown` without a reply. The results carry
  `roles` and `roles_reason`; `roles_accepted` is `roles == "accepted"`. T0 refuses `refused` and `unconfirmed` (exit 4,
  `cli.refused.preflight`, the reason in the message). The probe key changed from `a` (guessable) to a distinctive
  value, so the instrumentation item is now `agentdojo.preflight_probe@2`. Headers never enter the verdict; the
  `wire_headers` note keeps allowlisted values only (tested with cookie, key and organisation headers). Probe sessions
  are never stored, so no corpus byte moves.
