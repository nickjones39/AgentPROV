- **D-964 (2026-10-29, C-8: a corpus spec lists the secret findings a review withholds, by object digest and execution
  id; decided by the orchestrator under the user's delegation of decision 11 of the wave-2 pre-release checks ("can you do
  the secret scan review for me, and i approve your judgement on it"); push pending the user's yes; byte class 0).** The
  decision-11 review of the 2,985 released gitleaks findings with no derivable origin
  (`docs/reports/release/wave-2-pre-release-checks.md`, check 4b) withholds 14 findings and 3 more files in four corpora:
  `atia-benchmark` (a `ghs_` token in 3 primary objects; their executions go too), `openagentsafety` (4 raw objects and 2
  PROV files holding real-looking private keys, and 1 Square-format token), `tacit-agentdojo` (4 uncited raw objects)
  and `agentdyn-b` (3 uncited raw objects holding 4 private keys that are neither placeholders nor in AgentDyn's data). No
  existing cause could withhold them: a profile `[withhold]` rule matches bytes (a marker is a tag, never a secret),
  D-810's persona files cover e-mail addresses only, and purge is a corpus write.
  - **Decision.** The corpus spec gets an optional closed `[withhold]` table: `decided_by`, `objects` (stored raw objects
    as `"sha256:<hex>"`) and `executions` (execution ids). `load_policy` turns it into one rule `secret-withheld` of the
    new kind `object` (reason `secret`, scope `object`), added to the source profile's policy as D-810's `email-withheld`
    is. Sealing withholds each listed object alone (basis `profile_rule`, no execution) and each listed execution with
    its primary object, as a derived-file hit is (D-235); the PROV-file findings are listed by their execution. A listed
    object the corpus does not store, or a listed execution it does not hold, refuses the seal. The rule never scans
    bytes, so the decoded scan and the reason of `unscanned` archives are unchanged. `WITHHELD.json` becomes
    `agentprov-withheld/0.5` exactly when a policy has an object rule (schema `withheld-0.5.schema.json`, generated, equal
    to `/0.4` but for the rule kind). `verify --level chain` (`withheld.listed_released`) and the deposit builder
    (`release.refused.withhold_listed`) refuse a listed object among the released files or a listed execution in the
    index.
  - **Why the spec.** The finding is a fact about one corpus's bytes, found by its release scan, like D-810's
    `withhold-object` digests; the spec is the corpus's reviewed build input, sealed into `rules/` and bound to the root
    digest, so the selection travels with the corpus and `chain` re-checks it offline. Object digests and execution ids
    name files, not values: nothing in the spec or the ledger reveals or narrows a secret.
  - **Bytes (class 0).** `corpus/spec.py`, `corpus/withhold.py`, `corpus/withheld.py`, `corpus/package.py`,
    `corpus/verify.py`, `corpus/layout.py`, `formats.py` and `release/builder.py` are in no stage scope: all 41 stage
    digests are identical before and after. A spec without `[withhold]` gives the same policy (no rule added) and the
    same plan, ledger version and bytes as before, so the 8 sealed round-1 corpora and the wave-2 trees without the table
    are unaffected. Tests: `tests/unit/corpus/test_withhold.py` (`d964`), `tests/unit/release/test_withhold_listed.py`
    (seal, `chain`, deposit backstop, ledger version, schema, spec table).
  - **Rejected.**
    - `agentprov purge` (a tombstone in the working corpus): an irreversible corpus write, against the user's rule
      never to delete data, for files the sealed version only needs to leave out.
    - A profile `[withhold]` marker or pattern for each value: the rule would have to hold the secret (a marker is a
      tag, never a secret), and every affected profile would bump (class 1).
    - Listing value digests, as D-810 does for addresses: a digest of a short or low-entropy credential can be reversed
      by guessing; object digests and execution ids reveal nothing.
    - Withholding whole snapshots (`raw_policy = "withhold"`): it removes every execution of the corpus for a handful of
      files.
