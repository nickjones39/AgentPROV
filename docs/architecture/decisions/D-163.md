- **D-163 (2026-10-12, proposal P-2 implemented: `schemas/**`, `WITHHELD.json` and `views/` are reconciled by `chain`;
  user-approved 2026-10-12).** On a sealed corpus: every `schemas/<name>` present, and the two schemas
  sealing writes (`aer-0.1.schema.json`, `corpus-0.1.schema.json`), must equal the installed package's resource of that
  name byte for byte (`schemas.mismatch`, failed; a name outside the three published schemas is a mismatch; a schema the
  package does not ship is `schemas.unavailable`, unverified). `WITHHELD.json` present but not declared in the
  manifest's `files` is `withheld.undeclared` (a declared one is checked by `manifest.files`). A `views/` file needs a
  `views` stage in `derivation.json` and an index row for its execution (`views.undeclared`). Consequence: a published
  schema is frozen with its version, like the format it describes; changing the bytes of `aer-0.1.schema.json` or
  `corpus-0.1.schema.json` in a later package would make every corpus sealed earlier fail `chain`, so a schema change
  bumps the schema's version (new file name).
  - **Rejected:** recording schema digests in the manifest and comparing against those (it needs a manifest format
    change, and a forger regenerates the manifest anyway; the package is the authority, as for `rules/**`, AD-14);
    reconciling `raw/REFERENCES.json` with `files.references` in the same change (outside P-2; noted for the
    orchestrator).
