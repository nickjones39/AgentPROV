- **D-236 (2026-10-12, withholding: the backstops; user-approved 2026-10-13).** `chain` re-applies the source profile's `[withhold]`
  policy, read from the `rules/` copy, to every released file except `rules/**`, `schemas/**` and `checksums.sha256`.
  A match is `withheld.rule_hit` (failed). Sealing runs `chain` in release mode, so a seal whose withholding missed
  something fails. The deposit builder repeats the rescan (`release.refused.withhold_rule`). It also refuses a
  release-scan finding whose rule the policy's `scan_rules` names unless it is triaged `false-positive`
  (`release.refused.withhold_scan`), so a missed canary never passes as `synthetic-benchmark`. G.9.4's gitleaks scan
  stays the independent backstop.
  - **Further `chain` checks:** `withheld.invalid`, `withheld.present` (withheld bytes or files in the tree),
    `withheld.row`, `withheld.unregistered`, `withheld.unlisted`, `withheld.origins`, `withheld.policy`,
    `withheld.policy_invalid`, plus the schema copy.
  - **Rejected:** trusting `WITHHELD.json.policies` (an absent ledger cannot show that a policy was applied with no
    hits); scanning `rules/` (the profile copy holds the markers themselves).
