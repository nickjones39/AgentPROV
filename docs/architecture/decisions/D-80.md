- **D-80 (2026-10-12, regeneration-batch item 3: how D-24 and D-27 c6 are implemented; implementer's choices within
  the user-approved item).** Spec D.5.4 "Citation of D rules".
  - (a) **Verification is the catalogue `code` list, matched against the profile's `verified_code`.** Each profile
    lists the commits whose code produced its records, with an optional facet selector (`variant`; `transcript` for
    transcript/v1). A D rule is cited at D only where one of its `code` commits applies; otherwise its I twin
    `<id>_unverified@<n>` is cited. This replaces `structural_rule_class`, which governed four rules. A rule that cites
    no code is never verified (D-27 c6). The verified sets follow the phase-10 analysis and examination 2 (R07b):
    `c274885` for `v0.k11`; `a75aba76` + `089ed468` for `v1.k14` (the 0.1.30+ family); for Mandate, also its script
    `fa62a977`; for adprov-v1, `579a908`, plus `c274885` for converted transcripts; none for ROPE, AgentDyn and survey.
  - (b) **Fail closed.** A D rule that resolves to a missing twin raises `RuleNotDeclared` at map time. Two rules are
    declared independent of the producing code: `agentdojo.system_prompt_variant_digest` and
    `rope.security_correction`. 31 twins were added: agentdojo 18, agentdyn 3, rope 3, adprov 7. The adprov 7 include
    `adprov.empty_assistant_text_ambiguous`, the tenth code-less D rule a mapper cites, under the same c6 reasoning.
  - (c) **Classes follow the rules.** After mapping, every record is weakened per C.6.5 rule 1: a field whose
    applicable rule is I is I, and a D record cited unscoped by an I rule is I. A causal `after` edge on a twinned
    `generated_by` link is weakened with it. The weakening never raises a class and does not fire on any pre-change
    AER (checked on all 77 real fixtures).
  - (d) **Seal issues** cite their rule as given, except the issues that report a statement's reading (retry,
    last-pass, run-error), which cite the resolved rule.
  - (e) **Completeness (B6):** a loss issue proves loss (H.3.2(2)) only when its rule is class D, so an inferred retry
    leaves the execution `unverifiable`. `incomplete_run` keeps its D rule: the missing outcome or duration keys are
    observed.
  - (f) **Census and the artefact net** count a twin as its D rule's reading. One adprov entry was added:
    `adprov.art.single_attempt_inferred`.
  - **Why:** one mechanism, machine-checkable (the R07b test over every real fixture), and usable unchanged by the
    phase-10d profiles (`verified_code = []`).
  - **Rejected:** a per-profile list of rules to twin (not checkable against the evidence); keeping
    `structural_rule_class` and adding ternaries per rule (the C6 gap would reopen with every new rule); verifying the
    June-2024-only rules at `089ed468` now to keep head `v1.k14` at D (a research act per rule, not item 3; possible
    later as a code citation and a new rule version); twins for issue-only rules (an issue is not a statement).
  - **Addendum (d) (2026-10-15; regeneration-batch item 103; user decision in the regen-items window, from the corpus
    pre-check's refuted PC-ast-survey-agentdojo-01).** `unexecuted_tool_call` and `missing_tool_result` join the
