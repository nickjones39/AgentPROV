- **D-432 (2026-10-14, GUI design addendum; user request, approved as direction like D-390..D-399).** Three additions
  to `docs/reports/gui/design.md`: (1) Settings › Continuous integration offers three CI targets: local
  (`tools/ci_local.py`, the default), GitHub-hosted (dispatch, and the `CI_ON_PUSH` repository variable), and the Mac
  Studio as a self-hosted runner (`CI_RUNNER`); (2) every PROV-generating form has an on-by-default "W3C PROV conformance
  check" checkbox. Unticking it needs an acknowledged warning and maps to a proposed core option
  `--skip-prov-conformance` (G2c-5) that skips tier 4 only, marks the corpus unvalidated, and blocks sealing and release
  until `validate --corpus` passes; it is never allowed with `--release` or in the regeneration round; (3) Settings ›
  Compute exposes every compute setting: machine preset (`--m5ultra`, `--preset`), per-command `--jobs`, stagger, the
  queue's CPU and memory budgets, the test-gate worker count, and ingest limits read-only.
  - **Rejected:** a GUI-only skip that bypasses the CLI (breaks the CLI-only write rule); allowing the skip in release
    mode; editable ingest limits in the GUI (they are part of a corpus's recorded identity, so they stay profile edits).
  - **Amended 2026-10-15 (user decision):** `validate --corpus` stays read-only and does not clear the mark. Only a full
    `recompute --corpus OLD --out NEW --stages sem,prov,validation` produces an unmarked corpus, never in place. A
    derive never carries a skipped validation layer (`version_mismatch`). The GUI's "Revalidate (full recompute)…"
    action runs that recompute (design §8.3a, fe399912).
