- **D-312 (2026-10-13, RW-1: `agentprov-withheld/0.2`; part of the design the user chose with D-311).** The frozen
  `withheld-0.1` schema (D-163) lists rule kinds as `marker | pattern`, so a ledger that records an issue rule needs a
  new version. `agentprov-withheld/0.2` is `/0.1` with `issue` added to `policies[].rules[].kind`; nothing else differs
  (`$id`, title and format constant aside). The version is a function of the content: a document is `/0.2` exactly when a
  policy has an issue rule, the reader refuses either version that disagrees, and a sealed corpus holds the schema copy
  of its version (`schemas/withheld-0.2.schema.json`, new in `SCHEMA_FILES` and `CORPUS_LAYER_FORMATS`). The `/0.1`
  schema file still regenerates byte for byte from the code.
  - **No existing corpus byte changes:** sealing one working corpus with origin/main's code and with this build gives
    identical trees and sidecars, without a policy (35 files) and with a pattern-only policy (40 files, `WITHHELD.json`
    included). No AER, SEM, PROV or validation digest moves (sealing only); `recompute --check` is unaffected; shipped
    `[withhold]` profiles (credleak-p15b on phase-10k-credleak: marker and pattern rules only) seal as before.
  - **Rejected:** editing the `/0.1` schema in place (D-163); writing `/0.2` for every ledger (it would move the bytes of
    every corpus that withholds, with no new information); leaving issue rules out of `policies` (the ledger would no
    longer name the policy applied, D-230).
