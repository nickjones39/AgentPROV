- **D-395 (2026-10-14, core + GUI: API keys; approved as direction 2026-10-14 by the user, relayed by the orchestrator session; build after the regeneration round).**
  - **Storage:** API keys live only in the OS keychain through `keyring`.
    - Back-ends are restricted to an allowlist: macOS Keychain, Windows Credential Locker, Secret Service and KWallet.
    - `keyrings.alt`, `fail`, `null` and chainers containing them are refused, and the back-end is checked after
      loading.
    - Without an allowed back-end, real-model runs from the GUI are disabled.
  - **Entry:** keys are entered once in Settings and never shown again.
  - **Hand-off (core):** a new `run --env-stdin` reads one strict JSON object (≤ 64 KiB) from stdin before any other step.
    - It uses the same name allowlist as `endpoints.toml`.
    - It is exclusive with `--env-file`, and **it disables the default `<repo>/.env` read**.
    - The existing path then forwards only the selected key into the T2 worker environment, and registers it for
      redaction.
  - **Never:** on disk, in argv, in the T0 environment, in `job.json`, QSettings or logs. The GUI never reads `.env`.
  - **Rejected:**
    - a temporary `.env` (plain text on disk);
    - keys in the T0 environment (readable by same-user processes) or in argv;
    - QSettings;
    - an encrypted file with a master password (re-implements a keychain).
