- **D-15 (2026-10-08, unpinned `--input` is refused in v0.1; user delegated the choice, implementation ruling).**
  `agentprov import --input` requires `--verify-against-pin` (or the pin is read with `--fetch`); otherwise exit 4,
  `raw.origin.local`. MN N.2.2 is amended: its "local origin with a notice" path is withdrawn for v0.1.
  - **Why:** every corpus claim rests on re-verifiable origins (git blob id or listing digest against a pin); a `local`
    origin names only "a file on this machine", and release mode already refuses a corpus carrying one (HL origin
    table), so an unpinned working corpus could never be sealed: refusing at the door is the honest behaviour. Every
    registered source has a pin, so a pinned path always exists. Supporting `local` would need a mode-dependent AER
    writer, new core behaviour straight after the freeze, for no v0.1 use case.
  - **Where unpinned data goes instead:** a new source gets a profile with pins (an adapter's job); AgentPROV's own runs
    are live capture (phase 8), whose `capture` origin is self-recording.
  - **Rejected:** a mode-dependent writer accepting `local` in dev mode (unsealable corpora, core change);
    accepting unpinned files silently (unverifiable evidence). Revisitable as an explicit, documented
    `--allow-unpinned` dev flag if a real need appears.
