- **D-962 (2026-10-29, `scan_origins` classifies what the release scan finds; user-approved 2026-10-29 in the wave-2
  pre-release-checks session, the recommended class-0 tool fix; byte class 0, tools only).** The wave-2 D-810 pass left
  130 addresses in 13 corpora without a class: the release scan finds them in released files, but `tools/scan_origins.py`
  found no AER string that holds them, and they were not in uncited raw objects only, so the observed persona files did not
  list them and they would stay untriaged `email-address` findings. Two causes, by value-blind features:
  - **The byte boundary.** The release scan reads stored bytes and `scan_origins` read decoded strings. `find_addresses`
    reads a backslash run before an address as a JSON escape; an odd run (decoded text) and an even run (stored bytes,
    where each backslash is doubled) treat the letters `b` and `f` differently, so the two readings can yield different
    local parts. In every AER occurrence of these addresses the match starts right after a backslash, and the decoded
    text does not hold the byte reader's digest.
  - **Raw-only addresses in cited objects.** The rest occur only in raw objects that an execution cites but that the
    mapper does not read them from (supporting files, unmapped parts of a log). D-810's `withhold-object` class required
    the objects to be uncited.
  - **Decision.** `first_appearances` also reads each AER line's bytes: an address found there and in none of the
    record's decoded strings is attributed to that record, pointer `""` (the whole record), with the record's origin. A
    `tool_execution`'s bytes cannot tell arguments from output, so such an address takes `model` (it withholds more,
    never less). An address found only in raw objects is `withhold-object` whether an execution cites them or not; under
    D-961 its objects are withheld alone and the executions stay. Its evidence names an uncited object when there is
    one. The report row `not-in-aer|uncited-raw` is now `not-in-aer|raw-only`.
  - **Bytes (class 0).** `tools/` is in no stage scope. The persona files are data: each changed observed file is a
    reviewed spec amendment (its sha256 in the spec). Tests: a byte-only address takes its record's origin (fails
    without the byte pass); a raw-only address in a cited object is `withhold-object`.
  - **Rejected.**
    - Reading decoded strings in the release scan instead: the scan's byte reading is what the sealed release is
      checked by (D-491, D-810), and it must see what any reader of the stored bytes sees.
    - Leaving the 130 for a person to triage at the deposit: anything withheld must be decided before sealing, since a
      sealed corpus is never rewritten.
    - A new persona class for raw-only addresses in cited objects: `withhold-object` under D-961 already gives the
      narrowest outcome (the holding object alone).
