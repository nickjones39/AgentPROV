- **D-17 (2026-10-08, the published apv 0.1.0 gains no term in phase 7; implementation ruling).** The assessment rule
  `aprov.a_payload@1` needs an `apv:assumption` on an `ambiguous` injection-marker claim (EF E.7.3). It takes it from
  the SEM profile's catalogue: the marker rule or normaliser the annotation cites must declare one (for
  `agentdojo.suites@1`: `agentdojo:NormaliserRejectionIsContainment`, on `agentdojo.injection_marker_ambiguous@1`), and
  an ambiguous marker whose rules declare none is refused (`prov.sem_invalid`). The phase-7 engine's first cut added a
  core individual `apv:UndecodedMarkerMatch`; it was reverted.
  - **Why:** apv 0.1.0 is published (`nickjones39/agentprov-ns`, w3id PR #6836), and E.4.6 allows term additions only
    in a minor version. A 0.2.0 would change `apv:vocabularyVersion` in every document (every PROV digest) and needs a
    republish with the user's consent, for a term whose meaning is profile-specific anyway (which normaliser rejected
    what). Adapter-declared assumptions are already strings in PROV (EF E.10 item 11).
  - **Rejected:** editing 0.1.0 in place (E.4.6 forbids it; published IRIs would change meaning); bumping to 0.2.0
    now (every digest changes for one term); emitting the ambiguous claim without an assumption (E.7.3 requires one).
