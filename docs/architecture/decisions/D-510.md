- **D-510 (2026-10-14, phase 10q for phase 10j's R-10j-1: workstation account paths in directory names; user decision
  2026-10-14: approved, option (A)).** When a source names directories after an account-bearing string, as
  EnvironmentOptim does (`runs/<arm>/_ceph_ssd_students_<account>_qwen3_5…/`, 6,016 logs), that string also reaches the
  AER's `artifacts[].origin.path` and, from it, PROV's `apv:originPath`.
  - **AER and PROV.** The shared redaction (D-476) replaces the observed `pipeline_name` wherever the AER holds it:
    inside the origin path, in `ext` copies and in JSON-Pointer-escaped forms. PROV is therefore clean; SEM holds no
    path. This needs no new scope while the directory equals the logged `pipeline_name` byte for byte; a `path_segment`
    scope is added only if a source differs.
  - **Why resolution stays sound.**
    - Every tier resolves raw by sha256.
    - `o` locators resolve into the AER's own origin.
    - `verify --level chain` compares digests and origin counts, never the AER path.
    - A re-map re-applies the same pure, salted redaction to the raw path from `raw/origins.jsonl`, so it is
      byte-identical.
  - **Raw-level descriptors ship as they are (D-186 (c)).** `raw/origins.jsonl`, register path subjects and
    `WITHHELD.json` origins describe the raw object and repeat the path that is public at the pin. `executions.jsonl`
    and execution ids hold no path.
  - **Identity.** The TraceLogger build reads the layout facet from the raw path and calls `redact_value` on it before
    `identity.resolve`. Identity rows are keyed by the redacted label, so no account enters Git; the leaf is kept for
    the D-254 rows.
  - **Census path lint (approved; built by the regen-items session on the import path, generic across families where
    feasible).** Every selected origin path is scanned for account-path structure. An import whose matches no declared
    redaction rule covers is held or refused (fail closed). Only counts are reported.
  - Design: `docs/reports/phase10q/d510-directory-account-paths.md`.
  - **Rejected:**
    - (B) redacting the raw-level descriptors with a private mapping: `verify --against-pins` and the re-map read the
      raw paths, the mapping would be unverifiable, and it contradicts D-186 (c);
    - (C) holding the 6,016 logs (keeps them out of every corpus).
  - **Downstream:** no stored corpus moves. The 6,016 logs are held as `select.redaction_pending` until the wiring
    lands. The agentdojo `adapter_code_sha256` moves with the wiring.
  - **Addendum (regeneration-batch items 105, 106, 108; user decision 2026-10-21: release logs, keep D-510).** The wiring
    and the lint are built, and the 6,016 logs map. The derived label is `_cluster_home_{span12}_{leaf}`, which drops the
    raw directory's cluster prefix.
    - **D-604 does not apply here.** D-604 withholds raw objects that hold a third-party account path. Here the account
      is in the git path itself, which `raw/origins.jsonl`, `WITHHELD.json` and the register keep. Withholding the logs
      would lose primary data and still ship the account; a seal test confirmed that the chain backstop then refuses.
    - So the raw logs and their pinned paths ship as published (D-186 (c)). The datasheet discloses this (row 21,
      statement `environmentoptim-raw-paths-account-segment`).
    - **Rejected:**
      - withholding while exempting the descriptors (the account still ships);
      - redacting the descriptor paths (option (B) above).
