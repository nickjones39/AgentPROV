- **D-702 (2026-10-22, `agentprov keys` and `run --keychain`; part of D-700; user decision 2026-10-22: keyring becomes a
  core dependency).**
  - **What.**
    - `keyring` 25.7 joins the core's dependencies. It is locked offline from the uv cache (no download) and imported
      only by `agentprov/keys/helper.py` (M.5.3 row; a boundary test).
    - The helper is D-655's, moved from the GUI. It runs in a separate `python -I` process and constructs an
      allowlisted back-end directly (never `keyring.get_keyring()`). Its JSON protocol has the ops status, has, set,
      delete and emit.
    - `agentprov.keys` is its client.
    - `agentprov keys status|list|set|delete`:
      - only key variables `endpoints.toml` declares;
      - `list` shows names and presence only;
      - `set` reads the value from a no-echo prompt or `--stdin`, never argv, and registers it with the redaction first;
      - `delete` needs `--yes` when not interactive.
      - Without an allowed back-end: exit 4.
    - `run --keychain` reads the selected endpoint's key through the helper into the CLI process, which registers it
      for redaction at once. It is exclusive with `--env-file` and `--env-stdin`, and refused for a scripted run.
  - **GUI.** The GUI's own helper and keyring dependency are gone. Settings › Keys calls `agentprov keys`, and Run live
    passes `--keychain`, so the GUI never holds a stored key, not even in a pipe it opens.
  - **Rejected:** keeping keys GUI-only (the CLI could not manage them); `run` reading `keyring` in its own process
    (`jaraco.context` loads `urllib.request` into T0); keys in argv or the settings file.
  - **Class 0.** `keys/` and `cli/` are outside every stage closure.
  - **Tests:** `tests/cli/test_keys_cmd.py` (stub helper: names only, stdin only, refusals, `run --keychain` into the
    worker environment, exclusivity); `tests/cli/test_keys_helper.py` (the helper's protocol and import rules);
    `tests/boundary`.
