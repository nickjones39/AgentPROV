- **D-13 (2026-10-08, the engine agent is version-free; user delegated the choice, implementation ruling).** PROV
  documents name the AgentPROV engine `sw:agentprov`, with `apv:softwareName` but no version. The software version
  and code digest of each run are recorded once per corpus in `derivation.json` (H.8.2: `engine`,
  `engine_code_sha256`). Adapters keep `sw:<adapter-id>.<version>`, because the adapter version is in the AER header
  and therefore an input of `derive`.
  - **Why:** E.3.4 item 3 and E.9 require byte-identical PROV-JSON for fixed AER, spec, catalogue and options. A
    version in the document would change every digest at every release, even one that changes no semantics, so
    `recompute --check` could never pass across releases.
  - **Rejected:**
    - keeping `sw:agentprov.<version>`: every patch release becomes a recompute failure;
    - putting the software version into `dk`: every release mints new bundle IRIs, contradicting E.3.4 item 3;
    - naming the engine by spec version (`sw:agentprov.agentprov-prov-0.1`): redundant with the derive activity's plan
      `rules:agentprov-prov.0.1`.
