- **D-706 (2026-10-22, the Viewer's task and outcome columns and their CLI selectors; part of D-700; user request
  relayed by the local-endpoints session).**
  - **What the user asked.** Sort and filter a corpus's traces by suite, user task, attack, injection task, defence,
    model, utility and attack success; open a row's JSON and its rendered graph; highlight the rows whose attack
    succeeded, with a glyph as well as a tint (not colour alone), and nothing highlighted on an unknown or benign row.
  - **The rule for "attack succeeded".** An `outcome` element of the index row whose SEM claim is `attack_succeeded`
    holds (`holds: true`). The AgentDojo SEM profile gives that claim only on an attacked cell (`task.attack_id` a
    string) and only for a checker's result, never a harness default; a benign cell has no such element, so it reads
    "not judged" even when its raw security judgement is true. The GUI takes this from the row and computes nothing of
    its own. `utility` is the same rule with the claim `user_task_solved`.
  - **CLI selectors** (`agentprov stats --select`, `agentprov.api.iter_executions(select=…)`), so every Viewer filter
    is a CLI selection:
    - `cell.<member>`: a known H.7.4 cell member (`suite`, `task_id`, `attack_id`, `attack_target_id`, `defense_id`,
      `model`, `repeat`, …); an unknown member (`$unk`) never matches;
    - `outcome.<claim>=true|false|none`: an element with that claim holds, does not hold, or none has a `holds`;
    - `issue=<code>`: any of the row's issue codes.
    Working rows carry no cell or facets and match none of these (not even `none`). Class 0: `stats/` and `cli/` are
    outside every stage closure; no stored byte changes.
  - **The Viewer** (`gui/`): the columns suite, task, attack, injection task, defence, attack succeeded, utility,
    judgements and repeat; pickers for suite, attack, injection task, defence, model, utility and attack succeeded (yes,
    no, not judged); the `agentprov stats --select` line of the current filter with Copy CLI; the attack-succeeded rows
    tinted (theme- and contrast-aware) and marked with ⚑ plus "yes"; an Index Row tab; Export Graph… opens the
    `agentprov render --ex` job form. A working corpus shows a derive hint. The row readers live in
    `agentprov.corpus.rowvalues` (standard library only), which the GUI allowlist (D-391) now includes, so the GUI and
    `stats` share one implementation; a test checks that each filter selects exactly what its CLI selection selects.
  - **Rejected:** deriving "attack succeeded" in the GUI from the raw `security` judgement (it is true on the benign
    golden row, so it would highlight a benign trace); a GUI-only filter language (D-700: one implementation).
