- **D-623 (2026-10-22, ultrareview area "pipeline" fixes; `~/.agentprov/review/pipeline.findings.json`; user decision
  2026-10-22: fix every serious finding before the round, relayed by the orchestrator; regen item 159; branch
  `integration-fix-ultra-cli`).**
  - **#1, size guard on every read path.** `GitPinTree` takes the import's limits. A blob whose tree-entry size, or
    whose read length, is over `max_artefact_bytes` is that candidate's `ingest.size.file` and is never fetched or
    stored. A D.16.14 R3 pinned object is read no further than the limit (`read_pinned`). Before, one such file aborted
    the whole import, and D-610 then marked it interrupted.
  - **#2, a skipped tier 4 with no semantics profile.** No check beyond the AER validator fails a unit only when tier
    4 should have run. With `--skip-prov-conformance` and no tier-3 profile, nothing is left to check. This applies in
    the importer and in `derive`/`recompute`. Before, every execution failed with an empty `validate.failed` row.
  - **#3, the `aer` stage's `rules`.** When the stages are written (import and live), the recorded `aer` stage of the
    same function (`_AER_IDENTITY`) keeps the namespaces of the earlier runs: `rules` and `rules_sha256` are the
    union, and `fn_digest` follows. Before, a resume that sealed no unit declaring a namespace dropped it, and a later
    recompute saw an `aer` stage change.
  - **#4, `until`.** The manifest's `selection.until` is the furthest stage the corpus holds (the maximum of the
    recorded value and the run's). `_until_of` reads the furthest of it, the recorded SEM/PROV/validation layers, and
    `aer` when the index holds an execution, which also covers manifests written before. Before, a later `--until raw`
    run lowered it, and a re-map then mapped nothing.
  - **#5, release mode.** A release-mode import records `mode: "release"` in its `aer` stage (only then, so a dev-mode
    stage is byte-identical). `_mode_of` reads it next to the validation stage's. G4 compares it, so a dev run of a
    release corpus is refused. Before, a `--release --until aer|sem|prov` corpus was re-mapped and re-derived in dev
    mode.
  - **#6, derive's present-layer check** passes `prov_conformance`. A skipped-tier-4 validation layer then matches a run
    under the same setting, and `derive --skip-prov-conformance --views ...` is no longer refused.
  - **Schema.** The `agentprov-corpus/0.2` derivation schema allows the optional `aer.mode: "release"`
    (`corpus/manifest.py`, regenerated `schemas/corpus-0.2.schema.json`). The released `agentprov-corpus/0.1` schema is
    byte-identical. A corpus/0.1 corpus is never written by this build.
  - **Nit, live staging:** `stage_objects` refuses (`ingest.size.file`) a staged file that grew past
    `max_artefact_bytes` after `open_evidence`'s size check, instead of storing a truncated prefix.
