- **D-780 (2026-10-23, the building commit is recorded in every manifest a writer produces; user-approved 2026-10-23
  with the answers below; design `docs/reports/release/build-commit-design.md`).** After a change to a stage's code a
  corpus reproduces only at its building commit (D-430, regeneration finding F-8), but only the sealed manifest records a
  commit, and that one is the sealing commit (H.2.7). The round attributed its corpora by matching code digests.
  - **Decision:**
    - A working manifest's `producer` records `git_commit` and `git_tree_clean`, or `git_commit_absent_reason`
      (`not_a_source_checkout`, `git_unavailable`, `git_failed`) when the code is not a git checkout. Never a placeholder.
    - It also records an ordered `build_steps` list: `{agentprov_version, command, stages, commit facts}`, where an absent
      reason comes with the installed-distributions digest. `derive` and `recompute --out` carry the source's steps and
      append their own, so no commit is lost.
    - `stages` is only what that process wrote (the writer's own record for an import or live run; the stages a
      derivation recomputes, not the layers it copies), by the names of `derivation.json`, sorted, so the bytes stay
      deterministic. A derive that rebuilds only PROV shows that AER and SEM come from the earlier step.
    - A sealed manifest keeps its sealing `git_commit` (H.2.7 unchanged) and gains the optional `producer.build_steps`
      copy. Sealing is not a build step.
    - The commit is computed once per process in the CLI layer (`cli/gitinfo.py`) from the agentprov source root, never
      the cwd, only when git's top level is that root (a venv inside a project no longer reports the project's HEAD;
      sealing too), with every `GIT_*` variable of the caller removed. It is injected through
      `CorpusWriter(build_step=...)`, which merges it when it writes the manifest. No environment override.
  - **Format change, amended in place (user answer 1):** `agentprov-corpus/0.2` gains `producer.build_steps`, additive and
    optional: a manifest built without the key validates unchanged (tested). Checked before building (read-only, only
    the `sealed` and `release.status` fields): **33 kept corpora under `~/.agentprov/corpora`, 0 sealed, and no deposit
    draft exists**. No sealed or deposited artefact carries the 0.2 schema, so changing its bytes breaks nothing and is
    consistent with D-31 and the D-224 precedent; D-163 (a published schema's bytes are frozen) is not engaged. The
    schema pin in `tests/unit/test_format_freeze.py` moves. `agentprov-corpus/0.1` stays frozen and has no such key.
  - **Release-mode `package` (user answer 2):**
    - It refuses a dirty build step (`package.refused.build_dirty`, exit 4): the commit would not describe the code that
      ran.
    - It does not refuse an absent reason (a build from an installed wheel); the datasheet shows the reason with the
      version and the distributions digest.
    - It does not refuse a corpus with no steps (built before this, the 8 round corpora included); the datasheet says
      "building commit not recorded". This rule is revisited when the attestation question is decided.
  - **Byte class: 0, proved.** No file of any stage scope is edited (the writer hook keeps the importer and the session
    out: `adapters/runner` is in `AER_SEEDS`). A before/after computation against `53306617` of 43 digests (`aer` per
    family, `adapter_code_sha256` per family, `sem` per family, `prov`, `validation`, `compat`) moved none; no AER, SEM or
    PROV byte changes and no stored corpus is touched. `corpus.json` of a corpus built after this lands differs, and
    so does the datasheet and the content digest of a sealed one.
  - **Comparisons:** `producer` metadata is never a drift finding. `tools/regen/tree_compare.py` allows the producer
    pointers by default; `recompute --dry-run`, `verify --level rederive`, the golden fixtures and the gates do not
    compare `corpus.json`. A drift report and a drift refusal print the source's building commits.
  - **Not built, proposed (user answer 4):** `package --built-at <commit>`, an attestation for corpora that lack a
    commit (see the design note, section 7). It is decided later, together with Option B
    (`docs/reports/regeneration/option-b-deferred.md`): if the round is re-run every corpus records its commit and the
    attestation is not needed; if the current corpora are kept it gets its own branch.
  - **Rejected:**
    - an environment-variable override (a way to inject a commit into a real run);
    - editing `importer.py` or `session.py` (in `AER_SEEDS`: class 1, moves every family's AER digest);
    - the commit in `derivation.json` stage entries (breaks the reuse comparison, D-30);
    - overwriting the base producer on derive (loses the import commit);
    - a placeholder commit (invariant 7);
    - finding the commit by digest search at read time (ambiguous; what the round had to do);
    - computing it in `corpus/` (no subprocess there);
    - stages inferred from the carried layers (a derive copies SEM and PROV through the writer; only its plan says what it
      recomputed);
    - a new corpus format version `corpus-0.3` (nothing sealed carries 0.2, so nothing needs protecting).
