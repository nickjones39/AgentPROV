- **D-14 (2026-10-08, the phase-6 freeze of `aer/0.1` and `capture/0.1`; AD-06 executed).** Three importers were built
  against the formats before they froze: the Inspect `.eval` importer (D.9; 6 survey AgentHarm logs, 1,056 samples),
  the AgentDojo TraceLogger `v0.k11` importer (D.6; all 18,241 pinned logs at `c274885`, full gate R passing) and the
  FooBench future-framework adapter (D.12). None needed a new record kind, field or enum value. Two core changes were
  made before the freeze, both corrections recorded in C.20: cached agent calls answer the agent in
  `aer.acc.agent_calls_vs_assistant@1`, and adapter families are discovered by convention instead of from core name
  tables. `capture/0.1` gained its published schema (C.13.9). From this date the published schemas, the 13 record
  kinds and the closed enums are pinned by `tests/unit/test_format_freeze.py` (`versions.FROZEN`).
  - **Rule:** any change to a frozen format is a new version (`aer/0.2`, `capture/0.2`) with its own schema file,
    reader support for both, a DECISIONS entry and an AGENTS.md record (D.12.4); a pin is never updated in place.
    Seal issue codes (`CORE_ISSUE_CODES`) stay validator vocabulary and are not pinned.
  - **Rejected:** freezing before the three importers landed (the FooBench test found two core name tables that would
    have forced a core edit per framework, and the Inspect fixtures found the cached-call accounting gap); and freezing
    the validator's issue vocabulary with the record grammar (it would turn every new diagnostic into a format bump).
