- **D-100 (2026-10-12, phase 10d: how the AgentDojo-format sources are trial-imported; user-approved recommendations).**
  Each source gets a profile, a `planned` registry part (D.3.2: `planned` until a recorded full import) and one corpus of
  its own (D-94). Trial imports run offline into scratch corpora only, never `~/.agentprov/corpora/`: the pinned commit,
  its trees and the blobs the phase-10c staging clone holds are packed into a scratch fetch cache with lazy fetch and
  https blocked (`tools/agentdojo/phase10d_trial.py seed`); the listing is the product's `Fetcher.git_tree` over the
  largest pathspecs without an absent blob (absent blobs are figures and documents, never logs); the import is
  `import_source` with the pinned git tree in release mode through validation, bypassing only the CLI status gate; it is
  run twice with different worker counts from a snapshot worktree and the corpora are compared byte for byte.
  - **Why:** the full imports wait for the regeneration round; the trial must not touch shared stores or the network.
  - **Rejected:** `tools/seed_git_cache.py` (its fetch could lazily fetch absent blobs over the network; routing R2);
    `--input` over the staging worktrees (checkout filters could change bytes; the git tree is the pinned evidence).
