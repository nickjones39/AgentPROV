- **D-827 (2026-10-28, an optional key for a local endpoint: `OMLX_API_KEY`; user decision Q1 (b) of the Mac Studio
  calibration design note, confirmed in the calibration session's window).**
  - **Finding.** The oMLX server on the Mac Studio (`127.0.0.1:8000`) is set up with an API key. It answers
    `GET /v1/models` with HTTP 401, so `agentprov models --endpoint omlx` exited 3 (`run.local.bad_listing`) and no
    oMLX run could start. The `omlx` entry named no key variable, because local entries were keyless (D-690).
  - **Registry.** `api_key_env` is optional on a `local` entry (`endpoints.py` already parsed it; only the docstring
    said "needs no key"). `omlx` names `OMLX_API_KEY`. The other local entries stay keyless. A non-local entry still
    must name one.
  - **Sources.** As for every key (D-702 as amended): the OS keychain first, then `.env`; or only the source that
    `--keychain`, `--env-file` or `--env-stdin` names. For a local entry, a missing key is **never an error** in any
    mode (a notice): the server is asked without a key, as before.
  - **Where it is sent.** As `Authorization: Bearer`, only to the loopback server, and only after the peer check:
    `agentprov models` (listing and identity), the `run` preflight (D-691), the per-cell re-observation (A14) and the
    worker's model calls (the worker already sent `agent.api_key_env`'s value; the backend needs no change).
  - **LAN.** A key is never sent to a LAN address (D-698): `LoopbackClient` refuses it (`run.local.lan_key`, exit 4),
    and `run` refuses a set key with a LAN base URL (`cli.refused.lan_key`, exit 4). This matches the worker's existing
    rule ("a LAN endpoint is keyless").
  - **Configuration digest.** When the key is not set, the agent's `api_key_env` is `null`, so the digest is that of a
    keyless run before D-827. When it is set, the digest names the variable (never the value). No oMLX corpus exists
    yet.
  - **Errors.** A listing refused with HTTP 401 or 403 is `run.local.unauthorized` (exit 3). Its message names the
    variable and how to store it, or says the endpoint has no key setting. A wrong key is reported as "not accepted",
    never shown.
  - **GUI.**
    - Settings › Keys lists `OMLX_API_KEY` ("omlx (optional, local)"), stored through the same keychain helper.
    - Run Live shows the key as optional for a local endpoint, and a missing optional key never blocks Start.
    - The model picker and the identity record pass `--keychain` for a keyed local endpoint, so the CLI reads the
      keychain and never `.env` (the GUI's rule).
    - Real runs already pass `--keychain`.
  - **Addendum (same day, requested by the oMLX dev-test session through the orchestrator):** `omlx` also names
    `model_env = "OMLX_MODEL"`, the served model id when `--model-id` is not given (`_real_agent` already reads
    `model_env`). It is oMLX's own id (for example `Qwen3.5-4B-MLX-4bit`), not a Hugging Face repo id. `--keychain`
    reads only the key, so `OMLX_MODEL` comes from `.env`, `--env-file` or `--env-stdin`.
  - **`.env.example`.** Sessions cannot edit it (deny rule), so the user adds the line given in the calibration
    report.
  - **Class 0 for corpus bytes.** No AER, SEM, PROV, validation or views code moves. `capture/` and `cli/` are in no
    stage digest. However, `endpoints.toml` and `endpoints.py` are capture-package bytes, so **every backend
    environment's identity changes**, and the orchestrator rebuilds the four environments after the head lands.
  - **Rejected:**
    - turning oMLX's key off. The user chose to keep it.
    - a `--api-key` flag. A key value on the command line is visible in the process list and shell history (D-702).
    - sending the key to every local server. A key belongs to the endpoint that names it.
  - **Tests:**
    - `tests/cli/test_local_endpoint_key.py`: the stub server with a required key; registry, header, unauthorized
      hint, wrong key, LAN refusal, `models` with `--env-stdin` and without a key, `_real_agent` keyless digest input
      and LAN refusal;
    - the updated `capture/tests/test_endpoints.py`;
    - `gui/tests/test_models_picker.py` (the keychain-only rule for the optional key).
