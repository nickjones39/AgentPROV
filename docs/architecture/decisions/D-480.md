- **D-480 (2026-10-14, core review D finding CD-3; user decision 2026-10-14: approved).** The generic profile check of
  `[import] variant_labels` names no family's variant.
  - **Problem.** `adapters/profiles.py` exempted the literal DRIFT variant `drift.k18.conversations` from the rule that a
    label names a declared variant, for every family (invariant 5: family logic in the core). The exemption existed only
    so that `agentdyn.profile.toml` can label part `d`, which DRIFT's import serves (`repro/D1-3`).
  - **Rule.** A label may name a variant that `[import] variants` does not declare only when the label is not one of the
    profile's own `[profile] parts`: such an entry records which other part, served by another import, the variant
    belongs to. A label giving an undeclared variant one of the profile's own parts is a `ProfileError`, as before.
    D.6.12 item 12 states it. Tests: `tests/adapters/test_profile_variant_labels.py` and the adjusted case in
    `tests/adapters/agentdojo/test_profile_machinery.py`.
  - **Rejected:** an explicit `[import]` list of label-only variants (it changes the AgentDyn profile bytes, so
    `profile_sha256` and the AER headers of every AgentDyn corpus; class 1 for no gain in checking); moving the check
    into the agentdojo family schema (the rule is generic, and other families would keep no check).
  - **Downstream:** none in stored bytes. `adapters/profiles.py` is in no stage digest; both AgentDyn profile versions
    still load unchanged. A profile that labelled an undeclared variant with a foreign part is now accepted for every
    family, not only for the DRIFT name.
