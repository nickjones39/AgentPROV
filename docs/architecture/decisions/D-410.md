- **D-410 (2026-10-14, pipeline-perf; user-approved 2026-10-14).** `aer.rules.load_catalogue` caches each parsed rule
  catalogue by `(source, sha256 of the resource bytes)`.
  - **Why:** mapping cites rules record by record, so every execution parsed the TOML about 22 times. That was 15–19% of
    an import's CPU (Mandate: 8,851 parses, 71 s of 369 s).
  - **Purity:** the bytes are read on every load, so changed bytes are parsed again; a failed parse is never cached.
    `parse_catalogue` is unchanged and a `RuleCatalogue` is immutable, so the cache is a pure function of its inputs
    (G.4.7).
  - **Effect:** the map job's CPU on Mandate fell from 58.1 s to 2.7 s.
  - **Identity:** Mandate imported before and after: 1,595 of 1,596 files byte-identical. The only difference is
    `derivation.json`'s `aer` `engine_code_sha256` and `fn_digest` (regen-batch item 32; land before part C).
  - **Rejected:** `functools.cache` on `load_catalogue` (keyed by name, it would miss changed bytes); caching inside
    `code_verification` only (the registry autoloader and `MapContext` parse too).
