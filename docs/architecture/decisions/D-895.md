- **D-895 (2026-10-28, `derive`/`recompute` batch size follows the worker count; M5 Ultra performance round 2,
  item 1b).**
  - **Finding** (`recompute --dry-run` on `ast-survey-agentdojo-rg2`, main's code, exclusive window):
    - The derive pool, and the re-map's importer pool, retire every worker at the end of each 256-unit batch.
    - System time grows with worker starts, about 1 s each: 29 s at `--jobs 1`, 86 s at `--jobs 8`, 263 s at
      `--jobs 16`. `--jobs 16` was slower than `--jobs 8` (86.5 s against 72.4 s).
    - A profile of the parent at `--jobs` 3 and 16 shows it saturating one core (mean 0.86–0.87, p90 1.0). The parent
      seals AERs, runs the AER validator, writes and fsyncs each object, and reads cache hints. That sets a floor
      that more workers cannot lower.
  - **Change.** With no explicit batch size, `batch_for(workers)` = 64 units per worker (one worker lifetime), between
    256 and 1024.
    - It sets the re-derive batch, and the re-map's importer batch (`cli/derive._remap`).
    - A batch size never changes an output. Every measured batch size gave 3,243 identical and 0 unexplained. A new
      test compares one unit per batch with the default, byte for byte.
  - **Measured** (exclusive window, machine CPU 4–7):

    | Workers | Batch 256 | Batch 1024 | Batch 4096 |
    |---|---|---|---|
    | 8 | 66.2 s (system 97 s) | 63.0 s (system 58 s) | — |
    | 16 | 79.7 s (system 334 s) | 64.1 s (system 141 s) | 65.5 s (system 102 s) |

    So `--jobs 16` now matches `--jobs 8`. Past that the parent is the limit.
  - **Held as class 1** (until the round-1 seal):
    - workers kept alive across batches (`io/workers.py`);
    - no fsync for a throwaway dry-run tree (`raw/store.py`);
    - AER validation in the worker (`aer/`, `adapters/runner/`).
    These are the levers below the parent's floor.
  - **Not changed:** `validate`'s own 256-row batch (D-893 overlaps it instead; larger batches there are not yet
    measured).
  - **Class 0:** `corpus/derive.py` and `cli/derive.py` are outside every stage scope. The importer is only passed an
    argument it already takes.
