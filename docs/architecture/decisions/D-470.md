- **D-470 (2026-10-14, phase 10q: the results-container dialect and reader; user decision 2026-10-14: approved).**
  memo-ozdincer/agentdojo (rank 6, D-146) holds its runs in whole-file JSON containers: `label`, `suite`, `model`,
  `n_results`, `aggregate`, a `results` list, and some of `adapter`, `defense`, `attack`, `mode`, `base_url`, `port`,
  `elapsed_seconds`. They are read by a new dialect `agentdojo.results_container` with a new reader
  `ResultsContainerReader` (`adapters/agentdojo/results_reader.py`) that declares `multi_execution = True` (D-320).
  - The reader yields one located item per `/results/<i>`, whose value is `{container, row}`; `container` holds the
    top-level keys except `results` and `aggregate`.
  - Variants are chosen by row key set: `rc.k7` for the `run_eval` rows and `rc.k12` for the `eval_benign_utility` rows
    (with or without `classification`; smoke rows add `suite`).
  - `n_results` is checked against the list length.
  - A container with an unknown row key set is sealed degenerate (`unsupported_variant`), never dropped.

  Census: `docs/reports/phase10q/README.md` §2.
  - **Rejected:** a TraceLogger variant (the file is no TraceLogger object, and a whole-file variant cannot yield
    several executions); container mode (D-320 rejected it for whole files); streaming (the largest container is 4.5 MB).
  - **Addendum (2026-10-21, as built; user decision 2026-10-21 on the new-families bug pass, NF-9).** The located
    item's value is the whole parsed container, `aggregate` included; the locator `/results/<i>` selects the row, and
    `ext.rescont.container` keeps only the listed top-level fields (D.6.20 items 1 and 4). The code, the table, D.6.20
    and the census agree; only the `{container, row}` wording above described an earlier draft.
