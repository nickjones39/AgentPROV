- **D-546 (2026-10-14, derive and verify fixes from the bug pass and core review B: BF-20, BF-32, BF-33 stop-gap, CB-6,
  CB-11; push approved by the user 2026-10-14).**
  - **Objects absent on purpose (BF-20, CB-6).** A raw object that `purge` removed (`raw/tombstones.jsonl`), that a sealed
    corpus withholds (`WITHHELD.json`) or that it only references (`raw/REFERENCES.json`) is counted
    (`<kind>_unavailable`), not refused with `raw.object.missing`. The executions that need such an object, directly or
    through a container (AD-12), are not re-mapped, and `recompute` and `verify --level rederive` classify them
    `unverified` (H.4.5(6)). Register and origin lines about them, and about the withheld executions, are left out of the
    corpus-file comparison. `NEW` carries `raw/tombstones.jsonl` and `raw/REFERENCES.json` byte for byte, and the writer
    accepts an included object the derivation accounts for (`CorpusWriter.absent_ok`). Any other absence still refuses.
  - **Resume key (BF-32).** `derived_from` also records `semantics` and the `fn_digests` of the recomputed layers, so a
    resume under another `--semantics-profile` or another build is refused, exit 4 (N.1.8(3)).
  - **Reuse stop-gap (BF-33).** Until D-451 (stage code digests over each stage's import closure; proposed) lands, reuse
    also needs the source `aer` stage's `adapter_code_sha256` and `engine_code_sha256` to equal this build's. The family
    comes through `Catalogues.profile_family`; an unknown family reuses nothing. Reuse falls back to recomputing more
    often, and never carries stale output for these scopes.
  - **Row status (CB-11).** `verify` chain recomputes each row's status with `corpus.index.row_status` (H.3.2(1), as the
    writer builds it) and reports a difference as `index.status`. `rederive` reports a nonzero `index_refreshed` on a
    sealed corpus as `rederive.index_refreshed`: failed, or unverified when a declared version differs. The
    register ↔ issues reconcile stays one-directional (H.6.1 R5); making it bidirectional would be a spec change.
  - **Not changed:** AER, SEM and PROV bytes; every stage's code-digest scope (`corpus/` is in none); `import_arguments`
    and `_remap`, beyond excluding absent inputs from the trees (D-530 builds on them next).
  - **Rejected:** keying the absence fix on `WITHHELD.json` alone (it misses purged working corpora, CB-6); re-mapping
    absent executions from the fetch cache inside recompute (not available offline); dropping a purged execution's row
    in a re-derive (seal needs it to build `WITHHELD.json`).
