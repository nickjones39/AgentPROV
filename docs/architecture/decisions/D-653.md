- **D-653 (2026-10-22, GUI G3: estimate inputs; the shipped priors table).**
  - **Inputs.** Cells come from `run --dry-run --plan-json` (D-651). Calls per cell, input / cached / cache-write /
    output tokens per call, and cell duration (p50 and p90) come from three sources, in order:
    1. the corpus open in the viewer (a sample of up to 200 AER files);
    2. the shipped priors `gui/src/agentprov_gui/data/estimate_priors.json`;
    3. the user's defaults (Settings › Estimate), labelled as assumptions on every estimate that uses them.
  - **Keys.** Lookups go from most to least specific: benchmark, suite, attack (or benign), model family and backend
    (the execution's `<backend>-live` profile; user decision 2026-10-22: the same suite on two backends is kept
    apart), then any backend, then any model.
  - **Tokens.**
    - Recorded `usage` where the source has it, in the provider's own convention (D-656): Anthropic `input_tokens`
      excludes cache reads and writes; an OpenAI-compatible `prompt_tokens` includes the cached part. They are
      converted to "input sent" with cached and written parts.
    - Otherwise estimated from message sizes, four characters per token, plus the suite's tool-definition size from
      the D-652 catalogue. The AgentDojo-family stored corpora record no usage.
  - **Priors.** The table is generated by `gui/tools/gen_estimate_priors.py`, run through `tools/suite_queue.py
    --class import --cpu 2`. It holds counts and quantiles only, never corpus text or execution ids, and names each
    corpus (id, manifest sha256, executions read) and the building commit.
  - **Cost.** `(in − cached − written)·p_in + cached·p_cached + written·p_write + out·p_out`, at p50 and at p90 (each
    quantile independently: deliberately high), plus the preflight probe. The worst case counts every due attempt at
    p90. Time is `ceil(units / jobs)` × the mean cell duration.
  - **Dry run stand-in.** A real-model dry run needs the key and is refused while the live part is `planned`. The
    estimate's dry run therefore uses a scripted stand-in unless both hold, and says that a resumed real-model
    corpus's settled units are then not counted.
  - **Rejected.** Tokens from a tokenizer in the GUI (a model-specific download, and still no tool definitions);
    priors from the stored corpora's text (the table must hold no text); one global default (hides the per-suite
    spread).
  - **Class 0.** GUI only. **Tests:** `gui/tests/test_estimate.py`, `gui/tests/test_g3_live.py`.
