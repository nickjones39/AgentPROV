- **D-430 (2026-10-14, `recompute` at this package of a corpus built under other versions is a drift report; user ruling
  2026-10-14, after regeneration-plan finding F-8).** On the Mandate p10 clone, `recompute --dry-run` at main (with the
  D-31 bumps) re-mapped the `aer` stage under the current `mandate-agentdojo-eval@2` and catalogue `agentdojo` 2, while
  the recorded `agentdojo.suites@1` was replayed: 396 `changed_explained`, and an output that H.2.5 would refuse.
  - **Ruling:**
    - **Reproduction is at the building commit.** A corpus recomputes to 0 differences at the commit and core lockfile
      that built it (HL "Derivation reproducibility"), in a scratch worktree. This is the regeneration plan's D-358
      check. The commit is `producer.git_commit` (with `git_tree_clean`) where the manifest records it. The stored
      pre-round corpora do not record it: their commit is the one whose code digests (`derivation.json`
      `engine_code_sha256`, `adapter_code_sha256`) and core `uv.lock` digest match. All eight match `afe7038`, where the
      original import, repeated on the same pinned input, gave byte-identical outputs (regeneration plan §3.7).
    - **At this package it is a drift report.** `Derivation.check_inputs` lists every declared version this build would
      record differently, per recomputed stage (`version drift: aer: source profile <id> v<n> recorded, v<m> current`;
      `... catalogue <ns> v<n> recorded, v<m> current`; `sem: <ref> reads catalogue <ns> v<n>, the AER would declare
      v<m>`). A dry run prints them as notices and classifies as before (`changed_explained` where a declared version
      differs).
    - **A writing recompute refuses** (`--out`; exit 4, `corpus.derive.version_drift`) before `NEW.partial` exists: "re-import
      to upgrade, or recompute at the building commit". A corpus recorded under the current versions recomputes as before.
  - **Not built:** no legacy version gates in the mappers and no upgrade mode. Upgrading a corpus to current versions is a
    fresh re-import (the round's route (a)); an upgrade mode stays on the roadmap.
  - **Why:** replaying the recorded versions at main cannot give 0 differences. The Mandate AER bodies changed with the
    mapper code of regeneration-batch items 1-28, not only the headers, and the current mapper cites 28 `agentdojo` rules
    the archived catalogue v1 does not declare. A byte-identical replay at main would need every old mapper behaviour kept
    behind version checks.
  - **Rejected:** replaying the recorded versions in the importer (at main, old corpora fail on `RuleNotDeclared` or show
    `unexplained_change`; the user first chose it, then chose this); full legacy replay (large, permanent old code paths);
    writing the mixed corpus (H.2.5).
  - **Downstream:** moves no AER, SEM or PROV bytes, no compat output, no manifest and no manuscript number. Changes
    `corpus/derive.py` (not in any stage's code digest), `cli/derive.py` and `corpus/verify.py` (the injected current-profile
    lookup). `verify --level rederive` at main still fails on such a corpus, as it should: it is a reproduction check.
