  - **Context:** the DTap pre-check (`docs/reports/precheck/dtap-bench.md`, PC-01, S0) found five named workstation
    accounts of the harness hosts in 1,094 trajectory files: tool output, OpenClaw harness-config state
    (`/trajectory/*/state/plugins|agents|storePath`), agent arguments, agent text and final responses. Accounts #1, #3,
    #4 and #5 reach the L2 scratch AER and PROV. Account #2 (301 files, the harness-config account) reaches them on a
    full import. 137 other named account strings (1,393 in 301 files, 133 distinct names) are benchmark or model
    content. No DTap profile declared a redaction rule, so the AER, SEM and PROV of a full import would carry the five
    names. The user chose (2026-10-21) the option "exact, 0 collateral, over every AER string". It is an exception to
    D-604 (redact in tool and environment output only; model-authored text verbatim) for this source.
  - **Decision:**
    - A closed profile table `[[family.dtap.redact]]` `{id, scope, pattern, replacement, labels, note?}` and the module
      `adapters/dtap/redact.py`, a family copy of D-476's grammar. The only scope is `all_strings`: every string of
      every record the mapper writes, model-authored text included. The pass runs after the records are built, so it
      also covers ext copies and `ext.lex` member orders.
    - A pattern is structural, names no account and has a named group `span`. The replacement is
      `acct-{span12}`, with D-476's `{span12}` (first 12 hex of SHA-256 over `<profile id> NUL <span>`). It replaces
      the span only, so `/home/<n>/.ssh` becomes `/home/acct-<label>/.ssh`.
    - Only a match whose label the rule's `labels` list holds is redacted. Every other account is left as it is.
      `dtap-bench@2` lists six labels: the five PC-01 accounts and the one other letter case in which the data spells
      account #3 (109 occurrences). They were computed out of band (`python3 -I`, in memory) from the names in the
      pinned data. The five accounts were identified by the pre-check's own classification (the verifier's
      `v_acc.json` targets, which equal the four L2-reaching non-task-tree digests of `acc_l2.json` and the 301-file
      harness-config digest of `raw.json`). The repository holds only labels an AER would carry anyway, never a name.
    - Three rules share the list (the two token rules and the case-variant label: user decision 2026-10-21: kept
      (label-gated, 0 collateral)):
      - `host_account`: the account segment of an account path, in the forms and endings of the release scan's D-457
        rule, over decoded strings (`/home/<n>`, `/Users/<n>`, `\/home\/<n>`, `/mnt/<d>/Users/<n>`,
        `C:\Users\<n>`, `C:\\Users\\<n>`, `C:/Users/<n>`; trailing dots kept outside the span);
      - `host_account_token`: a whole letter-and-digit token, in any context;
      - `host_account_dotted`: a token whose letter runs are joined by single `.`, `_` or `-` (one listed name has
        such a separator).
    - The census showed that the path rule alone leaves the listed names in `ls -l` owner and group columns, munged
      project-directory names (`-Users-<n>-…`), deeper roots (`/home/<generic>/<n>/`), paths right after an escaped
      newline (`\n/home/<n>`) and plain text. The two token rules close that residue and stay exact, because a token is
      redacted only when its label is listed.
    - Pointers (`evf` and `unk` keys, scoped rule citations, `ext.lex.ord` keys and `ext.lex.flt`) are redacted token
      by token. A renamed object key and the pointers that name it stay in step, and two pointer tokens never join
      into a path. A recorded member order (`ext.lex.ord`) stays a permutation: `redacted` is appended when it is added
      to `ext.dtap`.
    - Source locators (`src`) keep pointing at the raw field. Raw bytes are untouched and ship as pinned
      (D-186 (c)).
    - Recording: each redacted pointer is tagged `D` (an `I` stays `I`) and cites the new rule
      `dtap.value_redacted@1` (D). `ext.dtap.redacted` lists `{p, rule: "dtap-bench@2#<rule id>"}`. One info seal issue
      `dtap.value_redacted` carries the count. Artefact entry `dtap.art.host_account_paths` (FO).
    - Two spans with one listed label are a `ProfileError`, as in D-476.
