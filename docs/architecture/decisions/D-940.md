- **D-940 (2026-10-29, the building-commit snapshot tool for D-911; built in the release-preparation session from the
  orchestrator's brief; the user's D-911 is its design).** D-911 keeps the sealed corpora's building commits checkable
  without the development history: the software record carries, per distinct commit, a `git archive` snapshot without
  the copyleft fixtures and a manifest whose stage code digests are recomputed from the snapshot and checked against the
  corpora. Nothing produced or checked that manifest.
  - **Decision (as built):** `tools/building_commit_snapshots.py` (standard library only, outside `src/`; it never imports
    `agentprov` itself), with three commands:
    - `plan` lists the commits per corpus: `producer.build_steps` (D-780; the stages each step wrote); else the datasheet
      statement `building-commit-by-digest-<abbrev>` (the full id must also be in a sealed corpus's `DATASHEET.md`); else
      an explicit `--attribute DIR=COMMIT`, recorded as an operator attribution. A commit is never guessed, and a dirty
      build step is refused. A sealed corpus's `producer.git_commit` is added as role `sealing` (no stage checks), unless
      `--no-sealing`.
    - `build` writes `agentprov-src-<commit>.tar.gz` (`git archive --format=tar --prefix=agentprov-<commit12>/`, gzip
      with mtime 0) per commit and `BUILDING-COMMITS.json` (`agentprov-building-commits/0.1`) into a new or empty
      directory. Exclusions come from each commit's own tree: every `tests/fixtures/<dir>/` whose `SOURCE.json` marks a
      sample `licence_class: restricted`, the matching `tests/fixtures/LICENSES/<dir>-*`, and `--exclude` paths, each
      listed with its blob id. The archive is read back: every member's blob id and mode must equal the commit's
      `ls-tree`, the member set must equal the tree minus the exclusions, and the pax comment must name the commit.
      `listing_sha256` records the sorted `<mode> <blob> <path>` lines.
    - The stage digests are computed by **the snapshot's own code**: its `src/agentprov` is extracted to a temporary
      directory and a child `python -I -B` imports that package (checked) and runs `stage_definitions.code_sha256` over
      `stage_scopes` (`expand` through `raw.members`; each semantics profile through `sem.profiles.profile_digest`). Every
      `derivation.json` entry the commit wrote is compared (`expand`, `aer` engine and adapter, `sem` engine and
      profiles, `prov`, `validation`, `views`, `compat`); the source profile and rule catalogues named by digest must be
      in the snapshot with those bytes; a one-commit corpus's `lockfile_sha256` must equal the snapshot's `uv.lock`. Any
      difference refuses the build and nothing is written. Each commit must descend from the history scrub `42a85025`.
    - `verify` needs no repository: archive size, sha256 and md5, the pax comment, the listing digest, the exclusions'
      absence, and the stage digests recomputed by each snapshot's code against the manifest and, with `--corpus`, the
      corpora.
  - **Dry run (round 1, scratch):** 4 commits (`5b1f6fdf`, `5fc39c16`, `d93aa261`; sealing `8bb6bc92`), 104 MB; 50 code
    digests, 38 files by digest and 8 lockfiles equal; `verify` with the 8 corpora: 0 problems; a rebuild gave identical
    bytes. Report: `docs/reports/release/building-commit-snapshots.md` (with the push plan for the local `wave2/build-*`
    tags, for the user's yes).
  - **Open for the user:** U-06 (B-2 / K.4.2 keep all real third-party fixtures private until it is decided; D-911 leaves
    out only the copyleft ones), and the class triage of 36 redacted gitleaks hits found in every snapshot.
  - **Rejected:**
    - recomputing the digests with this tool's own copy of the construction (as `tools/regen/find_building_commit.py`
      does): it proves what today's code thinks the old scopes were, not what the snapshot computes; the scopes changed
      with D-451;
    - a checkout or `git worktree` of each commit instead of the archive: the check must be of the bytes that are
      deposited;
    - `git archive --format=tar.gz`: its gzip header and level vary with the git build; the tar is gzipped by the tool;
    - deriving the commit by searching all commits for equal digests at deposit time (what D-358 had to do): the
      corpora now record it, or carry the user-approved statement.
  - **Byte class 0:** a new file under `tools/`, its tests, reports; no file of any stage scope changes.
