- **D-544 (2026-10-14, GUI "Dev run" mode; user feature request relayed by the orchestrator session; proposed
  defaults, every one editable; build: import side in G2, live side with G3).** A dev run imports **a few samples of
  every chosen corpus part** into fresh scratch corpora, then checks them, so a developer sees in minutes whether the
  pipeline still works end to end. Specification: `docs/reports/gui/design.md` §19.
  - **Import dev run (G2):** per source and part, N executions (default **5**), selected deterministically. With
    today's CLI the mode is **first-N** (`import --limit N`, the importer's own deterministic order); **spread**
    (round-robin over arms or variants) and **random with a recorded seed** need a core flag (a core need routed to the
    CLI robustness session: `import --sample N --sample-mode first|spread|random --seed S`), and the GUI offers them
    only when the CLI's `--help` lists that flag. Dev mode only: never `--release`, never `package`, `verify --release`
    or a deposit. Output: `$AGENTPROV_HOME/dev-runs/<UTC timestamp>/<corpus>/`, never a stored corpus. Steps per part:
    `import <source> --snapshot <part> --fetch --limit N` (offline fetch-cache read), `validate --corpus` (every tier; the scratch corpus
    is small), `recompute --corpus --dry-run`; one summary row per part (mapped, degenerate, issues, validation, recompute
    differences, timing). Every step runs through `tools/suite_queue.py --class import --cpu 2` (a small reservation, so
    a dev run never starves a gate). The last **5** dev runs are kept; older `dev-runs/<timestamp>` folders are deleted
    automatically, and only those folders, never while a job of the run is running.
  - **Live capture dev run (designed now, built with G3):** transport **scripted** by default (`--llm-script`; no
    network, no API call, no cost); 3 tasks per suite, 1 attack per task, all configured suites. A real-model dev run is
    opt-in: the §8.3 estimate first, explicit consent, a hard cap of **5** model calls in total (editable), keys only from
    the keychain through `run --env-stdin` (D-395), never a dotenv file.
  - **Settings › Dev runs:** the default N; a per-source/part override table; include and exclude lists; sampling mode
    and seed; keep count; queue CPU reservation; for live: transport, tasks per suite, suites, attacks per task, call cap
    and cost cap. Stored in the GUI's settings; "Reset to defaults" restores the shipped values.
  - **Caveat (core review D, CD-7):** with `--limit`, the raw members stored can depend on the import batch size. The
    fix is held in a core branch; today's `import` has no `--batch-size` option to pin, so a dev run records the CLI
    commit and treats sampled raw-member sets as non-comparable across CLI versions until the fix lands.
  - **Rejected:** dev runs into the stored corpora (they are read-only for the GUI and a sample would corrupt their
    identity); sampling in the GUI by building `--select` filters per arm (it needs the arms, which only the reader
    knows, and duplicates core logic); unbounded retention.
  - **Downstream:** GUI only (`gui/`, design §19); one core need (the sampling flag) routed to the orchestrator. No AER,
    SEM or PROV byte, corpus or core module changes.
