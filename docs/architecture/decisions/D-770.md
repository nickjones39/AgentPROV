- **D-770 (2026-10-23, the estimate of an Inspect plan and its judge calls; GUI session, orchestrator request
  2026-10-23 after `--judge` landed with D-740; class 0).**
  - **Why.** `agentprov estimate` could not read an Inspect plan: its dry-plan cells have no suite or kind, so the
    estimate stopped with an internal error (exit 70), and so did Run Live's estimate for AgentHarm. Judge calls are
    billed calls (D-667), and the estimate did not count them apart.
  - **The dry plan** (`run --dry-run --plan-json`, D-651, still `agentprov-run-dry-plan/0.1`; the fields are added):
    - each Inspect cell row also has `task` and `samples`, its sample count;
    - the document has `inspect: {task, epochs, message_limit, max_connections, judges{role: model}}`, from the
      worker's backend configuration, with every label escaped.
  - **Cells.** An Inspect cell is one unit of `samples × epochs` executions, run `min(max_connections, executions)`
    at a time. Its statistics are per execution (one sample), looked up under the plan's benchmark (`inspect-agentharm`
    → `agentharm`), with suite = task. Its attack row reads "(no attack)", because AgentHarm's harmful split is not
    benign.
  - **Judge calls.** The usage reader counts a model call whose actor is a `judge` apart from the agent's calls: calls
    per execution, and input and output tokens per call. The agent's `calls` now counts the agent's calls only.
    AgentDojo-family executions have no judge actors, so nothing changes for them.
  - **Pricing.**
    - Judges run at the agent's endpoint (D-667), so each role's model is priced there.
    - Roles on different models are all priced at the dearest of them, with a warning.
    - Judge input is priced without a cache discount.
    - A judge model with no price leaves the cost unknown, with a warning; the estimate does not guess.
    - Under the D-725 caps every judge must use the agent's model (D-740), so then both prices are the same. The
      estimate warns when a capped plan has a judge on another model, which the run refuses.
  - **The D-740 bound.** The estimate shows the billed-call bound per sample, `((M − 1)(1 + a) + j)(1 + K)` (42 for
    AgentHarm at `--message-limit 10`), beside its p50 and p90. Its worst case stays "every due attempt at p90".
  - **The shipped priors** were built before the split at first, so their two AgentHarm rows counted the judge calls
    among the agent's (`judges_in_calls`; rebuilt below). Those calls are priced at the agent's price, with a warning when the judge price
    differs, until `tools/estimate/gen_estimate_priors.py` rebuilds the table. The rebuild reads every corpus the
    table is built from, so it goes through the job queue as a separate step. A sample of 200 executions of
    `ast-survey-agentharm-rg1` gives, per sample at p50 (p90): harmful, 2 (6) agent and 1 (2) judge calls; benign,
    4 (9) agent and 1 (3) judge calls; judge calls about 350 input and 320 output tokens.
  - **Priors rebuilt (2026-10-24, after the post-check).** Built from the corpora that will be sealed:
    `ast-survey-agentdojo-rg2` (built at `d93aa261`) and the seven `-rg1` trees (built at `5b1f6fdf`). Two entries then
    moved to their sealable trees (below). That is 126,351 executions and 509 rows, as before, and each corpus records
    its `building_commit` (`gen_estimate_priors.py --corpus-commit`). Against the table built from the p10 copies:
    - AgentDojo: all 419 rows identical;
    - AgentHarm: both rows gain the judge columns, and `calls` is now the agent's only. Harmful, p50 (p90): 2 (5)
      agent calls and 1 (2) judge calls; benign: 4 (9) and 1 (3). Judge calls are about 350 to 360 input and about
      300 output tokens at p50;
    - AgentDyn: 10 of 88 rows have lower input tokens, in dailylife, github and shopping (chars/4 basis; calls and
      output unchanged). This is regen item 2 (B3, D-376): the 384 CaMeL executions' 2,342 agent calls now record
      their input as `not_recorded`, so the input they list is no longer counted.
    **Entries moved to the sealable trees (2026-10-24).** Only these `built_from` entries were replaced (name, manifest
    sha256, building commit); every row and the rest of the header are unchanged:
    - `ast-survey-agentharm-rg2`, the withhold re-import (D-811, built at `5fc39c16`). Run alone, it gives the two
      AgentHarm rows byte-identical to the shipped ones;
    - `adprov-v1-release-rg2`, derived at `5b1f6fdf` (rg1 is on the never-seal list: it lacks the compat PROV). Its
      17,664 AER files are byte-identical to rg1's, with the same paths, and the generator reads only the AER, so the
      AgentDojo rows it feeds cannot move.
    With the split, a 3-sample AgentHarm estimate (agent gpt-4o-mini, judges gpt-4o) rises from $0.0026 to $0.0134
    at p50, because the judge calls are now priced at gpt-4o.
  - **Rejected:**
    - pricing the judges at the agent's price whatever their model (wrong for uncapped runs with another judge model);
    - a separate price per role in the estimate (the plan's judges share the agent's endpoint, and the dearest price
      bounds them);
    - the D-740 bound as the worst case (it is the caps' reservation, and the estimate's worst case keeps its p90
      meaning across backends);
    - rebuilding the priors in this change (a heavy read of every source corpus).
  - **Class 0.** Nothing here feeds AER, SEM, PROV or a corpus.
