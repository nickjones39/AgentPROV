- **D-33 (2026-10-11, snapshot reconciliation and the sealed snapshot origin; phase 11).** (1) Counts in the sealed
  manifest are recomputed at sealing from `executions.jsonl`, `register.jsonl` and `raw/members.jsonl`, never copied from
  the importer. (2) A candidate is a selected execution-bearing file or member: `executions` = index rows whose
  `snapshot_ids` contain the snapshot, a selection exclusion is a `select`-stage `not_imported` entry whose path an
  exclude glob matches with the entry's own code (counted in `selection_excluded`, never a candidate), `not_imported` =
  every other `not_imported` entry attributed to the snapshot, `candidates = executions + not_imported`. This fixes
  AgentHarm (`candidates 6` against `executions 1056` becomes 1,056 = 1,056 + 0) and ROPE (14,066 exclusions become
  `selection_excluded`). (3) The sealed snapshot origin is built from the recorded pin and the objects' origins, never
  `local`: `git` `{repo, commit, subtree[, subtree_sha1]}`, `corpus` `{corpus, version, producer_commit}`; sealing refuses
  (exit 4) with no pin, `verification.unverified > 0`, a `local` object origin, a disagreement with the pin, or a spec
  origin that differs from the pin's. (4) A git origin has exactly one of `subtree` (a string, `""` for the whole commit)
  and `subtrees` (a sorted array of two or more relative paths; no v0.1 corpus uses it).
  - **Why:** H.2.3 requires `candidates == executions + not_imported` and the release refuses `local` origins; the
    working manifests break both. Counts defined from the register are recomputable by `verify --level chain`.
  - **Rejected:** copying the importer counters (they count containers); counting containers as candidates; a local path
    or placeholder origin in a sealed manifest (invariant 2); telling exclusions apart by the register `detail` text.
