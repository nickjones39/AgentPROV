- **D-49 (2026-10-11, gate D at full scope validates stored AERs, read-only, in a plain process pool; phase 11).**
  `agentprov migrate gate-d [--scope golden|full] [--release] [--workers N] [--corpus DIR ...] [--limit N]
  [--accept-gap TREE ...] [--report PATH]` (also `migrate gate D`). `golden` derives the 19 v1 and 9 native golden AERs
  twice and checks the committed pins; `full` reads the AERs of `--corpus DIR` (once per tree: `release`, `converted`,
  `native`, classified from the index rows) through `CorpusReader` and never writes into a corpus (a `--report` inside a
  corpus is refused, exit 4). Per execution it runs tiers 2-4 in release mode (a failed or skipped check fails the
  execution, MP-3) plus the dedicated J.3.5 checks; per tree it compares the aggregates with the J.3.5 table and the
  completeness 17,664 / 18,027 / 18,241. Full scope without `--limit` needs passing full-scope G0, A and B reports for the
  commit and lock, and its own passing report unblocks a full-scope gate E; `--limit N` is a diagnostic sample. A tree
  without a corpus fails `inputs.<tree>.present` unless `--accept-gap TREE` is given, and the report then records the gap.
  - **Finding:** no stored AERs of the converted tree exist (gates A and B map the converted transcripts into a temporary
    directory and delete them), so a full run needs `--accept-gap converted` and the native corpus's 18,027 matched
    executions are checked against that column. The AER side of the J.3.5 table reconciles exactly on the stored AERs.
  - **Measured:** about 0.96 s per execution on a 200-execution slice (tier 4 is about 90 %), so roughly one hour at ten

    report (the J.3.5 counts would be re-parsed from 7,000-statement documents in the parent), needs a job kind in
    `io/workers.py` (phase 12) and a scratch write per execution. The inputs were validated and sealed at import and are
    re-verified before use. The report states `isolation.mode: process-pool, grade: null`.
