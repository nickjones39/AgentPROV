- **D-46 (2026-10-11, `purge` lives in `corpus/purge.py` and `cli/purge.py`, not `raw/purge.py`; phase 11).** MN M.1.2 and
  G.9.6 name `agentprov.raw.purge`, but `raw/` belongs to phase 12; the engine uses the public read API of `raw` and the
  tombstone path `CorpusLayout.tombstones` (moving it later is a rename). A purge targets a working corpus (`--corpus DIR`,
  acting on `DIR.partial`) or the fetch cache (`--cache`, `--cache-dir`). It writes one tombstone row `{date, reason,
  sha256}` (sorted by digest, no value), gives every citing execution (and, for a container, its members' executions)
  `release.withheld`, then unlinks the object, so an interrupted purge is finished by running it again; origin rows, member
  rows and the index are kept. A sealed corpus is refused (exit 4); a non-interactive run needs `--yes`, a terminal asks
  for the first 8 digits. Purging a container lists the stored member objects, and vice versa; it never removes more than
  the one object asked for. `corpus.json` counts and index `issues` are not rewritten (derive and seal refresh them).
  - **Why:** the tombstone, `release.withheld` and the confirmation fit the corpus layer, which owns the register and the
    file layout; tombstone first and unlink last makes the operation resumable without a journal.
  - **Rejected:** editing `raw/`; waiting for phase 12 (phase 11 ships all fifteen commands); rewriting
    `executions.jsonl` and `corpus.json` in the purge (a second writer invites drift, D-33); withholding only exact-digest
    citations; automatic cascades; searching git objects in the cache.
  - **Open (phase 12):** a later `import` into the same working corpus would store a tombstoned file again; blocking
    tombstoned digests at ingest is raw-layer work.
