- **D-233 (2026-10-12, withholding: raw policy `withhold` per snapshot; user-approved 2026-10-13).** A snapshot with raw policy
  `withhold` releases nothing. Every execution that a row of that snapshot records is withheld, including a row shared
  with another snapshot (*withhold wins*). So is every object such a row cites, and every object whose origin the
  snapshot's pin vouched for (members follow their container). The reason is `licence`. The released snapshots must
  share one raw policy, which `licences.policy.raw_policy` records. When every snapshot is `withhold`, the corpus raw
  policy is `withhold`, and a sealed but unreleasable record can be built for any licence policy except `forbidden`
  (withholding only narrows a release). The deposit builder refuses a corpus whose raw policy is `withhold`, and
  accepts a `withhold` snapshot only alongside a `WITHHELD.json`. `chain` fails an index row of a `withhold` snapshot
  (`withheld.policy`).
  - **Why:** H.4.1 sets the policy per snapshot, and part A brought several snapshots per corpus.
  - **Rejected:** *include wins* for a shared object (it would release bytes on the strength of the other origin's
    licence reading; a user who wants that can split the corpus, D-35); refusing every corpus with a `withhold` snapshot
    (the old H.4.1 table row, written for one-snapshot corpora).
