- **D-550 (2026-10-14, tier-4 round-trip cache; session prov-perf; requested by the user; push approved by the user in
  the prov-perf window, 2026-10-14).** The
  PROV-O round trip of tier 4 (the `pv.roundtrip.*` checks; 65–81% of pipeline CPU) is kept under
  `$AGENTPROV_HOME/cache/tier4` (`validate/cache.py`), so a document whose bytes and context are unchanged is not
  round-tripped again.
  - **Key.** The document's sha256 plus the context: the sha256 of every `agentprov` source file (which subsumes the
    validation stage digest), the version and code-file digest of `prov`, `rdflib`, `pyparsing`, `isodate`, `lxml`,
    `python-dateutil` and `six`, the Python build, and the round-trip options.
  - **Value.** The five outcomes exactly as returned, with their digest. A completed round trip only: never `skipped`,
    never `pv.roundtrip.load`.
  - **Rules.**
    - A bad entry is a miss and is removed.
    - Writes are atomic renames, and size is bounded by LRU eviction.
    - T1 jobs get a prefetched hint and return a frame; the parent does all I/O (G.4.4).
    - `validate_prov(..., fidelity=)` consults the cache only inside `if roundtrip:`, so the G2c-5 skip
      (`--skip-prov-conformance`) composes: a skipped run never reads or writes an entry.
    - `--no-validation-cache` turns it off.
    - `validate --release` never reads an entry: it recomputes and audits the entries it finds.
  - **Rejected.**
    - Caching all of tier 4: the key would need the AER, SEM and catalogue digests, and the rest is cheap.
    - A key built from the validation digest alone: the round trip also runs `prov/serialise/nquads.py`, the strict
      loader and the vocabulary.
    - Library versions without file digests: a patched or forked library keeps its version string.
    - Letting T1 workers read the cache: the audit hook forbids it, and it would widen G.4.5.
    - SQLite: a corrupt database is harder to make a clean miss, and the user asked for atomic write-rename.
    - Trusting the binding for release: a forged local entry, or an unseen nondeterminism, would enter a decision that
      third parties rely on; one full release validation costs about 3 h.
  - **Downstream.** Class 1: `validate/` moves the validation stage's `engine_code_sha256` (regen-batch item 94).
    Later, `adapters/runner/provjob.py` and the importer move the AER engine digest, and they join item 94. No AER, SEM,
    PROV or validation-row bytes change. Reports: `docs/reports/prov-perf/cache-design.md`. Spec: N.2.5 item 9 and
    E.5.5 "Reuse".
