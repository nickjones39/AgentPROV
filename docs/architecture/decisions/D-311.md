- **D-311 (2026-10-13, RW-1: a `[withhold]` rule that selects executions by an AER seal issue code; trigger chosen by the
  user 2026-10-13 together with D-289 (c)).** A `[[withhold.rules]]` entry may carry `issue = "<namespace>.<code>"`
  instead of `marker` or `pattern` (exactly one of the three; no `scope` key, the rule withholds executions; optional
  per-rule `reason` and `public_note` as before; one rule per code). At sealing, every execution whose index row lists
  `map.<namespace>.<code>` or that has a register entry with that code is withheld with its primary object, exactly as
  a derived-file hit is (D-234). The other executions that cite that object stay released, and `chain` counts the object
  as `raw_withheld` for them (D-235). Basis `profile_rule`; finding `{agentprov-withhold/1, <profile>@<v>:<rule id>,
  <AER path>:<rule id>}`; the code and any value stay out of `WITHHELD.json`. Marker and pattern rules are unchanged and
  stay the byte-level backstop, scanned exactly as before (an issue rule is never matched against bytes).
  `corpus/` names no family: the code is data in the profile, evaluated against index rows and the register. First user:
  MCPHunt (phase 10m), whose mapper emits `mcphunt.canary_flagged` for every trace with a canary-flagged event (agreed
  with phase 10m through the orchestrator; profile entry `{id = "canary-flagged", issue = "mcphunt.canary_flagged"}`).
  - **Why:** D-289 (c): the source records which traces expose a planted canary (4,595 flagged), and 2,191 unflagged
    traces stay releasable although a raw file holds up to 723 traces. The flag lives in three released places (the AER
    seal, the index row, the register), and the register survives withholding (D-231), so the selection can be
    re-derived offline (D-314). An issue code is declared in a closed, versioned list (the catalogue's `issue_codes`,
    AD-18), so an unknown code can be refused when the policy is read (D-313).
  - **Rejected:** a rule over a recorded AER field (the 10m README's wording): the field (per-event `ext` flags) is
    declared nowhere, so parsing can check its syntax but not its existence, a mapper change could silently change the
    selection, `corpus/` would need a pointer-and-predicate language over AER records, and after the seal the flag sits
    only in the withheld AERs in the private sidecar, so `chain` could not check that a withheld execution really
    matched; a table-level list of codes (`[withhold] issue_codes = [...]`, the orchestrator's first sketch): no rule id
    for the ledger's findings and no per-rule reason or note; withholding every execution that cites the object (the
    raw-hit `executions` scope): it would drop the 2,191 unflagged traces, the point of (c).
