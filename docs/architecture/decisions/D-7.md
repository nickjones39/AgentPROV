- **D-7 (2026-10-08, platform agnosticism; user requirement, architect ruling).** AgentPROV MUST run on Linux,
  macOS and Windows, on x86_64 and arm64. Platform handling is **capability-based**:
  - `agentprov.host` (L0) probes the host once per process. `detect_host() -> HostProfile` holds the facts (OS
    family, release, normalised arch, CPU count, physical memory, page size) and the **probed** capabilities
    (rlimits present and *enforced*, RSS sampler `procfs | libproc | psapi | none`, process-tree kill `killpg | job
    object`, hard memory cap `RLIMIT_AS | job object`). Each capability records how it was decided. Code tests
    capabilities, never OS names, and no platform constant (page size, flags) is hard-coded.
  - `constants_for(profile, calibration) -> HostConstants` is a **pure** function that sets the watchdog interval,
    the RSS trigger margin and the default worker count. Without a hard memory cap, a short, bounded
    memory-bandwidth calibration in a T1 worker sizes the margin. Nothing is cached on disk.
  - **Isolation grade** `enforced | watchdog | degraded`. Release mode requires at least `watchdog`; below it,
    exit 3 (`worker.isolation.insufficient`). Dev mode warns and records the grade. This mirrors AD-16.
  - The profile, capabilities, constants, calibration and grade are recorded in the `corpus.json` producer block.
    They never enter AER, SEM or PROV bytes, which MUST be byte-identical on every platform (binary I/O, `\n` line
    ends, no locale encodings).
  - The CI `core` job runs on `ubuntu-latest`, `ubuntu-24.04-arm`, `macos-latest` and `windows-latest`.
  - **Added 2026-10-08 (first CI run):** three more probed capabilities, each with its "how decided": `nofollow`
    (`native | verify_identity | none`, selected once in `ingest.paths._probe`, G.3.10(13)), `posix_permissions` (chmod
    bits read back; G.4.12(7)) and `startup_vm_bytes` (the floor under `RLIMIT_AS`; G.4.12(8)). Tests skip on
    capabilities, and no source file other than `ingest/paths.py` names `O_NOFOLLOW`.
  - **Scope:** the live backends' T2 OS sandbox (G.4.10) stays per-platform and is decided at phase 8.
  - **Rejected:** `sys.platform` branches with per-OS constants. They are brittle on new hardware and cannot tell
    "accepts setrlimit" from "enforces it", which is exactly macOS's `RLIMIT_AS` behaviour. A `psutil` dependency was
    also rejected: it is a compiled third-party package in the tier-1 safety path, and it is not needed.
