- **D-880 (2026-10-28, Zenodo in the desktop app, and the uploader as its own distribution; addendum to D-790 and
  D-870; scope from the user through the orchestrator, design and choices approved by the user in the session window).**
  The user asked for GUI settings and a GUI action, "so this can be done by anyone downloading the software".
  - **Packaging (option A, the user's choice):**
    - **The distribution:** the uploader moves from `tools/zenodo_draft.py` to the distribution `agentprov-zenodo`
      (`zenodo/`, a uv workspace member like `capture/`; module `agentprov_zenodo.draft`). It runs as
      `python -I -m agentprov_zenodo`, `agentprov-zenodo-draft`, or the checkout entry `tools/zenodo_draft.py`.
    - **Installing it:** `agentprov` offers it as the `zenodo` extra, and the dev group installs it in every checkout,
      where the GUI runs it.
    - **The boundary:** the `agentprov` package never imports it (a new boundary test). So H.10.1(1), the M.5.3 network
      table for `agentprov` and the D-654 parity are unchanged.
    - **The locks:** `uv.lock` was relocked once against PyPI with the user's yes (only the member and the extra were
      added); `gui/uv.lock` was relocked offline (metadata lines only).
  - **The token:**
    - `agentprov keys` accepts `ZENODO_SANDBOX_TOKEN` and `ZENODO_TOKEN` (`RELEASE_KEY_NAMES`) next to the endpoints'
      key variables. Settings › Keys lists them.
    - The uploader's `--keychain` reads the target's token through the keychain helper (D-702) straight into its
      `Secret`. It is refused with `--check`.
    - The GUI never holds the token: every GUI run passes `--keychain`, and the child's environment is the GUI's
      allowlist.
  - **Settings › Zenodo** stores the `agentprov settings` keys `zenodo.target_preselect`, `zenodo.communities`,
    `zenodo.concept_doi` and `zenodo.creators.N.name|orcid|affiliation`.
    - **Preselect only:** the target is only preselected; the uploader's `--target` keeps no default (D-790).
    - **Validators:** each community identifier is checked; the concept DOI is never AgentDojo-PROV's (D-5); ORCIDs
      are checked.
    - **Prefill only:** `release.toml` stays the record (H.10.2). The Package page's *Write release.toml from the
      Zenodo settings…* writes a template, never over an existing file. Its empty title keeps `package --deposit`
      refusing it until the user fills it in.
    - **No token key:** no setting holds a token.
  - **Package › 9 Finish › Create Zenodo drafts…:**
    - **The runs:** one deposit per line (`DEPOSIT_DIR sha256:ROOT ...`; the first is the umbrella). Each deposit
      without a receipt gets a create; one that is not `complete` gets `--resume`; a complete one is skipped. Then
      `--cross-link` runs when there are two or more. Each run is `python -I -m agentprov_zenodo ... --keychain`, with
      the checkout's interpreter.
    - **Consent (the user's choice):** each run is under a **pseudo-terminal**. The user types every confirmation
      phrase in the dialog's terminal pane, so D-790's consent rule ("a person at a terminal", no `--yes`) is unchanged.
    - **Publishing:** it makes drafts only; Publish stays on Zenodo's website.
    - **Platforms:** POSIX only (macOS, Linux); the action says so elsewhere.
    - **Reverse parity:** a new `OUTSIDE_CLI` registry holds the GUI actions that are deliberately not an `agentprov`
      command, with the uploader options they use, checked against the uploader's parser.
  - **Rejected:**
    - **B, a module inside the GUI package:** CLI-only users would need `tools/`, giving the uploader two homes, or the
      tool would depend on the GUI.
    - **C, an `agentprov zenodo` command:** it reverses D-790. It would put a network client in `agentprov`, add an M.5.3
      row and force a D-654 form.
    - **A GUI dialog that passes the phrase over a pipe:** that is a non-terminal consent channel, which D-790 rejected.
    - **The token in the GUI's environment or settings.**
    - **Creators kept as one list setting:** the D-703 list kind cannot hold names, so creators use indexed keys.
  - **Open (the user decides later):** what the umbrella record holds. `package --deposit` needs at least one corpus
    archive; an index-only umbrella is a separate `agentprov.release` decision.
  - **Not trialled:** `--keychain` and the GUI action against the sandbox (`docs/reports/release/zenodo-sandbox-trial.md`).
  - **Byte class 0:** `zenodo/`, `tools/`, `gui/`, `agentprov.keys`/`settings`/`cli.keys` (no stage scope), tests and
    docs.
