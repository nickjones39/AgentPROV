How it works

From raw bytes to W3C PROV, in five versioned stages.

Each stage is a versioned function of the one before it, and each output is chained to its input by sha256. A corpus can be checked end to end, and its provenance recomputed without running a model again.

  1. sha256 · pinned origins

    Raw store

    Byte-identical source artefacts. Raw bytes are never edited and archives are never extracted to disk.

    1
  2. aer/0.2

    AER

    The AgentPROV Execution Record: 13 typed record kinds, explicit unknowns and locators back into the raw bytes.

    2
  3. sem/0.1

    SEM

    Standoff annotations from versioned profiles: integrity, roles, injection markers and outcome meaning.

    3
  4. agentprov-prov/0.1

    PROV

    PROV-JSON in three bundles: core (observed and derived), inference, and assessment for policy claims.

    4
  5. validate · verify · seal

    Corpus

    Validation tiers gate every write. A sealed corpus has a manifest, a register and a root digest.

    5

Temporal order is never causality.

Order is recorded as order. It never becomes a PROV dependency.

Context is not derivation.

A model invocation uses the messages in its request. A tool execution uses only its request and the environment state it read.

Missing evidence is declared.

No placeholder timestamps and no reconstructed trajectories. Unknowns carry a reason from a closed list.

Policy claims stay out of the facts.

Integrity labels, taint and injection markers live in a separately attributed assessment bundle.

Evidence classes

Three kinds of evidence, drawn three ways.

Every AER record and field is tagged with how it is known. Core PROV statements carry observed or derived evidence; inferred statements go to their own inference bundles. The app draws the difference in the line itself.

  • OObserved: read directly from the source.
  • DDerived: computed by a declared, deterministic rule.
  • IInferred: produced by a named inference method, kept apart from the core.
The desktop app

Open a corpus. See how every fact is known.

A viewer and job runner for AgentPROV corpora. Opening a corpus never writes to it, content stays hidden until you ask for it, and every action has a command-line equivalent. Pick a step, then a numbered point to look closer.

Browse every corpus on your machine.

The Viewer scans your corpus roots and opens a corpus by reading its files only. No file is written and no lock is taken.

Same thing in a terminalagentprov stats --corpus DIR --select …

Read the graph and its JSON side by side.

Each execution opens in a tab of its own, from any corpus, so you can compare executions across corpora.

Same thing in a terminalagentprov render --corpus DIR --ex ID

Find the cells where an attack succeeded.

On a derived corpus the Viewer adds task and outcome columns, and the SEM tab lists every annotation of the selected execution.

Same thing in a terminalagentprov inspect ID --corpus DIR --view sem

Look underneath, at the execution record.

The AER is the canonical record every graph is derived from. Each record says how it is known and which rule put it there.

Same thing in a terminalagentprov inspect ID --corpus DIR --view records

See the exact command before it runs.

New Job has a form for every command: import, derive, validate, verify, recompute, render, statistics, seal and more.

Sources

Live runs and released logs, one record.

Runs captured live and logs released by other research projects become the same AgentPROV Execution Record, so the same engine derives their provenance.

Released logs

Import what other studies published.

Import adapters read released logs as untrusted bytes. Parsing is bounded, archives are streamed and never extracted, and the raw bytes are kept and hash-pinned beside the record.

Live runs

Capture new runs as they happen.

Four live backends: AgentDojo, AutoDojo and AgentDyn record runs as capture/0.1, and an Inspect harness runs AgentHarm and keeps Inspect's own log of the run.

  • A real model starts only with your consent, cost caps and a containment choice.
  • Keys come from the OS keychain; the app never shows one.
  • A scripted transport tests the whole path with no network, keys or cost.

A tested capability. Live capture works and is tested in v0.1. No live results are claimed, and live corpora cannot be sealed until v0.2. Live runs need macOS or Linux.

Corpora

Corpora you can check for yourself.

The corpora built with this release are published on Zenodo as one collection. Each has a datasheet, a licence class and a root digest.

  1. Raw bytessha256 of each source artefact
  2. AERexecution digest and seal
  3. SEMannotation digest
  4. PROVbundle digests, then the root digest
On Zenodo

One collection, one DOI per record.

Download a corpus, then check its chain from the raw bytes to the root digest. Provenance is derivation-reproducible: recompute it from the stored record without running any model.

Collection DOI: assigned at deposit

Check a corpus
# the chain from raw bytes to the root digest
$ agentprov verify --corpus CORPUS --level chain

# run the validation tiers again
$ agentprov validate --corpus CORPUS

# recompute provenance from the record and compare
$ agentprov recompute --corpus CORPUS --dry-run
